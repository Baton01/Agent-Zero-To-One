# 🧰 skills/ · 技能包目录

> 这里放**可复用的技能包（Skill）**：一套"什么时候用、怎么做、做到什么算完"的流程说明书。对应章节 [[docs/第09章 Skills能力包]]，配套代码 `code/ch09_skills.py`，深入阅读 [[02-Wiki/专题总结/07-Skills与MCP协议]]。

---

## 一、这个目录是干什么的

- **不是教程，是给模型和给自己看的工作流程**：把"每次都要粘进 prompt 的那段流程"沉淀成文件。
- 概念分工：Tool 让它能做、Prompt 管这一次、**Skill 管一类任务的流程**、MCP 管工具怎么复用接入。
- 结构（一个技能 = 一个目录 + 一份 `SKILL.md`）：

```text
skills/
├── README.md                  # 本文件
└── example-skill/             # 一个技能
    ├── SKILL.md               # 必需：frontmatter（元信息）+ 正文（流程）
    ├── scripts/               # 可选：确定性脚本（算数、统计、格式化）
    └── templates/             # 可选：输出模板（报告形状固定的东西）
```

---

## 二、`SKILL.md` 字段规范

```markdown
---
name: example-skill          # 必需：kebab-case，与目录名逐字符一致
description: >-              # 必需：唯一常驻上下文的内容
  做什么 + 什么时候用 + 什么时候别用（三句；折叠块写法避开 YAML 冒号陷阱）
version: 1                   # 可选：改了流程就升版本，A/B 才分得清"哪一版"
---
```

| 字段 / 小节 | 必需 | 写错会怎样 |
|---|---|---|
| `name` | 是 | 中文或含空格 → 加载器找不到 / 对不上号 |
| `description` | 是 | 写太宽 → 到处乱触发；写太窄 → 永远不触发 |
| `version` / `license` | 否 | 团队协作时说不清"哪版好用" |
| `## 何时使用` | 是 | 模型不知道正向触发条件 |
| `## 不适用` | 是 | 技能被套用到所有相近任务上（最容易省、最容易出事） |
| `## 步骤` | 是 | 祈使句 + 编号 + 每步产物；商量语气会让模型只挑最容易的两步做 |
| `## 验收标准` | 是 | 每条都要能被机械判定；没有它模型会"再补充一点"停不下来 |
| 资源引用（`scripts/` `templates/`） | 否 | **路径必须真实存在**，否则模型读不到就开始编造脚本内容 |

## 三、怎么加一个自己的技能

1. **先成功一次**：手工把这任务做成功一遍（允许试错、查资料）；**再记录动作**：写出"你脑子里默认做的事"，包括那些"顺手看一眼"的检查项——这里才是技能的价值。
2. **固定顺序**：排成编号步骤，每步写清输入、产物、如何验证；**补验收标准**：checklist + 一个正例一个反例，再加"越界禁令"（如"不要顺手重写代码"）。
3. **建目录**：`skills/<你的技能名>/SKILL.md`（文件名必须是大写 `SKILL.md`），按需补 `scripts/`、`templates/`；**登记**：在下表补一行。

| 技能名 | 何时用 | 附带资源 | 版本 |
|---|---|---|---|
| `example-skill` | 审查代码改动（diff / 文件 / 片段） | `scripts/count_diff.py`、`templates/review.md` | 1 |

## 四、怎么验证技能真的有效（smoke test）

**结论只有一个来源：同一批任务跑两遍，用代码判定，且效果与成本一起看。**

1. **任务集固定**：6–10 条，从真实历史里挑，覆盖典型 + 边界 + **一条"不该触发"的**。
2. **判据可机械判定**：每条写出"必须出现哪些要素"，交给代码检查；判据让**没读过技能的人**写。
3. **重复 3 次**：同一模型、同一 `temperature`、同一提问模板，除技能外全部一致。
4. **必须有等长基线**：A 组给**等量无关文本**，不是空白 prompt——否则只证明了"上下文变长有用"。
5. **指标一起看**：成功率提升 ≥ 20 个百分点**且** token 增幅 < 50%，才算值得留。
6. **离线 / 在线分开说**：离线跑是"检查器自检"，在线跑才是"效果验收"。

```bash
cd code
AGENT_MOCK=1 python ch09_skills.py     # 离线：验证索引与判定器能跑通
python ch09_skills.py                  # 在线：拿真实数字（去掉 AGENT_MOCK）
python ../skills/example-skill/scripts/count_diff.py --diff sample.patch   # 技能里的脚本要能独立跑
```
