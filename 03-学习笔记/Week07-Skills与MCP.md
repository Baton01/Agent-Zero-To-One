## 一、本周目标

- [ ] 分清四个概念各就各位：Tool 让它能做、Prompt 管这一次、Skill 管一类任务的**流程**、MCP 管工具怎么被**复用接入**；它们是叠加而不是四选一
- [ ] 说清一个 Skill = 一个目录 + 一份 `SKILL.md`：frontmatter 负责"被找到"、正文负责"怎么做"、附带资源负责"确定性执行"
- [ ] 写出一条能触发、又不乱触发的 `description`：三句话覆盖"做什么 + 什么时候用 + 什么时候别用"，并把用户真实说过的话抄进去
- [ ] 说清渐进式加载三层（目录常驻 / 正文按需 / 资源最后）与 `top_k` 上限、匹配阈值的作用；解释"为什么两三个技能不值得搭"
- [ ] 跑一次 A/B smoke test 并给出数字结论：固定任务集 6–10 条、**等长基线**（A 组不能是空白 prompt）、重复 3 次、代码判定、成功率与 token 一起看
- [ ] 说清 MCP 的贡献是接入标准化：把 M×N 份适配压成 M+N 份；三方角色 Host / Client / Server 中**权限在 Host**
- [ ] 分清三种能力谁决定：Tools 由模型提议调用、Resources 由应用选择加载、Prompts 由用户主动使用
- [ ] 写出一个最小 MCP Server（至少 2 个工具 + 1 个 Resource 或 Prompt），能被 `--live` 模式连上；验证"未确认的危险工具，客户端根本不发 `tools/call`"

**过关标准：** 能回答验收问句——"为什么这个技能会在用户说那句话时被触发？不触发时你从哪里看出是哪一环出的问题？"
