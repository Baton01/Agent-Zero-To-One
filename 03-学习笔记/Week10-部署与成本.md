## 一、本周目标

- [ ] 分清延迟的三个指标：TTFT（首字，靠流式 + 前缀缓存 + 精简 prompt）、TPOT（每 token，靠模型选择与输出长度）、端到端 P95（用户真正抱怨的）；并知道 **Agent 里 TTFT 每步都要付一次**
- [ ] 说清"为什么必须看 P95 而不是平均值"，并知道样本太少时 P95 本身就是噪声
- [ ] 说清流式不只是打字机效果：它把"14 秒空白"变成"0.9 秒有反应"；Agent 还要**流状态**（正在查天气…），否则用户卡在工具调用的那几秒里
- [ ] 说清流式与结构化输出的冲突及三种解法（分阶段 / 放进工具参数 / 部分 JSON 解析），并知道"推出去的内容收不回来"
- [ ] 列出成本七手段并说清各自的代价：模型分级路由、前缀缓存、历史压缩、输出限制、结果缓存、批量处理、预算熔断；**省输入靠缓存与压缩，不靠换模型**
- [ ] 说清可靠性四件事：每层超时（内层 < 外层）、重试只覆盖可重试错误（指数退避 + 抖动）、降级链显式标注、副作用操作幂等（生成与执行分离）
- [ ] 区分缓存两层：L1 精确匹配（key 必须含模型 / prompt / 工具版本）无条件先上；L2 语义缓存只对无状态、无个性化、非时效的问题开，阈值从 0.97 起
- [ ] 说清四种发布形态的取舍：CLI（自己用）、Web API（集成，长任务要异步化）、后台任务（离线省钱）、机器人（团队，注意分片与确认交互）
- [ ] 跑通 `ch13_deploy.py` 并填完上线前检查清单（未打勾项写明"为什么现在不做"与"计划什么时候做"）

**过关标准：** 能回答验收问句——"如果现在有 10 个人同时用你的 Agent，你会先看哪一个数字来判断系统是否健康？"答不出具体指标名，说明延迟与成本两节还没落地。
