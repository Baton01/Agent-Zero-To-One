## 一、本周目标

- [ ] 说清"为什么 demo 能跑离上线很远"：概率会**复利**——单步 95% 在 10 步后只剩约 59.9%，所以"把工具描述写清楚"往往比"换个更强的模型"更划算
- [ ] 从**真实场景**采样建评测集：20~50 条起步，四类配额齐全（常见 50% / 边界 25% / 无答案 15% / 恶意 10%），每条含 `id / category / input / judge / notes`
- [ ] 说清判定方式的四级阶梯：精确匹配 → 关键词 → **规则（Agent 主力）** → LLM 评分；LLM 评分要固定 judge 版本、先理由后分数、与人做一致性校准
- [ ] 区分 `pass@k`（能不能做到）与 `pass^k`（能不能稳定做到），跑 3 次给出实测差距，并说明差距来自哪几条用例
- [ ] 说清 Agent 特有指标比普通 LLM 应用多哪些：完成率、工具正确率、无效调用、步数超限率、失败分布、`$/完成任务`、P95 延迟，并且**指标要一起看**
- [ ] 会用 trace 定位失败层：记录每步输入摘要、模型输出、工具调用与结果、token、耗时、错误；失败全量、成功采样；标准是"只看 trace 就能复现一次失败"
- [ ] 说出八种失败模式并能分类：工具选错 / 参数填错 / 反复调用 / 提前收工 / 不会停 / 幻觉引用 / 上下文丢失 / 被输入带跑
- [ ] 实现 `PermissionGate`：`high` 风险工具展示**完整参数**再确认，并演示"用户拒绝后 Agent 如何继续"
- [ ] 构造一次**间接注入**攻击并防住它：工具输出被当成指令的链路 + 四层防御（不可信内容包裹 + system 规则 + 域名白名单 + 确认门）
- [ ] 做一个 CI 门禁：通过率 < 75% 或任一恶意/无答案用例失效时返回非零退出码

**过关标准：** 能回答验收问句——"如果把 system prompt 里'回答要简洁'改成'回答要专业有深度'，你能在多长时间内说出通过率会掉几个点？靠什么说出这个数字？"
