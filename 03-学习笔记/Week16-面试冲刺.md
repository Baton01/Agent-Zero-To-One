## 一、本周目标

- [ ] 按**岗位差异**确定复习重点（Agent 应用开发 / RAG 工程 / 平台与基础设施），说出你的目标岗位最看重哪三章
- [ ] 题库**三刷**：第一遍照着章节正文答，第二遍合上笔记答，第三遍只答"开门句"然后自评漏了什么
- [ ] 高频题每类准备一个**开门句**（10 秒内说清结论 + 展开方向），覆盖：概念辨析 / 架构选型 / 工程取舍 / 失败排查 / 安全
- [ ] 用**六段式**把 2 个项目各讲一遍：业务问题 → 技术选型 → 系统设计 → 评估指标 → 故障与优化 → 最终结果；每个控制在 3 分钟
- [ ] 记录**追问三框架**的实战用法：承认 X 的适用场景再讲取舍 / 把"10 倍"换算成绝对数字 / 用分段评估把"效果不好"定位到环节
- [ ] 简历条目按公式重写：动词 + 对象 + 方法 + **数字**；空话词（负责 / 参与 / 显著提升 / 效果良好）见面就删；每个数字能答"怎么测的"
- [ ] 准备 3 个反问问题（针对团队与业务，而不是"贵公司有什么培训"）
- [ ] 走一遍面试前一晚检查清单：项目能跑、指标有出处、失败案例能讲、简历每一行都能扩展成 1 分钟

**过关标准：** 随机抽 3 道题库题，你能先给开门句、再展开到 90 秒；随机抽 1 个项目，你能在 60 秒内说清"给谁用、解决什么、指标多少"，剩下 2 分钟讲"一次真实的失败与修复"。

## 二、预习：先想三个问题

> 开始刷题之前先自己想一想，刷完回来对照。

1. 面试官问"效果不好你怎么排查"——为什么必须先**分段评估**？不分段会出现什么对话？
2. "我用了 10 倍的并发"这句话该怎么讲才可信？换算成绝对数字时你要补哪几个量？
3. 简历里最有说服力的一行是什么？它凭什么是"最有说服力"的（因为数字、因为取舍，还是因为失败修复）？
