## 一、本周目标

- [ ] 背下并会用"该不该上多 Agent"的**四条判断清单**：上下文隔离 / 对抗检查 / 并行 / 角色差异——一条都不满足就别拆
- [ ] 说清"角色是契约不是名字"：planner / executor / reviewer / critic / router 各自的输入、输出、停止条件、禁令；reviewer 要收敛（输出必须是 pass/revise）、critic 要发散、router 只路由
- [ ] 说清三种协调方式的边界：Supervisor（可控）、Pipeline（可预测）、Graph（可恢复）；以及**为什么明确不推荐自由对话式**
- [ ] 说出四类典型故障的**机械解法**：循环争论 → 轮次上限 / 无进展熔断；任务漂移 → 目标复述；上下文膨胀 → 隔离 + 压缩；责任真空 → 交付清单
- [ ] 说清"上下文隔离才是多 Agent 的核心价值"：独立上下文提升质量的同时降低 token；回传时压缩但**保留指针与不确定性**
- [ ] 算一次总账：多 Agent 输入 token 高 20%~200%，只有并行能降延迟——你买的是"上下文干净"与"对抗检查"
- [ ] 跑通 `ch11_multi_agent.py`，能指着输出讲清契约校验、漂移检测、轮次上限、交付清单四个机制各自的证据

**过关标准：** 能回答验收问句——"如果有人把 reviewer 的意见改成'再写得好一点'，你的系统会在第几轮停下来？靠哪个机制停？"答不上来说明保险还没装好。
