## 一、本周目标

- [ ] 说清毕设不是"把第 15 章再做一遍"：题目自己定、指标自己定并给依据、至少 2 组替代方案对比、≥20 条评测集、失败要按环节分类
- [ ] 用**选题四问**筛题目：数据拿得到吗、效果验证得了吗、有没有真实取舍、四个里程碑跑得完吗；偏向"脏数据 + 可验证"的题目
- [ ] 写完需求文档（`docs/requirements.md`）：具体角色、可量化成功标准（含**至少 1 个反指标**）、≥3 条"不做什么"、边界与约束
- [ ] 写完技术方案（`docs/design.md`）：文字架构图 + 模块划分表 + ≥2 组替代方案对比（选择 / 替代方案 / 为什么没选 / **代价**），至少一行"代价明确变大"
- [ ] 走完四个里程碑，每个都有可运行产出：M1 骨架跑通 → M2 接真实数据与模型 → M3 评估闭环 → M4 交付打磨（评测集从 M1 就开始攒）
- [ ] 交付四件事：README 四问（怎么跑 / 怎么配 / 怎么扩展 / 已知限制 ≥3 条）、一键复现、离线演示、失败分类归因
- [ ] 写一份失败分类报告（`docs/failures.md`）：按六个环节归类（输入解析 / 检索 / 工具 / 推理 / 格式 / 拒答）+ 归因分布 + 下一步优先级
- [ ] 用**六段式**讲清项目：业务问题 → 技术选型 → 系统设计 → 评估指标 → 故障与优化 → 最终结果；并做一次 3 分钟录音，自删形容词与"然后"
- [ ] 按公式重写简历条目，空话词清零，每个数字都能答"怎么测的"，并做一页纸项目卡

**过关标准：** 能回答验收问句——"把 README 发给一个没参与过的同学，他能在 10 分钟内跑出你的指标吗？"跑不出来，问题不在他。
