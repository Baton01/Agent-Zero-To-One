## 一、本周目标

- [ ] 说清该抽象的时机是"第三次抄同一段代码"（Rule of Three），会用三个测试判断：改动测试、解释测试、"没有它会怎样"
- [ ] 一张**九模块对照表**，每一行写出"没有它会出现的具体现象"（不是复述职责，要写症状或报错）：LLM 客户端层、Tool Registry、Agent Loop、Context 管理、Memory、Session 持久化、Trace、Permission Gate、Sub-agent
- [ ] 背下三条架构铁律：依赖只能向下、LLM 客户端是唯一的服务商边界、Trace 是横切观察者且不能被依赖
- [ ] 说清五个抽象取舍：三次法则、窄接口 + 配置对象（参数 > 4 个就该收进 `AgentConfig`）、配置描述"用什么"而代码描述"怎么做"（**配置里出现 if/else 就该停手**）、只在"并行 / 多用户 / 流式并行"时上 async、**状态放实例里**
- [ ] 说清错误信息三要素（发生了什么 + 传了什么 + 下一步怎么做），并知道"给模型的错误要带可用选项"能让下一轮自纠率从 40% 提到 80%
- [ ] 会用三个调试开关：`AGENT_DEBUG` / `AGENT_TRACE` / `AGENT_DRY_RUN`
- [ ] 说清 demo 到项目的五个差距：配置管理、错误处理、日志、文档（含已知限制）、可复现性
- [ ] 说出三个实战项目各自的核心：研究助手 = 引用可追溯；文档问答 = 链路完整并量化（切片 0.74 → 0.88）；代码审查 = 控制误报（双阶段 + 置信度阈值 + 条数上限）
- [ ] 说清三个项目共用的流水线：输入 → 证据 → 生成 → 校验 → 指标 → trace

**过关标准：** 能回答验收问句——"如果现在要给 Agent 加一个'检索为空就联网搜索'的行为，你要改几个文件？"超过 2 个说明分层还没做对。
