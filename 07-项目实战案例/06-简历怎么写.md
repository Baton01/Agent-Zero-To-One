## 一、先想清楚：面试官在简历上找什么

大部分简历教程会说"要突出亮点""要量化成果"。这是废话 —— 你不知道他要什么，就不知道量化什么。技术面试官在简历上其实在找**四个信号**，每个信号都有可验证的判据。

### 信号一：真实性 —— 你是真做过，还是只见过

**判据（面试官怎么验）：**

| 他看的 | 你的简历上必须有 | 反例 |
|---|---|---|
| 有没有**具体到模块名**的描述 | "引用计数"「令牌桶」「Lua compare-and-delete」这种**只有写过才知道的词** | "负责 Agent 模块开发" |
| 有没有**失败和取舍** | 至少一处"我踩过 / 我发现 / 我放弃了 X" | 全篇顺利交付、零障碍 |
| 数字有没有**口径** | 能说清"12253 行"是怎么数的 | "提升了 300% 性能"（无基线） |
| 描述的**粒度对不对** | 一个技术点讲透，而不是五个技术点各一句 | 罗列 12 个技术名词 |

**为什么"踩过坑"是最强信号：** 没写过的人只会描述"应该是什么样"，写过的人知道"实际会怎么坏"。你简历里出现一句"发现引用计数存在 TOCTOU 窗口，采用……」

**面试官的反应是**：他要么自己踩过，要么见过别人踩过 —— 无论哪种，他都相信你了。

### 信号二：判断力 —— 你会不会做选择

**判据：** 简历里有没有"**A 而不是 B，因为 C**"这种句式。

这个项目里现成的判断力素材（都是真的，见第二节表格）：

- 手写 embedding HTTP 而不用 `go-openai` 的 SDK —— 为了兼容任意非 OpenAI 模型名（`nomic-embed-text`）
- Skill 只做 prompt + 工具白名单、**不做流程执行** —— 把控制权交回 ReAct 循环
- Redis 锁释放用 **Lua compare-and-delete** 而不是直接 `DEL` —— 防超时后误删他人锁
- RAG 长度一律用 `RuneCountInString` —— 中文不按字节切坏

**没有"B"的简历 = 没有判断力的简历。** 因为不做选择意味着你只是执行了别人给的方案。

### 信号三：数据意识 —— 你分得清配置值和实测值

**判据：** 你写"QPS 1000"的时候，是不是知道那只是 `stage3.yml:97` 里的一行配置，而不是你压出来的数？

**这是最容易翻车的一条。** 把配置值写成成果值，面试官一问口径就崩。正确的能力不是"有数据"，而是：

- 说得出每个数字的**来源**（配置文件 / `wc -l` / 代码常量）
- **主动区分**"我测过的"和"我配的"
- 没有数据的地方，敢说"没测过，我只能给你定性的瓶颈分析"

**"没测过"是不扣分的，"编了"是致命的。** 见第五节，我把这个项目的 12 个数字分成了两组。

### 信号四：工程完备度 —— 你知不知道什么叫"能上生产"

**判据（逐项过）：**

| 维度 | 判据 | 这个项目的真实状态 |
|---|---|---|
| 测试 | 有 `*_test.go` 吗 | **0 个**（`find . -name "*_test.go"` 返回空） |
| 监控 | 有指标/日志/链路吗 | Prometheus 6 个自定义指标，**无 tracing，2 个指标无写入点** |
| 优雅关闭 | 收到 SIGTERM 会怎样 | **做了，且链路完整**（`cmd/stage3/main.go:512-548`） |
| 超时控制 | 每条出网调用都有超时吗 | **大量缺失**（LLM 无超时、stdio MCP 无超时、工具 `Execute` 不带 ctx） |
| 错误处理 | 错误是被吞还是被处理 | **多处静默吞掉**（重连失败、Redis 写失败、watch 报错退出） |
| 并发安全 | 共享状态有保护吗 | 部分有（引用计数用 atomic），部分没有（MCP `CallTool` 全程无锁） |

**这张表你自己先过一遍，再决定简历上写什么。** 工程完备度不需要满分 —— 需要你知道自己缺哪块，并且在被问到时能说出来。**不知道缺什么，才是真正的问题。**

## 六、把"教学项目"写成"工程经历"的三个技巧

前提：**不做假。** 下面的三个技巧全部是"把真实做过的事说到位"，不是"把没做的事说成做过"。

### 技巧一：写决策，不写功能

**功能句 vs 决策句：**

| 功能句（弱） | 决策句（强） | 决策素材出处 |
|---|---|---|
| "实现了 embedding 调用" | "embedding 层绕过 LLM SDK 手写 HTTP，为的是兼容任意非 OpenAI 命名的模型（项目里用的是 `nomic-embed-text`）" | `pkg/llm/openai.go:155-236` |
| "实现了 Skill 系统" | "Skill 只承载专业 prompt + 工具白名单，**不含执行体**，把控制权交回 ReAct 循环 —— 因为流程编排应该由工作流引擎负责，混在一起会让两个抽象都变脏" | `pkg/skill/skill.go:6-12,14-35` |
| "用 Redis 实现了分布式锁" | "锁释放用 **Lua compare-and-delete** 而不是 `DEL` —— 因为业务可能超过 TTL，直接 DEL 会删掉别人持有的锁" | `pkg/redis/client.go:145-159` |
| "实现了文档分片" | "分片长度用 `RuneCountInString` 而不是 `len()` —— 后者按字节算，中文文档会被拦腰切断" | `splitter.go:58,169` |
| "实现了热更新" | "热更新选择**引用计数 + 优雅销毁**而不是直接替换 —— 直接替换会让在途请求读到一半旧一半新的状态" | `registry.go:154-214` |
| "实现了会话串行化" | "会话串行化用**每 session 一条车道**，而不是全局锁 —— 全局锁会把不同会话也串起来，吞吐直接掉到 1" | `lane.go:33-68` |

**操作规则：** 每写完一条项目描述，问自己"**这条里有 B 吗？**" 如果没有 B（被放弃的方案），就把这条改写成决策句。**"我做了 X" 只能证明你干过活；"我选 X 不选 Y 因为 Z" 才能证明你会干活。**

**注意：决策句必须能说出 B 的真实代价。** 如果你说"手写 HTTP 而不用 SDK"，面试官会问"手写丢了什么" —— 正确答案是"**丢了 SDK 的重试、超时、错误分类**，这个取舍在只需要两个端点（chat / embeddings）时是划算的，端点一多就不划算了"。**说不出代价的决策句等于没做决策。**

### 技巧二：写故障与修复，不写顺利交付

**关键诚实点：只能写你真的改过的故障。** 没改过的，必须明确说"这是我在复盘时发现的、还没修"。

这个项目里可以讲的故障分两类：

**A 类：已经修过的（可以完整讲"发现 → 定位 → 方案 → 验证"）**

| 故障 | 证据（修复后的代码） | 讲法 |
|---|---|---|
| 热更新期间在途请求读到已销毁实例 | `registry.go:24-63` 的 `refCount`/`marked` + `gateway.go:99-115` 的 acquire/release | "第一版是直接替换，我在写并发测试用例推演时想到在途请求可能拿到已 Close 的 Agent，于是引入引用计数" |
| 请求持有了被标记实例 → 返回 AGENT_NOT_FOUND | `gateway.go:101-108` 的刷新逻辑 | "加了引用计数之后出现了新的可用性缺口：请求拿到已被标记的旧实例时会直接失败。补的方法是检测到标记就刷新到最新实例" |
| 新实例创建失败导致 Agent 永久不可用 | `registry.go:181` 的回滚 | "创建新实例可能失败（比如 MCP 起不来），如果这时候标记位已经置上，就会既没新实例又拿不到旧实例 —— 所以失败要回滚标记" |
| 分布式锁超时后误删他人锁 | `redis/client.go:145-159` 的 Lua 脚本 | "轮询超时后如果我直接 DEL，可能删的是后来者的锁。改成 Lua 脚本比对 value 再删" |

**注意这四条都是"设计时想清楚"的，不是"线上炸了"的。** 这完全可以讲 —— 讲法是把时态改成"我在设计/评审阶段识别出"，**不要编造"线上出现过 P0"**。

**B 类：发现但未修的（只能讲"我识别出的已知缺陷 + 我的修复方案"）**

| 缺陷 | 证据 | 讲法 |
|---|---|---|
| etcd watch 遇 compaction 永久退出 | `watcher.go:132-135` | "我在读 clientv3 文档时意识到 `required revision has been compacted` 是不可恢复错误，而我的处理是直接 return —— **这意味着配置热更新会静默失效且无人知晓**。修复方案是识别该错误后用当前 revision 重建 watcher + 指数退避，并加一个告警指标" |
| MCP `IsAlive()` 恒真 | `stdio_transport.go:117-123` | "我判的是 `ProcessState == nil`，但 `ProcessState` 只有 `Wait()` 之后才非 nil，而我全项目没有一处调 `Wait()` —— **所以崩溃检测和重连逻辑永远不触发**。正确做法是在 read goroutine 里感知 EOF，或者起一个 `Wait()` 协程" |
| 引用计数的 TOCTOU 窗口 | `registry.go:34-40` | "`acquire()` 是'先查 marked 再自增'两步，中间可以被 `markForDeletion` 插入 —— 窄窗口下请求会在已关闭的 Agent 上跑。**修法是把这两个 atomic 合并成一个状态机**，或者用 `atomic.Int64` 把标记位和计数位打包进一个字" |
| 客户端断开导致锁卡满 TTL | `distributed.go:99` | "释放锁用的是 `r.Context()`，客户端一断开 ctx 就取消，Lua 调用失败 → 锁不释放、卡满 60s。应该用 `context.WithoutCancel` 或独立的清理 ctx" |

**B 类怎么用才加分：** 不要等面试官问，**在讲 A 类之后主动接一句**"同一块代码我还知道有两个没解决的问题：……"。主动暴露缺陷是**最强的真实性强信号**，因为它反直觉 —— 编简历的人不敢说自己有洞。

**一个必须守住的边界：** A 类和 B 类的说法不能混。如果你把 B 类说成"我修了"，面试官让你打开代码看，当场就崩。**B 类永远用"我发现 / 我知道 / 修法是"这三个词打头。**

### 技巧三：写边界，不写全覆盖

**"全覆盖"句 vs "边界"句：**

| 全覆盖句（不可信） | 边界句（可信） |
|---|---|
| "支持高并发分布式部署" | "分布式模式下用 Redis 锁做跨实例会话串行；**验证过的是单机 + 单 Redis 场景，多实例我只做过时序推演，没有真实组网压测**" |
| "支持多种文档格式" | "分片器吃纯文本；**Markdown 的结构没有特殊处理**，标题会被当成普通文本切进 chunk" |
| "Agent 工具生态完整" | "内置 4 个工具（calculator/datetime/web_search/data_analyzer），其中 **web_search 和 data_analyzer 是 mock 实现，不发真实网络请求**" |
| "支持中文" | "**分片这一层做了中文处理**（rune 计数 + 全角标点切句）；但 Skill 的关键词匹配用的是 ASCII 分词器，**对中文完全失效**，所以实际全部依赖 LLM 匹配（`manager.go:163-173`）" |
| "工作流引擎支持 8 类节点" | "实现了 8 类节点，**8 个 demo 实际用到 6 类；ToolNode 和 LoopNode 零使用**" |

**边界句的公式：** 「我做了 X，在 A 场景下验证过；**B 场景未覆盖**，因为 C。」

**为什么边界句更强：** 全覆盖句在面试官眼里等于"我没想过边界"。边界句传递的是**你知道这个系统在哪里会断** —— 这正是工程能力的定义。而且边界句**提前排掉了追问**：你说"多实例没真实组网压测"，面试官就不会再花五分钟逼问这个。

**边界句的一个陷阱：** 不要把边界说得太多，变成自我否定。**每条描述最多带一个边界。** 三条描述 = 最多三个边界，其余用决策句和故障句填充。

## 七、三条自检清单

写完简历之后，别急着投。**关掉文档，用白板/白纸**过这三条。

### 清单一：数字口径自检

对简历上**每一个数字**，问三遍：

1. **这个数怎么算的？** 说不出计算过程（`wc -l` / 配置文件哪一行 / 代码常量），删掉或改写成定性描述。
2. **这是配置值还是实测值？** 配置值必须写明"配置基线"或"设计上限"，不能写成成果。这个项目里 `globalQps: 1000`、`userQps: 10`、`maxIterations = 10`、`chunkSize = 500`、`TTL 60s` **全部是配置值/常量**。
3. **如果面试官说"这个数我不信，你证明一下"，我能打开哪个文件？** 每个数字都要能指到 `file:line`。

**补充一条：小数不敢写。** 三处以上的"约"、"左右"、"大概"会让整段描述的可信度打折。宁可写"12,253 行"（精确、可验证），也不要写"约 1.2 万行代码"。

### 清单二：白板画图自检

**这四张图必须能不看资料画出来。** 画不出来 = 你没真的想清楚，面试被要求画图时必然卡住。

1. **一次请求的完整链路**（Stage3 分布式模式，10 个环节）：
   CORS → `ServeMux` 路由 → handler 解析 JSON/sessionID/API-Key → `activeProcessFunc` 选单机/分布式 → 过滤器链（Auth 10 → Security 20 → RateLimit 30）→ 分布式限流 → Lane 串行化 → Skill 匹配 → `ChatWithSession`（ReAct 循环）→ 写分布式记忆。
   （出处：证据文件 `02-网关与并发线.md` 第一节表格）

2. **Agent 热更新的时序图**：
   `markForDeletion(marked=1)` → 创建新实例（可能失败 → 回滚 marked=0）→ 替换 map → `go gracefulDestroy(oldEntry)` → 等 `refCount` 归零（50ms 轮询，上限 5s）→ `DestroyAgent` → `DisconnectAgentServers`。
   图上必须标出**两个窗口**：① `markForDeletion` 到新实例注册之间（请求会拿到 AGENT_NOT_FOUND）；② `acquire()` 里 `marked.Load()` 到 `refCount.Add(1)` 之间（TOCTOU）。

3. **ReAct 循环的三个出口**：
   画成一个 for 循环，三个箭头出去 —— 无 `tool_calls`（正常返回 content）、跑满 `maxIterations`（返回 error）、LLM 调用失败（返回 error）。**并标注第 3 个和第 2 个的语义不同**（一个是基础设施故障、一个是预算耗尽）。

4. **工作流的 interrupt / resume 时序**：
   节点执行 → `CheckpointStore.Save(status=paused)` → `state.Set("_interrupted", true)` → executor 检测到标记 return → …… 外部输入 → `Resume` 校验 `Status == "paused"` → 重建 state → `resolveNextNode(cp.CurrentNodeID, state)` → **从下一条边继续，中断节点不重跑**。

**加分动作：** 把第 2 张图和第 1 张图各画一遍在纸上，面试时**直接掏出来讲**。这比说十句话管用 —— 而且它传达的是"我准备过"。

**每个技术选型都要准备好被问"为什么不用业界方案"。** 下面 8 个问题必须都能答，答案里必须有**被放弃方案的代价**。

**这张表的使用方法：** 面试前一晚读一遍，**每个问题在心里默答一遍，再对照右列**。这 8 个问题命中率极高，因为它们是"自己实现 vs 用现成方案"的通用考点。

**唯一不能答的一句话是"没想过"。** 没实现没关系（"没做"是答案），但"没想过"说明你没有技术判断力 —— 而判断力是简历要找的四个信号之一。

## 八、如果面试官说"这是个教学项目吧"

### 先说结论：承认，然后立刻换战场

**不要否认，不要含糊，不要把它包装成生产系统。** 面试官会这么问，通常有两种情况：

1. **他看了 README**（你的 README 里写着"教学导向的 AI Agent 项目"、"三个渐进阶段"）—— 否认就是自曝。
2. **他做了判断**（没有测试、没有压测、规模不对）—— 否认就是自曝得更难看。

但"教学项目"**本身不是减分项**。减分的是"教学项目 + 说不清设计". 你要做的是：**把话头从"这是什么"转到"我在这里面想清楚了什么"。**

### 一段可以直接背的 60 秒回答

> "对，这是个教学项目，我从一开始就是按'把每个阶段的机制走一遍'来设计的 —— Stage1 只做单 Agent + ReAct，Stage2 加多 Agent 和 etcd 热更新，Stage3 加网关和 Redis 分布式，Stage4 是工作流引擎。
>
> 但我想说清楚它的边界：**这个项目没有测试、没有压测、没有检索评估** —— 这三块是我知道的最大缺口。它验证的是机制能不能跑通，不是能不能上生产。
>
> 也正因为是教学项目，有两点可能和一般项目不一样：**第一，每个设计决策的原因我能说清楚** —— 比如为什么 Skill 只做 prompt 不承载流程、为什么 embedding 手写 HTTP 而不用 SDK；**第二，里面踩的坑都是真踩的** —— 我可以现在打开代码给你看引用计数怎么保证热更新零中断，也可以告诉你同一块代码里 `acquire()` 还有一个 TOCTOU 窗口我没修。
>
> 如果您想验证的话，随便挑一条我简历上写的，我可以说到文件和行号。"

**这段话的结构值得注意：**

| 句子 | 作用 |
|---|---|
| "对，这是个教学项目" | 一秒承认，不浪费面试官耐心 |
| 四个 Stage 的顺序 | 证明你有体系，不是随便写了个 demo |
| **"没有测试、没有压测、没有检索评估"** | **主动交出短板**，抢在面试官之前定义"它的边界" |
| "验证机制能不能跑通，不是能不能上生产" | 给项目一个**准确的定位**，去掉不切实际的期待 |
| "每个设计决策的原因我能说清楚" | 教学项目的**真实优势一** |
| "坑都是真踩的" | 教学项目的**真实优势二** |
| "可以说到文件和行号" | **把抽象辩护变成可验证的承诺** —— 这一句最有力 |
| "还有一个 TOCTOU 窗口我没修" | 教学项目的**真实优势三**：敢说我哪里没做好 |

### 三条打死不能说的话

| 不能说 | 为什么 |
|---|---|
| "这个在生产环境跑过" | 一句话就够面试官让你描述部署拓扑、机器规格、监控面板、事故记录 —— 你一个都答不出，而且这一刻起你的所有其他话都不可信了 |
| "服务过 X 个用户 / 日均 QPS 是 Y" | 同上。更糟的是，你有 `globalQps: 1000` 这个配置值在手边，很可能会顺口说成"设计上支持 1000 QPS" —— 而"设计上"这个词救不了你，因为它会引出"那你测过吗" |
| "我们团队…" | 除非真的是团队。这个项目是单人单仓（0 个 `*_test.go`、README 是单人视角）。说了"我们"之后，所有的设计决策都不能算你的了 —— **这对你反而是净亏** |

### 教学项目的三个真实优势（不是安慰，是可以主动打出去的牌）

**优势一：每个设计决策的原因都说得清。**
在真实项目里，你可能是照着一份架构文档写的代码，问你"为什么这样设计"你只能答"上面定的"。在教学项目里，**每一个取舍你都真的面对过**。所以主动引导面试官往这个方向问："这个项目里所有的技术选型都是我自己做的，您可以随便挑一个问为什么。"

**优势二：踩的坑都是真踩的。**
真实项目里的 bug 常常是别人修的、或者修的时候你在开会。而这里 —— `IsAlive()` 恒真、watch 遇 compaction 永久退出、`skillsModTime` 永不命中、`distributed.go:77` 的死代码 —— **每一个你都能说出是怎么发现的、当时在想什么、为什么还没修**。这类细节编不出来。

**优势三：没有历史包袱，所以可以承认不完美。**
真实项目里说"这块我做得不好"是有职业风险的。教学项目里说这句话是**加分** —— 它说明你的评价标准比这个项目本身高。**主动说三处缺陷，比被动承认一处强十倍。**

### 面试官可能接着问的两个问题

**"那你从这个项目里学到最重要的一件事是什么？"**

不要答"学会了 Go"或"理解了 Agent 原理"这种。给一个**具体的、带代价的**判断：

> "最重要的是：**描述是容易的，机制是难的。** 我一开始写 RAG，觉得就是'切块、embedding、检索'三步；写完才发现真正的坑都在细节里 —— 中文按字节切会切坏、阈值放在结果侧会让结果变空而不是变好、每次重启都往向量库追加一份重复数据。这三个问题在架构图上完全看不出来。所以我现在看任何技术方案，第一反应是问'它在边界上会怎么坏'。"

**"如果让你重做一遍，你会改什么？"**

给三条，**按优先级排序**，每条都要有理由：

> "三件事，按优先级：
> **第一是补测试。** 整个仓库 0 个 `*_test.go`，这是最大的缺口 —— 因为并发相关的设计（引用计数、Lane、锁）**不写测试就没法证明它是对的**，我现在的论证都是推演。
> **第二是把并发边界补上。** 服务端没有并发闸门（`globalMaxConcurrent` 配了不读），LLM 调用没有超时，工具 `Execute` 接口不带 `context.Context`（`pkg/tool/tool.go:4-16`）—— 这是超时和取消**无法实现的结构性原因**，要改得从接口签名开始改。
> **第三是接可观测。** 现在两个指标没有写入点、Histogram 分桶对 LLM 场景完全错位、没有 tracing。没有数据就没法谈优化。"

**注意这三条的顺序是有说法的：** 测试在前（影响正确性）→ 并发闸门在中（影响稳定性）→ 可观测在后（影响优化能力）。**说出这个排序本身就是判断力。**
