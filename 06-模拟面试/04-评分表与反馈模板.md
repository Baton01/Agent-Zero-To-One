# 评分表与反馈模板

> **这份文件解决两个问题：怎么把"感觉答得还行"变成一个能比较的数字，以及怎么把"你这块不行"说成对方知道下一步做什么的话。**
> **配套：** [[06-模拟面试/01-面试全流程脚本]]（流程）· [[06-模拟面试/02-面试官提示词]]（评分协议在提示词里的简版）· [[06-模拟面试/05-面试记录]]（记录往哪写）
> **一句话：** 没有 rubric 的模拟面试，复盘只能靠印象；**而印象在两周后会变成"我记得当时答得还行"。**

## 一、七个评分维度与权重

权重不是拍脑袋定的，它对应的是招聘方真实的注意力分配——**背概念的人太多了，能讲清取舍和踩坑的人太少了**，所以「工程实现」与「技术取舍」合计占 40%。

| 维度 | 权重 | 一句话定义 | 主要在哪一轮考 |
|---|---|---|---|
| **工程实现** | 20% | 知道怎么做、参数是多少、失败了怎么办 | 知识轮 + 项目深挖轮 |
| **技术取舍** | 20% | 说得出被放弃方案的代价，以及什么时候改选它 | 知识轮 + 项目深挖轮 |
| **故障排查** | 15% | 有归因顺序，先分段定位再动手 | 知识轮 + 项目深挖轮 |
| **概念理解** | 15% | 给出的标准是可判定的，不是形容词 | 知识轮 |
| **编码能力** | 10% | 先说思路再写代码，自己给测试用例，报得出复杂度 | 算法轮 |
| **系统设计** | 10% | 先澄清约束，再画主链路，再补失败路径与演进 | 系统设计轮 |
| **沟通表达** | 10% | 结论先行、有数字、被压缩时能三句话讲完 | 全轮 + 行为轮 |

**算法岗 / 后端岗可以调权重**（把编码能力提到 20%、系统设计提到 15%），但**七个维度都要出现**——只按一个维度打分，等于没有评分表。

## 二、通用分档（每题先按 0/1/2 记，汇总时换算）

| 分 | 名字 | 判定标准（三者同时满足才算下一档） |
|---|---|---|
| **0** | 不会 | 答不出，或给完三档提示仍答不出；或答案完全是错的 |
| **1** | 半懂 | 方向对，但**机制、数字、边界**三项里缺至少一项；或给提示后才答出来 |
| **2** | 掌握 | 结论清楚 + 有机制或数字 + **主动**说了边界（不等你问） |

**维度换算公式：** 维度分 = 该维度相关题目的得分之和 ÷ 该维度题数 ÷ 2 × 3，保留一位小数。也就是把 0–2 的均分线性映射到 0–3。

例：工程实现相关 5 题，得分 2+2+1+2+1 = 8。8 ÷ 5 = 1.6（均分）→ 1.6 ÷ 2 × 3 = **2.4 分**。

## 三、每个维度的 rubric（照着打，不要凭感觉）

### 3.1 工程实现（0–3 分）

| 分 | 表现 |
|---|---|
| 0 | 只会说"用 XX 就行"，没有任何参数、机制或失败处理 |
| 1 | 说得出模块名与大致做法，但给不出参数；被问"失败了怎么办"才开始想 |
| 2 | 说得出具体参数与机制（8 步闸门、70% 水位、Top-30 → Rerank → Top-5），并主动说失败与降级路径 |
| 3 | 在 2 的基础上，说得出「为什么是这个值」（它是测出来的还是拍的），以及改动过它的依据 |

**「什么表现算 2 分」的具体锚点：**

- 说上下文压缩：**同时**给出触发水位（70%–80%）、压缩产出三件套（摘要 / 关键实体逐字 / 待办）、以及怎么验证没丢信息（must_keep 清单或回归样本）
- 说工具失败处理：**执行层不抛异常**，失败转结构化结果（含 retryable 字段），错误信息写成"说明书"（列出可用替代动作）
- 说评测：给出评测集条数与来源、判定方式（代码断言占多少、人工占多少）、以及一个反指标

### 3.2 技术取舍（0–3 分）

| 分 | 表现 |
|---|---|
| 0 | 只会说自己选的方案好，或贬低被放弃的方案（"微调太贵了""多 Agent 就是噱头"） |
| 1 | 说得出两条候选路线，但说不由被放弃方案的适用场景与代价 |
| 2 | 说得出被放弃方案的**代价与适用条件**，并给出自己的约束（数据规模、更新频率、团队能力） |
| 3 | 在 2 的基础上，说得出「什么信号出现时我会改选它」 |

**「什么表现算 2 分」的具体锚点：**

- 被问"为什么不用微调"：先承认微调在固定风格与格式上更强，再说自己的约束（文档每周改 3–5 处、必须可溯源），最后给数据（RAG 方案引用准确率 0.93 已经够用）
- 被问"为什么不用多 Agent"：先给单 Agent 基线（输入 token 9200），再说拆完的代价（11400、涨 24%、串行更慢），最后说四条门槛一条不命中
- 被问"为什么不用现成框架"：说清框架强在哪（断点续跑、多分支），再说自己的任务（20 秒内跑完、无中断需求），最后说代价（调试要穿过框架层）

### 3.3 故障排查（0–3 分）

| 分 | 表现 |
|---|---|
| 0 | 没有顺序，靠猜（"先看 prompt 写得对不对"），或直接跳到解决方案 |
| 1 | 说得出"要分段测"，但说不出分段之后怎么判方向 |
| 2 | 给得出定位顺序（分段 → 对比 → 看 trace → 最小复现 → 一次只改一个变量），并按**集中度**判方向 |
| 3 | 在 2 的基础上，有真实故障的完整链条（现象带数字 → 定位 → 根因 → 修法 → 修完的数字 → 沉淀的机制） |

**「什么表现算 2 分」的具体锚点：**

- 引用准确率下降：先说分段测（0.93→0.71 → 检索层 Recall@5 0.88→0.62），再说定位（换回上一版索引恢复 → 说明是索引问题），最后说根因与机制（扫描件乱码进索引 → 加排除清单与告警）
- Agent 绕圈：先看 `stop_reason` 分布（repeat_action 从 4% 涨到 17%），再看失败样本的观察结果（`{"error": "未收录"}` 让模型无法决策），最后给修法（错误信息写成说明书、同签名第 2 次警告第 3 次终止）
- 成本异常：先按 task_id 聚合分诊（是请求数变多还是单请求变长），再查两个隐形放大器（解析失败重试循环、工具返回全量列表）

### 3.4 概念理解（0–3 分）

| 分 | 表现 |
|---|---|
| 0 | 用形容词回答（"Agent 就是能自主规划的 AI 系统"），给不出可判定的标准 |
| 1 | 背得出定义与术语，但举不出边界例子 |
| 2 | 给出的标准**可判定**（能拿它去判断一个具体系统算不算 Agent），并主动举一个反例 |
| 3 | 在 2 的基础上，说得出这个概念与相邻概念的机制差异（ReAct 与 Function Calling 是范式与协议的区别） |

**「什么表现算 2 分」的具体锚点：**

- Agent 与 Workflow 的分界：控制流决定权在代码还是模型 + 两连问（下一次迭代谁决定、循环何时结束谁决定）+ 反例（流水线里嵌一次 LLM 分类不算 Agent）
- 上下文工程与 Prompt 工程：关注点不同（这一次的措辞 vs 整个窗口的内容组成与生命周期）+ 四个动作（选择、压缩、隔离、编排）+ 包含关系
- MCP：乘法变加法（M×N → M+N）+ 三种能力按决策者分 + 边界（只解决接得上，不解决会不会用）

### 3.5 编码能力（0–3 分）

| 分 | 表现 |
|---|---|
| 0 | 写不出来，或写出来是错的且自己不知道 |
| 1 | 写得出暴力解法，但看不出可优化点；或最优解靠背，讲不清为什么对 |
| 2 | 先说暴力解法并指出慢在哪 + 写出优化解 + 自己给测试用例 + 报复杂度 |
| 3 | 在 2 的基础上，主动说边界用例（重复元素、无解、溢出）并主动提一个变体的解法 |

**「什么表现算 2 分」的具体锚点：**

- 写完后自己跑一个例子（不是等面试官问"你对一下"）
- 报复杂度时报的是自己代码的复杂度，而不是背下来的标准答案
- 边界条件主动说（数组为空、只有一个元素、目标值不存在）

### 3.6 系统设计（0–3 分）

| 分 | 表现 |
|---|---|
| 0 | 上来就说技术选型（"用 Milvus 加 LangChain"），不澄清约束 |
| 1 | 画得出主链路，但没有失败路径、没有成本与规模估算 |
| 2 | 先澄清约束（规模、租户、延迟、成本）+ 主链路按数据流讲 3–5 个模块 + 主动补失败路径与幂等 |
| 3 | 在 2 的基础上，给出演进路径与触发信号（"等出现断点续跑需求我再引入框架"），并给出指标如何度量 |

**「什么表现算 2 分」的具体锚点：**

- 10 万文档知识库：先算块数（10 万 × 20 = 200 万）再谈选型；主动提 pre-filter 与索引一致性
- 30 步分析 Agent：状态外置（槽位与任务清单落盘）+ 四道闸门 + 恢复语义，而不是只设 max_steps
- 多租户平台：隔离分层说（数据用 pre-filter、密钥按租户、工具权限白名单、日志脱敏）

### 3.7 沟通表达（0–3 分）

| 分 | 表现 |
|---|---|
| 0 | 讲了五分钟没有结论；或全程只有架构名词没有数字 |
| 1 | 结论有但埋在最后；被要求"三句话讲一遍"时把原话重复一遍 |
| 2 | 结论先行（1 句结论 + 2 句依据 + 1 句边界）+ 每个结论挂一个数字或一次踩坑 |
| 3 | 在 2 的基础上，被压缩、被质疑、被追问时都不乱节奏，并能主动划边界 |

**「什么表现算 2 分」的具体锚点：**

- 项目陈述：4 分钟内讲完六段式（业务问题 → 技术选型 → 系统设计 → 评估指标 → 故障与优化 → 最终结果），每段带数字
- 被质疑"这不就是写 prompt 吗"：先接住合理部分，再用机制区分，最后给数字，全程不辩解
- 不会的题：用三段式（我没做过 → 我的理解是 X → 要验证我会先做 Y）

## 四、反馈的结构：先好后补，最后行动

**反馈必须是三段，顺序不能换。** 只讲问题会让人自我否定，只讲好的等于没讲。

### 4.1 第一段：讲好的（1–2 条，必须具体）

> **模板：** 「你这题**具体做了 X**，这个动作**帮我确认了 Y**。」

- ✅ 「你在说召回率的时候主动给了口径和样本量（30 条自建评测集、判据由产品同学写），这一句让我确认你是真跑过评测的。」
- ❌ 「整体表现不错，基础挺扎实的。」

### 4.2 第二段：讲要补的（不超过 3 条，每条带证据）

> **模板：** 「第 X 题你说了 A，但**没提 B**。这在面试官听来的信号是 C。」

- ✅ 「K11 你说了压缩历史，但没说压缩完之后怎么验证关键信息没丢。面试官听到这里会判断：你还没被『摘要把订单号压没了』坑过。」
- ❌ 「上下文这块还要再深入一下。」

**为什么最多 3 条：** 一次能改的只有 1–2 件事，列 10 条的效果等于一条都没记住。

### 4.3 第三段：给行动项（每条当天就能开始）

> **模板：** 「下一步你只要做一件事：**（具体动作）**，做完拿（具体产物）再跑一次这一轮。」

- ✅ 「今晚做一件事：把 [[docs/第08章 RAG全链路]] 的评估一节重读一遍，从中挑 2 条多跳样本补进你的 30 条评测集，重跑一次指标。下周再跑项目深挖轮。」
- ❌ 「多练练 RAG 这块。」

**判据：一条行动项如果明天早上你还不知道该打开哪个文件，它就是废话。**

## 五、反馈话术：把"你不行"说成"你知道该怎么改"

**核心手法只有一个：把评价换成事实，把"你不好"换成"这个动作缺了什么"。**

| ❌ 伤人且没用 | ✅ 可用且能改 |
|---|---|
| 「你这块理解得不够深。」 | 「你答对了机制，但没给数字——面试官没法判断你是用过还是读过。」 |
| 「你项目讲得太乱了。」 | 「你的项目陈述里，技术选型放在了业务问题前面，所以我前两分钟不知道你在解决谁的问题。」 |
| 「你这回答太浅了。」 | 「你说『用了向量数据库』，被追问『为什么不用 ES』时停了。这个问题在 [[02-Wiki/面试题库/02-RAG高频面试题]] 的实现题里有现成答法，改一遍就行。」 |
| 「沟通还需要加强。」 | 「你在被要求『三句话讲一遍』时把原话又讲了一遍。改成『结论 + 依据 + 边界』的结构，再录一次音对比。」 |
| 「感觉你不太行。」 | 「按今天的结果：概念理解 2.3、工程实现 1.5。差距集中在『数字说不出口径』这一类，补法很具体——给你的每个指标写一句口径，写在简历旁边。」 |
| 「你答得挺好的，没什么问题。」 | 「你三题都答到了 2 分。下一层的问题是：你只说了自己的方案，没说被放弃方案的代价——这是从 2 到 3 唯一缺的那一块。」 |

**三条纪律：**

1. **不留情面地说事实，不留情面地说下一步**——但要**给人留台阶**，不说"你不适合这个方向"
2. **每条批评后面必须跟一个可执行动作**，否则那句话只是在发泄
3. **不要用"可能""感觉""有点"这类软化词**——「你有点没讲清口径」不如「你这题没讲口径」清楚

## 七、怎么看分数：分布比总分重要

**总分 2.0 和总分 2.0 是两回事。** 同样的总分，不同的分布指向完全不同的下一步。

| 分数分布 | 说明什么 | 下一步做什么 |
|---|---|---|
| 概念理解高（≥2.3），工程实现/技术取舍低（≤1.5） | 书读得多，手做得少 | **去把项目补完再练**——不是练表达，是练动手 |
| 工程实现高，技术取舍低 | 会做但不知道为什么这样做 | 每个技术决策补一条"被放弃的方案 + 它的代价"，写在本子上 |
| 工程实现 + 技术取舍都高，故障排查低 | 会搭不会修 | 给自己造一次故障：故意删索引、故意改一个选择器，记录定位过程 |
| 概念理解 + 技术取舍高，编码能力低 | 思路清楚但手感差 | 按 [[05-算法面试/02-专题总结/13-复杂度速查表]] 的顺序刷 Hot 100，每周 6 题 |
| 全部在 1.0–1.5 之间（都很平均） | 每一块都"知道一点" | 停一停：先把一个项目做完整（含评测集与一个故障故事），再回来练 |
| 编码/知识都不低，沟通表达低（≤1.5） | 会做不会讲 | **只练表达**：90 秒自我介绍录三遍、每个项目按六段式录音计时、被压缩时三句话复述 |
| 沟通表达高，其它都低 | 讲得漂亮但内容薄 | 警惕"面试表演"——面试官追问两层就会露；回去补数字与机制 |
| 系统设计低、其它都不低 | 缺全局视角 | 练 [[06-模拟面试/03-题库与追问链]] 的系统设计轮，每题都按"澄清约束 → 主链路 → 失败路径 → 指标 → 演进"五段讲一遍 |

**两条读数纪律：**

1. **总分只和自己的上一场比**，不要和别人比——每个人的起点、方向、时间预算都不一样
2. **超过 2.5 分不要高兴太早**——那是"这一轮的题你已经熟了"，该换一套更难的了（去跑完整终面，或把追问深度调深）

------

> **最后一句：** 评分的意义不是给你一个分数，而是**把"我好像不太行"变成"我第 3 题缺了口径、第 11 题缺了验证动作"**——能被指出来的问题，都是能改的问题。
