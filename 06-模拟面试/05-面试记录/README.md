# 面试记录

> **这里是归档每一次模拟面试的地方。** 每一场建一个文件，命名成 `YYYY-MM-DD-场次.md`，例如 `2026-10-08-标准技术面.md`。
> **配套：** [[06-模拟面试/README]]（怎么用这套模拟面试）· [[06-模拟面试/04-评分表与反馈模板]]（评分标准与反馈话术）

## 一、为什么必须写下来

不归档的模拟面试，两周后你只会记得一个模糊的印象：「当时好像答得还行。」

而真正有用的信息全在细节里：**卡住的是哪几题、缺的是机制还是数字、是知识问题是表达问题。** 这些不写下来，第二次练还是从零开始——你会反复在同一个坑上摔，却以为是"运气不好"。

**一份记录要能回答三个问题：**

1. 这次卡在哪几题？（题号）
2. 卡的原因是**不知道**，还是**知道但说不出来**？（这两件事的补法完全不同）
3. 下一步具体做什么？（打开哪个文件、做什么动作）

## 三、复练节奏：隔两周，打同一套题

**单次分数没有意义，分数变化才有意义。**

- **同一套题，隔两周再打一次**，对比两次的分数与卡住的题号。这才能看出"补的东西有没有补进去"
- 分数涨了但卡住的题号没变 → 你补的是会的东西，短板一点没动
- 分数没涨但卡住的题号变了 → 正常，说明你在换方向补，继续
- 每次至少跑到**上一场卡住的题**，答对了才算过关
- 三到四场之后换一套题（换轮次组合、或把追问深度调深），否则你会开始"背自己出的题"

**什么时候必须重练：** 换了目标岗位、补完一个项目、或者距上一场超过一个月。

## 四、备份：这些记录是你的资产

面试记录是这个项目里**最不该丢的东西**——它记录的是你的真实水位与成长曲线，比任何笔记都值钱。

- **用 Git 定期提交**：`git add 06-模拟面试/05-面试记录 && git commit -m "面试记录：2026-10-08 标准技术面"`（与 [[学习中枢]] 第 6.4 节的备份原则一致）
- [[03-学习笔记/]] 与 [[04-Outputs/]] 同样值得备份，这三处是"你自己的东西"
- 记录里如果写了公司的真实信息（面试官的话术、内部指标），**提交前先脱敏**

## 五、往上一步：从记录到简历

累计三场之后，回头看这三份记录，你会发现一个规律：**反复卡住的那一类问题，就是你简历上最不该写的那一条。**

反过来也成立：**连续两场都答到 2 分的那一块，才是你可以写进简历、并且在面试里往深了讲的强项。**

简历与项目表达的写法见 [[01-Raw/03-项目阶梯与能力对照表]] 第四节与 [[02-Wiki/面试题库/03-项目表达与追问应对]]。
