## 轮次：算法轮

> **一轮只够问一到两道题，不要贪多。** 算法轮看的不是"你刷了多少题"，而是"遇到没见过的问题，你会不会先说思路、先用例子验证边界"。12 分钟里必须听到的四件事：先说暴力解法、再说优化方向、自己给测试用例、报复杂度。
> **候选人卡住时的三档提示：** ①"你打算用什么数据结构撑住这个操作？"→ ②"如果是暴力，你觉得哪里重复算了？"→ ③"试试先把数组排好序再看"。给了提示之后答出来，记 1 分；给到第三档还答不出来，换题。

### A1 · 给定一个整数数组和一个目标值，找出和为目标值的两个数的下标

- **维度**：编码能力
- **难度**：基础
- **岗位**：全部
- **时长**：10
- **考察**：能否想到用哈希表把 O(n²) 降到 O(n)，以及边界处理是否严谨
- **题面**：一个整数数组 nums 和一个目标值 target，返回和为 target 的两个数的下标，每个输入只对应一个答案，同一个元素不能重复使用
- **参考思路**：
  - 先说暴力双层循环是 O(n²)，明确慢在哪：每个数都要和其余所有数配对一次
  - 一遍哈希：遍历时先查 target - num 在不在表里，再把当前值存进去
  - 强调「先查后存」是为了避免同一个元素用两次（[3,3] 配 target 6 是经典反例）
  - 报复杂度：时间 O(n)、空间 O(n)，本质是拿空间换时间
- **加分**：
  - 主动报出时间与空间复杂度，不等面试官问
  - 主动提边界：重复元素、负数、无解时返回什么
  - 主动说「如果要求返回所有不重复的数对，要先排序再用双指针去重」
- **扣分**：
  - 只说「用哈希」但讲不清为什么能一遍扫完
  - 没意识到同一个元素不能用两次，先存后查还浑然不觉
  - 写完代码不问「要不要处理无解的情况」
- **追问**：
  - 如果数组已经排好序了，还能怎么做？复杂度是多少？
  - 如果要求返回所有不重复的数对，怎么改？
- **关联**：`05-算法面试/02-专题总结/01-哈希表.md`、`05-算法面试/03-题目详解/1-两数之和.md`

### A2 · 找出字符串里不含重复字符的最长子串，返回它的长度

- **维度**：编码能力
- **难度**：进阶
- **岗位**：全部
- **时长**：12
- **考察**：滑动窗口与哈希表的配合，以及「左边界怎么跳」这个最容易写错的细节
- **题面**：给定一个字符串 s，找出其中不含重复字符的最长子串，返回它的长度，比如 abcabcbb 的答案是 3
- **参考思路**：
  - 先给暴力：枚举所有子串再逐个判断是否重复，O(n³) 或退一步 O(n²)
  - 滑动窗口：右指针不断扩，遇到重复字符就移动左指针，窗口内始终无重复
  - 关键细节：哈希表存字符最近一次出现的下标，左边界只能往右跳，写成 left = max(left, last[c] + 1)
  - 报复杂度：每个字符进出窗口各一次，时间 O(n)、空间 O(字符集大小)
- **加分**：
  - 主动解释「为什么存下标而不是存布尔值」——存下标才能一次跳到位
  - 主动给测试用例：空串、bbbbb、pwwkew（答案是 3，但不是 pww 那一段）
- **扣分**：
  - 左边界用 while 一格一格挪，被问复杂度时说不出它总共只挪了 n 次
  - 遇到重复字符就把整个窗口清空重来，漏掉 pwwkew 这类用例
- **追问**：
  - 如果允许最多 k 个重复字符，怎么改？
  - 如果字符集确定是 ASCII，空间上你会怎么优化？
- **关联**：`05-算法面试/02-专题总结/02-双指针与滑动窗口.md`、`05-算法面试/03-题目详解/3-无重复字符的最长子串.md`

### A3 · 找出数组中所有和为 0 且不重复的三元组

- **维度**：编码能力
- **难度**：进阶
- **岗位**：全部
- **时长**：15
- **考察**：排序加双指针的组合，以及去重逻辑是否严谨——这题的去重是最大的坑
- **题面**：给你一个整数数组 nums，找出所有和为 0 且不重复的三元组，答案里不能有重复的组合
- **参考思路**：
  - 先说暴力三重循环是 O(n³)，再指出排序不会改变答案集合，但能让双指针成立
  - 排序后固定第一个数，剩下两数用左右指针夹逼：和太小左指针右移，太大右指针左移
  - 去重分三层：第一个数跳过相同值、左右指针跳过相同值；跳过时必须和「前一个」比较
  - 剪枝：排序后第一个数已经大于 0 就直接结束
- **加分**：
  - 主动解释「为什么跳过的是 nums[i] == nums[i-1] 而不是 nums[i+1]」——后者会漏解
  - 报复杂度：排序 O(n log n) 加双指针 O(n²)，整体 O(n²)、空间 O(1)（不计结果）
- **扣分**：
  - 用 set 去重却说不出代价（元组哈希与额外排序），被追问就含糊
  - 去重只做一层，[-1,0,1,2,-1,-4] 这个用例直接输出重复三元组
- **追问**：
  - 两数之和的双指针解法为什么要求数组有序？不有序会怎样？
  - 如果要求和为 target 的四元组，你的框架怎么改？
- **关联**：`05-算法面试/02-专题总结/02-双指针与滑动窗口.md`、`05-算法面试/03-题目详解/15-三数之和.md`

### A4 · 反转一个单链表，说说迭代和递归两种写法

- **维度**：编码能力
- **难度**：基础
- **岗位**：全部
- **时长**：10
- **考察**：指针操作的严谨性，以及能不能自己发现递归的栈空间问题
- **题面**：给你单链表的头节点 head，请反转链表并返回反转后的链表
- **参考思路**：
  - 迭代：三个指针 prev / cur / next，先把 next 存下来再改 cur.next，否则链会断
  - 递归：先反转后面的部分，再把 head.next.next 指向 head，最后把 head.next 置空
  - 两个边界：空链表、只有一个节点，都要能原样返回
  - 报复杂度：迭代 O(n) 时间 O(1) 空间；递归 O(n) 时间 O(n) 栈空间
- **加分**：
  - 主动说「递归的 O(n) 栈空间在长链表上会爆栈，生产里我会写迭代」
  - 主动在纸上画出指针变化过程，一步一步说清楚
- **扣分**：
  - 写迭代时没有先保存 next，指着已经断掉的链说「这里再指回去就行」
  - 递归写法忘记把 head.next 置空，结果形成环，被问怎么验证才发现
- **追问**：
  - 如果要求每 k 个一组反转，你的迭代写法要怎么改？
  - 链表有 100 万个节点，递归会怎样？
- **关联**：`05-算法面试/02-专题总结/04-链表.md`、`05-算法面试/03-题目详解/206-反转链表.md`

### A5 · 判断链表是否有环，如果有，找出入环的第一个节点

- **维度**：编码能力
- **难度**：进阶
- **岗位**：全部
- **时长**：12
- **考察**：快慢指针的原理，以及能不能说清「为什么第二次相遇点就是环入口」这个推导
- **题面**：给定一个链表，判断它是否有环，如果有环请返回入环的第一个节点，没有环返回 null
- **参考思路**：
  - 第一问：快慢指针，快指针每次两步、慢指针一步，相遇即有环
  - 第二问：相遇后把一个指针放回头节点，两个指针同速前进，再次相遇就是入环节点
  - 讲清推导：设头到入口为 a、入口到相遇点为 b、相遇点回入口为 c，可得 a 与 c 同余于环长
  - 报复杂度：O(n) 时间、O(1) 空间；哈希表法也要会（时间一样，空间 O(n)，但更直观）
- **加分**：
  - 先给哈希表解法做保底，再给快慢指针，说「面试里我先写对的、再写优的」
  - 主动指出「环形数组、寻找重复数（LeetCode 287）用的是同一套快慢指针」
- **扣分**：
  - 只会判断有环，说不出入环点怎么求，或者直接把相遇点当成入环点
  - 快指针走两步时没有先判 next 与 next.next 是否为空，无环链表直接空指针异常
- **追问**：
  - 为什么慢指针在相遇之前一定还没走完一圈？
  - 如果还要求出环的长度，怎么求？
- **关联**：`05-算法面试/02-专题总结/04-链表.md`、`05-算法面试/03-题目详解/142-环形链表II.md`

### A6 · 二叉树的层序遍历，按层返回节点值

- **维度**：编码能力
- **难度**：基础
- **岗位**：全部
- **时长**：10
- **考察**：BFS 模板的掌握度，以及「怎么知道一层结束了」这个细节
- **题面**：给你二叉树的根节点 root，返回节点值的层序遍历，即逐层地、从左到右访问所有节点，并且要按层分组
- **参考思路**：
  - 队列加层长度：每轮先取当前队列长度，只弹这么多，剩下的自然就是下一层
  - 也可以用两个列表分别装当前层与下一层，代价是多一份空间
  - 报复杂度：每个节点进出队列一次，时间 O(n)、空间 O(树的最大宽度)
- **加分**：
  - 主动提变体：「锯齿形层序」和「二叉树右视图」都是这一套，只是层内顺序或取值位置不同
  - 主动说「这里用 deque，不用 list.pop(0)，后者每次是 O(n)」
- **扣分**：
  - 每轮不问长度、直接 while queue 弹出，结果所有节点混成一个列表
  - 用 list.pop(0) 且对复杂度问题毫无反应
- **追问**：
  - 如果要求每层从右往左输出，改哪里？
  - 如果只要每层最右边的那个节点呢？
- **关联**：`05-算法面试/02-专题总结/05-二叉树.md`、`05-算法面试/03-题目详解/102-二叉树的层序遍历.md`

### A7 · 判断一个只含括号的字符串是否有效

- **维度**：编码能力
- **难度**：基础
- **岗位**：全部
- **时长**：8
- **考察**：栈的基本功，以及是否主动处理了两类边界——长度奇数、右括号多余
- **题面**：给定一个只包括小括号、中括号、大括号的字符串，判断它是否有效——左括号必须用同类型的右括号按正确顺序闭合
- **参考思路**：
  - 左括号入栈，遇到右括号就检查栈顶是否匹配，不匹配或栈为空直接返回 false
  - 遍历结束后栈必须为空，否则说明还有未闭合的左括号
  - 字符串长度是奇数可以直接返回 false，这是最省事的剪枝
- **加分**：
  - 说「用字典把右括号映射到左括号，比写三组 if 更好扩展」
  - 主动说「括号种类如果真的会动态增加，字典这套结构不用改」
- **扣分**：
  - 只比较左右括号的数量，([)] 这种会被判成有效
  - 忘记遍历结束后判断栈是否为空
- **追问**：
  - 如果要求返回最长有效括号子串的长度呢？思路会变成什么？
  - 栈里存下标而不是存字符，能多解决什么问题？
- **关联**：`05-算法面试/02-专题总结/06-栈与堆.md`、`05-算法面试/03-题目详解/20-有效的括号.md`

### A8 · 跳跃游戏：每个位置写着你能跳的最大长度，判断能不能到终点

- **维度**：编码能力
- **难度**：进阶
- **岗位**：全部
- **时长**：10
- **考察**：贪心的正确性论证，以及遇到更省的做法时会不会主动放弃 DP
- **题面**：给定一个非负整数数组 nums，你最初位于数组的第一个下标，每个元素代表你在该位置可以跳跃的最大长度，判断你是否能够到达最后一个下标
- **参考思路**：
  - 贪心只维护一个量：当前能到达的最远下标 max_reach
  - 遍历时若 i 超过 max_reach，说明这个位置根本到不了，直接返回 false；否则用 i + nums[i] 更新 max_reach
  - 讲清为什么贪心是对的：能不能到终点只取决于最远能到哪，与具体跳法无关
  - 报复杂度：时间 O(n)、空间 O(1)；对比 DP 的 O(n²) 更能说明取舍
- **加分**：
  - 主动说「这题用 DP 也能做，dp[i] 表示能否到达，但贪心更省——前提是能说清贪心为什么成立」
  - 主动提「跳跃游戏 II 求最少步数，要在贪心的基础上多记一层当前步的边界」
- **扣分**：
  - 写成回溯枚举所有跳法，被问复杂度才发现是指数级
  - 只会说「贪心就行」，追问「为什么这样贪是对的」时答不上来
- **追问**：
  - 跳跃游戏 II 求最少跳跃次数，你的贪心要怎么改？
  - 什么情况下贪心会失效、必须退回 DP？举一个你刷过的例子
- **关联**：`05-算法面试/02-专题总结/11-贪心算法.md`、`05-算法面试/03-题目详解/55-跳跃游戏.md`

### A9 · 二维网格里 '1' 是陆地、'0' 是水，计算岛屿的数量

- **维度**：编码能力
- **难度**：进阶
- **岗位**：全部
- **时长**：12
- **考察**：图的遍历模板，以及会不会想过「递归深度」这个现实问题
- **题面**：给你一个由 '1' 和 '0' 组成的二维网格，岛屿由水平或垂直方向相邻的陆地连接而成，请计算网格中岛屿的数量
- **参考思路**：
  - 遍历整个网格，遇到 '1' 就计数加一，并把这一整片陆地「淹没」（把访问过的 '1' 改成 '0'）
  - 淹没用 DFS 或 BFS 都行，方向是上下左右四个；注意越界判断
  - 报复杂度：O(m×n) 时间，每个格子最多被访问一次；空间取决于递归深度或队列宽度
- **加分**：
  - 主动问「网格多大」——如果是 1000×1000 的退化地形，递归 DFS 会爆栈，应该换迭代或显式栈
  - 主动说是同构题：岛屿最大面积、封闭岛屿、被围绕的区域，都是「淹没法」这一套
- **扣分**：
  - DFS 里没有先把当前格子标记就继续递归，导致重复访问甚至死循环
  - 用了额外的 visited 数组却说不清它和「直接改原数组」的取舍
- **追问**：
  - 如果要求最大岛屿面积，你的代码要加什么？
  - 如果陆地可以斜着连接（八个方向），改哪里？什么时候这两个版本答案会不同？
- **关联**：`05-算法面试/02-专题总结/07-图论.md`、`05-算法面试/03-题目详解/200-岛屿数量.md`

### A10 · 给定一个不含重复数字的数组，返回它的所有全排列

- **维度**：编码能力
- **难度**：进阶
- **岗位**：全部
- **时长**：12
- **考察**：回溯模板与状态重置，以及能不能说清剪枝与复杂度
- **题面**：给定一个不含重复数字的数组 nums，返回其所有可能的全排列，可以按任意顺序返回答案
- **参考思路**：
  - 标准回溯：used 数组标记已选，路径长度等于 n 时收集结果并返回
  - 关键动作是「选完要撤销」：path.pop() 与 used[i] = False，忘记撤销是这题的头号错误
  - 复杂度：叶子节点有 n! 个，每层循环 O(n)，所以时间 O(n × n!)，空间 O(n)（不计结果）
- **加分**：
  - 主动说「如果有重复元素，要先排序再在同一层跳过重复值，这是全排列 II 的正确做法」
  - 主动说「收集结果时要拷贝一份 path 的副本，直接塞引用最后会全是空列表」
- **扣分**：
  - 忘记撤销 used 或 path，结果只输出了一条路径
  - 把复杂度说成 n!，漏掉每层循环贡献的那个 n
- **追问**：
  - 全排列 II 有重复数字，你的去重写在哪一层？
  - 如果只要第 k 个排列，还需要枚举全部吗？
- **关联**：`05-算法面试/02-专题总结/08-回溯算法.md`、`05-算法面试/03-题目详解/46-全排列.md`

### A11 · 在一个旋转过的有序数组里搜索目标值

- **维度**：编码能力
- **难度**：进阶
- **岗位**：全部
- **时长**：12
- **考察**：二分的边界把控，以及在「局部有序」的结构下还能不能维持 O(log n)
- **题面**：一个原本升序的整数数组在某个未知下标上做了旋转，请你在数组中搜索 target，存在返回下标、否则返回 -1，要求 O(log n)
- **参考思路**：
  - 二分的每一轮，总有一半是有序的：用 nums[left] <= nums[mid] 判断左半有序，否则右半有序
  - 在有序的那一半里判断 target 是否落在区间内，据此决定收缩左边还是右边
  - 边界三件事：`<=` 与 `<` 的选择、mid 用 left + (right - left) // 2 防溢出、循环终止条件
- **加分**：
  - 主动说「如果有重复元素，nums[left] == nums[mid] 时就无法判断哪边有序，只能 left += 1，最坏退化到 O(n)」
  - 先用几个小数组把边界跑一遍：[4,5,6,7,0,1,2]、[3,1]、[1]
- **扣分**：
  - 先找旋转点再做两次二分，但 target 该落在哪一段判断不清，写了一大堆分支还过不了
  - 二分写成 left = mid 导致死循环，调试时才发现
- **追问**：
  - 找旋转数组最小值那题怎么改？和这题的判断条件差在哪？
  - 为什么这题特别容易写出死循环？你自己的二分模板是什么样？
- **关联**：`05-算法面试/02-专题总结/09-二分查找.md`、`05-算法面试/03-题目详解/33-搜索旋转排序数组.md`

### A12 · 爬楼梯：每次可以爬 1 或 2 个台阶，爬到楼顶有多少种方法

- **维度**：编码能力
- **难度**：基础
- **岗位**：全部
- **时长**：10
- **考察**：能不能从递归走到递推、再压缩空间，以及说清「为什么这就是斐波那契」
- **题面**：假设你正在爬楼梯，需要 n 阶才能到达楼顶，每次可以爬 1 或 2 个台阶，问有多少种不同的方法可以爬到楼顶
- **参考思路**：
  - 先给状态定义与转移：dp[i] = dp[i-1] + dp[i-2]，因为最后一步要么从 i-1 走一阶，要么从 i-2 走两阶
  - 再给优化：只依赖前两个状态，两个变量滚动即可，空间从 O(n) 降到 O(1)
  - 边界：n 为 0、1、2 时分别是什么；提到递归写法要主动补一句「会大量重复计算，必须记忆化」
- **加分**：
  - 主动指出「这题本质是斐波那契，n 很大时要换矩阵快速幂或大数处理」
  - 主动说「如果一次能爬 1 到 m 阶，转移就变成前面若干项的前缀和」
- **扣分**：
  - 只写得出递归，且不知道它会指数级重复计算，被问 n=40 就跑不动时才发现
  - 把状态定义说成「dp[i] 表示第 i 阶的答案」，讲不出转移是从哪来的
- **追问**：
  - 如果每次可以爬 1 到 m 阶呢？
  - 如果相邻两步不能迈相同的台阶数呢？这题的框架还能用吗？
- **关联**：`05-算法面试/02-专题总结/10-动态规划.md`、`05-算法面试/03-题目详解/70-爬楼梯.md`

### K1 · 你简历上写了 Agent——那我问你，Agent 和 Workflow 的分界线到底在哪？

- **维度**：概念理解
- **难度**：基础
- **岗位**：全部
- **时长**：4
- **考察**：能不能给出一条可操作的判定标准，而不是背一段定义
- **题面**：你说的这个 Agent，和普通的 Workflow 流水线，分界线到底在哪？给我一个能判定的标准
- **参考思路**：
  - 分界线是控制流的决定权：下一步做什么由模型现场决定，还是由代码写死
  - 判定方法两连问：下一次迭代谁决定？循环什么时候结束谁决定？两个都答「模型」才算 Agent
  - 边界：流水线里嵌一次 LLM 做分类，那只是 Workflow 里一个会思考的节点，不是 Agent
  - 补一句代价：交出去的不只是决定权，还有成本、延迟和失败模式的方差——从常数变成分布
- **加分**：
  - 主动说「交出去的是方差」，而不是只说「更灵活」
  - 主动认领自己项目里哪一步其实是写死的（说明你分得清）
- **扣分**：
  - 「Agent 就是能自主规划、自主行动的 AI 系统」——全是形容词，没有可判定的标准
  - 「用了 LangChain 就是 Agent」——把框架当成定义
  - 答完标准后追问「那你的项目算不算」，开始含糊
- **追问**：
  - 如果两个问题都答「模型」，那你靠什么防止它一直转下去？
  - 你的项目里哪一步是模型决定的，哪一步是代码写死的？举一个具体的
- **关联**：`docs/第01章 认识AI-Agent.md`

### K2 · 我们想做个智能客服，你觉得该用 Agent 还是 Workflow？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：全部
- **时长**：5
- **考察**：你会不会默认选更简单的那个——这是资深与否的分水岭
- **题面**：我们想做个智能客服，你觉得该用 Agent 还是 Workflow？说说你的判断过程
- **参考思路**：
  - 先按四问顺序过：步骤能否固定 → 输入输出契约能否定死 → 有没有两个以上需要隔离上下文的角色 → 子任务数量是否未知且可并行
  - 客服 FAQ 在第一问就命中，答案是 Workflow 加 RAG，不是 Agent
  - 只有在「客户问题需要现场决定查哪个系统、查几步」时才放开一步给 Agent
  - 结论要带依据：用灵活性换成本和方差，必须有量化论证才换
- **加分**：
  - 主动给反例清单：FAQ、固定字段抽取、每日定时报表，这三类看起来像 Agent，实际都该用 Workflow
  - 主动说「我会先写一个 Workflow 版本做 baseline，再用数据证明 Agent 版值得多出来的成本」
- **扣分**：
  - 「用 Agent 更灵活，以后扩展方便」——用灵活性换成本与方差，没有量化
  - 「现在都上 Agent，是趋势」——用趋势代替论证
  - 说不出「什么情况下该改回 Workflow」
- **追问**：
  - 你会用什么数据证明 Agent 那一版值得多出来的成本？
  - 如果业务方坚持要 Agent 呢？你怎么处理？
- **关联**：`02-Wiki/面试题库/01-Agent高频面试题.md`

### K3 · Agent 的五个部件里，哪个最容易被忽略？上线后后果是什么？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：你是不是只跑过 demo——demo 里唯一看不出问题的就是停止条件
- **题面**：Agent 的五个部件里，你觉得哪个最容易被忽略？忽略它的后果是什么？
- **参考思路**：
  - 最容易被忽略的是停止条件，因为 demo 阶段它永远不触发
  - 后果是上线后账单爆炸与请求挂死——线上表现是「看起来一切正常，但一直在烧钱」
  - 其次是状态（表现为绕圈）和工具返回值设计（模型拿到 ok=true 却不知道发生了什么）
  - 停止条件要有具体参数，不是「设个上限」四个字
- **加分**：
  - 直接给参数：max_steps=8（简单任务 5、调研类 15–20）、同签名重复第 2 次警告第 3 次终止、连续 3 次无进展终止、单任务成本上限 2 倍、墙钟 120 秒
  - 主动说「这些闸门上线后应该被触发过并有统计，没触发过说明设得太宽」
- **扣分**：
  - 「要有好的 prompt」——prompt 不是五个部件之一，也没回答「最容易被忽略」
  - 只答「要限制步数」，追问具体数字和触发条件时给不出来
- **追问**：
  - 这些闸门你在项目里真的设了吗？被触发过几次？
  - 如果是调研类任务，max_steps 你会调到多少？为什么？
- **关联**：`docs/第05章 ReAct最小Agent-Loop.md`

### K4 · ReAct 的核心贡献是什么？Thought 为什么有用？

- **维度**：概念理解
- **难度**：基础
- **岗位**：全部
- **时长**：4
- **考察**：知不知道 ReAct 到底解决了什么，而不是会背三个英文单词
- **题面**：ReAct 的核心贡献是什么？为什么中间那一步 Thought 是有用的？
- **参考思路**：
  - 论文：Yao 等，2022，arXiv:2210.03629
  - 核心贡献是把推理与行动写进同一条文本流，让中间结果成为后续决策的上下文——所以它能应对事先画不出分支的路径
  - Thought 的作用是「把上一步看到的东西写下来再决定下一步」；但它只是上下文，想对了不等于做对了
  - 边界：工具描述与参数校验不能因为有了 Thought 就省掉
- **加分**：
  - 指出「相比纯 Act，多步任务的提升来自看到上一步结果再决定，不是来自模型变聪明」
  - 报得出论文编号，而不是「我记得有篇论文」
- **扣分**：
  - 把 ReAct 说成「让模型自己思考的框架」——没有机制，也解释不了它什么时候失效
  - 只会背 Thought-Action-Observation 三个词，说不出为什么中间结果必须留在上下文里
- **追问**：
  - ReAct 什么时候会失效？给一个你遇到过的场景
  - 你怎么确认是 ReAct 起了作用，而不是模型本身够强？
- **关联**：`docs/第05章 ReAct最小Agent-Loop.md`

### K5 · Plan-and-Execute 的代价是什么？什么时候你会把它拆掉？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：Agent工程师、AI应用开发
- **时长**：4
- **考察**：会不会只讲优点——这题的分数全在代价那半边
- **题面**：Plan-and-Execute 的代价是什么？什么信号出现时你会把它拆掉？
- **参考思路**：
  - 收益是线性的成本、计划可人工审核、无依赖步骤可并行
  - 代价是「计划错则一路错到底」——它省下的推理代价，要在 replan 机制上加倍还回来
  - 触发 replan 的信号：步骤失败、连续偏离、预算消耗过半、外部状态变化
  - 拆掉的判据：执行偏离率超过 30%；工程上的常见形态是外层 Plan、内层单步 ReAct
- **加分**：
  - 报出量级参照：同一任务量级下 Workflow 约 900 token、Plan-and-Execute 约 6000、ReAct 约 8000、Reflection 约 11000
  - 主动说「省下的那部分不是消失了，是换了个地方花」
- **扣分**：
  - 「Plan 更省钱所以更好」——没提执行偏离率，也没说代价
  - 只列优点，被追问「那它的缺点呢」才开始想
- **追问**：
  - 偏离率你怎么统计？有没有真的算过？
  - replan 触发时是重规划整张计划还是只改后面几步？为什么？
- **关联**：`docs/第06章 范式进阶.md`

### K6 · Reflection 什么时候有效？什么时候是纯浪费？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：这是范式里最常被问坏的一题，答案只有一句核心
- **题面**：Reflection 什么时候有效？什么时候纯粹是浪费钱？
- **参考思路**：
  - 反思的前提是有外部信号：测试结果、编译错误、检索证据、schema 校验，任何来自模型之外的东西
  - 有信号时它显著提质量，论文依据是 Reflexion（Shinn 等，2023，arXiv:2303.11366）
  - 没有外部信号时，模型只会越改越自信但没变好——它在自己的错误里打转
  - 停止条件：两轮之后指标不升就该停，创作类任务最多一轮
- **加分**：
  - 分级说：L1 润色（主观任务，最多一轮）、L2 带 rubric 的批判（要有停止条件：指标不再提升、预算耗尽、轮数上限）
  - 主动说「创作类任务多轮反思会变啰嗦、同质化」
- **扣分**：
  - 「反思能让答案更好，一般反思两三轮」——把「没有信号也想改」当默认配置
  - 说不出停止条件，只能说「感觉差不多了就停」
- **追问**：
  - 你的 rubric 是谁写的？怎么防止模型自己批改自己的卷子？
  - 反思一轮要加多少成本？你算过吗？
- **关联**：`docs/第06章 范式进阶.md`

### K7 · 怎么提升工具调用的准确率？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：全部
- **时长**：5
- **考察**：有没有真的统计过选错率，并按统计结果去优化
- **题面**：你的 Agent 工具有十几个，怎么让模型别选错工具？
- **参考思路**：
  - description 写全五件事：干什么、何时用、何时不用、返回什么、失败长什么样
  - 合并同义工具（search_order 与 query_order 必须合并，这是选错工具的头号原因）、控制总数
  - schema 用 enum、pattern、required 把「靠模型自律」改成「靠结构约束」
  - 关键路径用 tool_choice 强制首次必须调用；再用 trace 按「实际调的工具 vs 期望工具」聚合，找 confusion pair
- **加分**：
  - 报分层阈值：1–7 个直接全量注册、8–20 个合并并补「何时不用」、20–50 个分层加载、50 个以上先路由再进循环
  - 说「大多数选错集中在 3–5 组相似工具上，改这五组就够了」
- **扣分**：
  - 「换一个更强的模型就好了」——把工具设计问题外包给模型
  - 「把 description 写详细点」——详细不等于写了「何时不用」
- **追问**：
  - 你的选错率怎么统计的？基线是多少，优化后是多少？
  - 举一个你发现的 confusion pair，你最后怎么改的？
- **关联**：`docs/第04章 工具调用.md`

### K8 · 工具执行失败了，Agent 该怎么处理？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：全部
- **时长**：5
- **考察**：你把工具失败当异常，还是当一条可以喂回模型的观察结果
- **题面**：工具执行失败了，Agent 应该怎么处理？错误信息要怎么设计？
- **参考思路**：
  - 前提：执行层永不抛异常，所有失败转成结构化结果 {ok:false, error:{code, message, retryable}} 喂回模型
  - 异常穿透主循环等于 Agent 死了——这是最致命的一种写法
  - 可重试的判据只有一句：换个参数重试有没有可能成功。超时、坏 JSON、临时不可用可以；NOT_FOUND、DENIED 不可以
  - 错误信息要写成说明书：未收录该政策，可用主题是退款/换货/发票，或调用 list_policies 查看全部
- **加分**：
  - 强调失败结果显式区分可重试与不可重试，因为模型和小模型路由都看得懂这个字段
  - 说「重试上限 + 退避 + 预算，到顶走兜底降级」
- **扣分**：
  - 「catch 住打个日志继续」——模型收到的是一条空消息，它只会再试一次一样的调用
  - 「失败就重试三次」——不区分错误类型，也没有退避
- **追问**：
  - 超时算可重试吗？如果那个操作是下单呢？
  - 你项目里失败率最高的工具是哪个？为什么它会失败？
- **关联**：`docs/第04章 工具调用.md`

### K9 · 工具从 4 个涨到 50 个，你要做的第一件事是什么？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：知不知道工具清单本身就在吃上下文——每次请求都要付一遍
- **题面**：工具从 4 个涨到 50 个，你最先做的是哪件事？为什么不是全注册进去让模型自己选？
- **参考思路**：
  - 先算账：工具 schema 常驻上下文且每次请求都付一遍，实测 4 个工具约 832 字节、8 个约 1.7 KB，几十个 MCP 工具的定义可以吃掉上万 token
  - 三个动作按序做：合并同义工具 → 描述里写「何时不用」→ 分层（先给工具目录，模型选定命名空间后再加载该组 schema）
  - 还是太多就路由：用一次轻量分类调用选出候选工具集，再进入 Agent 循环
  - 应用侧裁剪 MCP Server 暴露的工具，不要把 Server 的全部工具直接转发给模型
- **加分**：
  - 提「工具清单要像 API 一样治理」——定期清理不用的 Server、给工具名加前缀、锁版本
  - 能给出一份具体清单：哪几个工具合并成了一个、合并后轮数怎么变
- **扣分**：
  - 「都注册进去让模型自己选」——把上下文预算和选择准确率一起丢掉
  - 「一个 API 一个工具，职责单一最好」——忽略模型要多做多少编排决策
- **追问**：
  - 合并到什么粒度算合适？你的判断标准是什么？
  - 路由那一步用什么做分类？它自己错了怎么办？
- **关联**：`docs/第04章 工具调用.md`

### K10 · 工具调用全成功，模型却答错了，问题在哪？

- **维度**：故障排查
- **难度**：进阶
- **岗位**：全部
- **时长**：5
- **考察**：知不知道「成功」和「可用」是两件事
- **题面**：日志里工具调用全是成功，但模型答错了，你觉得问题出在哪？你会先看什么？
- **参考思路**：
  - 先看工具返回值——是不是只返回 {ok: true} 而没有业务关键字段（订单状态、金额、单号）
  - 模型需要的是「用来决策的最小充分信息」，不是执行成功的确认
  - 再看截断：是不是在非语义边界硬截断、且没有标 truncated: true，模型以为那就是全部
  - 再看失败表示：是不是用空值表示失败，模型会把「没有」当成「是空的」
- **加分**：
  - 说「工具返回值的设计标准是让模型少做猜测——你给模型看什么，它就只能基于什么思考」
  - 举自己项目里「ok=true 但内容为空」导致绕圈的例子
- **扣分**：
  - 「换个更聪明的模型」——错在接口设计，不在模型
  - 只答「检查 prompt 写得对不对」
- **追问**：
  - 你怎么判断返回值够不够模型做决策？
  - 截断长度你按什么定的？截断标记你会加在哪一层？
- **关联**：`docs/第04章 工具调用.md`

### K11 · 上下文窗口快满了，你怎么排查？

- **维度**：故障排查
- **难度**：进阶
- **岗位**：全部
- **时长**：5
- **考察**：排查顺序，而不是「上压缩」这一个动作
- **题面**：一个长任务的上下文窗口快满了，你会怎么查、怎么处理？
- **参考思路**：
  - 先把预算拆开算：system 加槽位 10%–15%、工具定义 5%–20%、检索资料 25%–40%、历史 20%–30%、输出预留 15%–25%
  - 找出超出预期的部分——工具定义和单条超大工具返回是两个最常见的隐形大户
  - 按代价从低到高处理：裁剪工具与资料 → 工具结果截断并落盘成引用 → 压缩历史 → 下调触发水位到 70%
  - 输出侧显式设 max_tokens 并且必须预留，否则 finish_reason=length 会截断结构化输出
- **加分**：
  - 提「大对象用资源引用模式：上下文里只留 doc_id 加摘要，需要时再分页读」
  - 说「每轮打印各部分占用，下次就能在超限前发现」
- **扣分**：
  - 「换个上下文更大的模型」——把预算问题换成成本问题，没解决
  - 只答「上压缩」一个动作，说不出先测量再动手
- **追问**：
  - 你怎么知道是哪一段吃的 token？有没有真的打印过分段占用？
  - 压缩之后你怎么验证关键信息没丢？
- **关联**：`docs/第07章 记忆与上下文工程.md`

### K12 · 怎么压缩历史而不丢关键信息？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：Agent工程师
- **时长**：5
- **考察**：有没有被「摘要把订单号压没了」这种事坑过
- **题面**：多轮对话要做历史压缩，你怎么保证关键信息不被摘掉？
- **参考思路**：
  - 一次合格的压缩同时产出三样：摘要（脉络）、关键实体逐字（订单号、金额、日期、承诺）、待办与结论
  - 关键实体外置到槽位（slots），压缩只动摘要文本，槽位永不被摘要覆盖
  - 加 must_keep 验证清单，压缩后逐项自检，缺失即判失败并重试
  - 按 token 水位（70%–80%）触发而不是按轮数——一次工具返回可能顶十轮对话
- **加分**：
  - 说「防止摘要的摘要级联失真：每次压缩都把上一次摘要和新增对话一起输入，且始终携带原始槽位」
  - 说「保留原始消息 id 支持回查」
- **扣分**：
  - 「每隔 5 轮摘要一次」——按轮数触发是错的，且没提关键实体保护
  - 「用摘要就行，简单」——不知道摘要是最容易丢关键信息的一种
- **追问**：
  - 压缩是同步做还是异步做？延迟加多少？
  - 压缩本身用哪个模型？为什么是它？
- **关联**：`docs/第07章 记忆与上下文工程.md`

### K13 · 长期记忆怎么实现？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：全部
- **时长**：5
- **考察**：知不知道「记什么」比「怎么存」更重要
- **题面**：要做跨会话的长期记忆，你会存什么、怎么读、什么时候删？
- **参考思路**：
  - 写入：抽取 → 过滤（用户明确陈述、可复用、非敏感）→ 去重 → 落盘（带来源、时间戳、置信度）
  - 读取：检索 → 时间衰减排序（半衰期 90 天，score = 相似度 × 0.5^(age/90)）→ 只注入 Top-3 → 在 prompt 里标注「以下为历史记忆，可能与当前情况不同」
  - 生命周期四动作：覆盖更新（保留 previous）、TTL 过期、用户显式删除、冲突挂起（无法判定就去问用户）
  - 隔离：检索层强制注入 tenant_id 与 user_id 过滤，绝不依赖 prompt
- **加分**：
  - 说出最容易犯的错——只写用户明确陈述，模型推断不落盘，否则「用户想退货」这种早期推断会被固化
  - 主动提「注入的记忆要标注来源与时间，让模型知道这条信息可能过期」
- **扣分**：
  - 「存到向量库里，需要时检索出来」——没回答记什么、什么时候删、冲突怎么办
  - 把记忆写进 system prompt 当成「长期记忆」，完全不谈更新与过期
- **追问**：
  - 两条记忆互相冲突时你怎么处理？
  - 记忆写错了、影响了十次对话，你怎么兜底？
- **关联**：`docs/第07章 记忆与上下文工程.md`

### K14 · 为什么说多智能体往往不如单 Agent？

- **维度**：技术取舍
- **难度**：困难
- **岗位**：Agent工程师
- **时长**：6
- **考察**：敢不敢说「不用」，以及理由是不是工程的
- **题面**：行业里有个说法是多 Agent 往往不如单 Agent，你怎么看？你项目里为什么那么设计？
- **参考思路**：
  - 拆角色不改变模型能力——五个 Agent 用的是同一个模型、同一份知识、同一套工具
  - 能买到的只有四样：上下文隔离、对抗性检查、可并行、可恢复
  - 代价是输入 token 通常高 20%–200%、延迟按最慢分支算、新增四类协作故障（循环争论、任务漂移、上下文膨胀、责任真空），真实业务里成功率常常下降几个点
  - 四条门槛一条不命中就别拆
- **加分**：
  - 引用 Anthropic 的数字：单 Agent 的 token 消耗约为普通对话的 4 倍，多 Agent 约 15 倍，且 token 量本身解释了性能差异的绝大部分（约 80%）
  - 说「升级顺序不可颠倒：单 Agent → 加 Skill → 加工具 → 加评测 → 最后才拆 Agent」
- **扣分**：
  - 「多 Agent 可以模拟一个团队，各司其职」——把组织架构隐喻当技术方案
  - 「四条都满足才拆，但我们的任务四条都满足」——没有取舍，也没有失败样本
  - 为了迎合面试官否定自己做的多 Agent 项目（两面都当不成立场）
- **追问**：
  - 那你项目里为什么要拆？四条门槛命中了哪一条？
  - 拆完成功率如果降了，你怎么解释？
- **关联**：`docs/第11章 多智能体协作.md`

### K15 · 上下文隔离到底买到了什么？代价是什么？

- **维度**：概念理解
- **难度**：进阶
- **岗位**：Agent工程师
- **时长**：4
- **考察**：是不是把隔离理解成「省一点 token」
- **题面**：你说多 Agent 的一个好处是上下文隔离——它到底买到了什么？代价又是什么？
- **参考思路**：
  - 买到三样：质量（噪音不进主上下文）、成本（中间过程不回传）、故障面（单点跑偏可隔离可重跑）
  - 代价是信息传递会丢细节，以及子 Agent 可能目标不一致
  - 关键动作是压缩回传：只回传结论、依据数量、不确定性，并保留可回查的指针（路径 / 来源 id / 行号）
  - 判断标准一句话：主管下一步决策需不需要这条细节——不需要就丢，需要就落盘
- **加分**：
  - 给数字：共享上下文与隔离回传在第 5 轮时差约 10.7 倍——隔离不是省一点，是把增长曲线从平方压到线性
  - 主动说「压缩回传要带指针，否则主管想回查时只能再去问一遍子 Agent，这笔账更贵」
- **扣分**：
  - 「隔离就是每个 Agent 有自己的 memory」——没提压缩回传，等于只说了半个机制
  - 只说「隔离更省 token」，说不出它换来了什么质量上的东西
- **追问**：
  - 有没有一次压缩回传丢掉细节、导致主管决策错的例子？
  - 你说的「指针」具体指向什么？存哪？
- **关联**：`02-Wiki/专题总结/06-多智能体协作.md`

### K16 · 多 Agent 反复互相改稿、停不下来，你怎么定位？

- **维度**：故障排查
- **难度**：困难
- **岗位**：Agent工程师
- **时长**：5
- **考察**：认不认得四类协作故障里的「循环争论」
- **题面**：你的多 Agent 系统里，reviewer 永远说「再改改」，轮次一直涨，你会怎么定位和解决？
- **参考思路**：
  - 现象：轮次一直涨、成本线性上涨、产出没有变化
  - 定位：打印每轮的 issues 列表与轮次计数，看意见是否可判定、相邻两轮是否高度重复（重合度超过 0.8 就是无进展）
  - 三层修法：意见必须可判定并附验证方式、无进展熔断提前停、MAX_ROUNDS 兜底（2 到 3）
  - 停止时必须产出「未达成一致 + 分歧点 + 各方理由」交人工，不能静默丢弃
- **加分**：
  - 说输出 schema 强制 verdict 二选一、每条 issue 带 how_to_verify
  - 说「上限是止损不是提质，调大只会多烧 token」
- **扣分**：
  - 「让它别再改了」——没有机制，只是换个说法
  - 「把轮数上限设大一点让它充分讨论」——把成本当不确定性买
- **追问**：
  - 重合度具体怎么算？阈值为什么定 0.8？
  - 熔断之后交到人工手上的东西应该长什么样？

### K17 · Tool、Prompt、Skill、MCP 四个词，你能一句话说清各自的职责吗？

- **维度**：概念理解
- **难度**：基础
- **岗位**：全部
- **时长**：5
- **考察**：四件套的职责边界，这是最高频的辨析题
- **题面**：Tool、Prompt、Skill、MCP 这四个东西，各自的职责是什么？什么时候用哪个？
- **参考思路**：
  - Tool 给能力（让模型能做，靠注册函数加 JSON Schema）
  - Prompt 管这一次（本次的特殊要求，写死在请求里）
  - Skill 管一类任务的流程（SKILL.md，按 description 语义匹配后按需注入）
  - MCP 管接入标准化（把 M×N 份适配变成 M+N 份）；判断顺序是：只有这次特殊用 Prompt、没这个能力加 Tool、每次都做不规范建 Skill、多应用复用才上 MCP
- **加分**：
  - 补一句「四者叠加不互斥」，并给一个同时用到四者的真实例子
  - 说「Skill 不能注册任何工具——工具必须真的注册，Skill 只管什么时候该用哪个工具」
- **扣分**：
  - 「Skill 就是更长的 prompt」——忽略它是按需加载的文件，没被选中时正文等于不存在
  - 「MCP 是一个工具市场」——把协议说成了产品形态
- **追问**：
  - 什么时候该建 Skill，什么时候写进 Prompt 就行？
  - 「把常用 prompt 都存成 Skill」这个做法对不对？为什么？

### K18 · MCP 解决了什么问题？Tools / Resources / Prompts 怎么分？

- **维度**：概念理解
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：知不知道 MCP 是「接入标准化」，不是「让模型变强」
- **题面**：MCP 到底解决了什么问题？它的 Tools、Resources、Prompts 三种能力怎么分？
- **参考思路**：
  - 之前的工具接入是乘法（M 个工具 × N 个应用 = M×N 份适配），协议之后是加法（M 份 Server 加 N 份 Client）
  - 10 个工具 × 5 个应用从 50 份适配降到 15 份，这是它的全部价值
  - 三种能力按决策者分：Tools 由模型提议加 Host 放行、Resources 由应用或用户选择后进上下文（只读数据）、Prompts 由用户主动选用
  - 澄清：MCP 只解决「接得上」，不解决「模型会不会用」
- **加分**：
  - 说清权限门的位置在 Host，且拒绝时连请求都不发出去
  - 接一句「接一个能删库的 Server 不可怕，Host 无脑放行才可怕」
- **扣分**：
  - 「MCP 是一个工具市场 / 插件协议」——把协议说成产品形态
  - 「MCP 是标准，早晚要接」——不回答「我这份能力有没有第二个消费者」
  - 说「Resources 就是让模型读数据」，分不清它是谁决定的
- **追问**：
  - 你接了几个 MCP Server？为什么不直接自己写一个 ToolRegistry？
  - stdio 和 HTTP 两种传输你怎么选？
- **关联**：`docs/第10章 MCP与通信协议.md`

### K19 · 线上成本涨了，给你七种手段，你按什么顺序用？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：AI后端、AI应用开发
- **时长**：5
- **考察**：会不会罗列而不排序——排序才是判断力
- **题面**：线上 Agent 的成本要降，你会按什么顺序做？为什么是这个顺序？
- **参考思路**：
  - 按收益/成本比排序：模型分级（路由、抽取、循环用便宜模型，写作与 judge 用强模型）→ 减步数（工具与提示词优化）→ 前缀缓存（命中部分输入费降 5–10 倍）→ 历史压缩加工具结果截断 → 输出限制（输出单价是输入的 3–4 倍）→ 结果缓存或批量通道 → 预算熔断
  - 输入侧永远是主战场，历史重发常占七成以上
  - 优化对象是「每成功一次的成本」（总成本除以成功次数），不是单次调用的 token
  - 降本必须和评测联动，否则是拿质量换成本
- **加分**：
  - 给算例：6 步 Agent 从 7380 输入 token / ¥0.0198 降到约 3000 token / ¥0.0110，降 44%
  - 强调「重试是全损——失败那次调用的 token 白花，还要再付一次」
- **扣分**：
  - 只说「用便宜的模型」——这是七种里的一种，且它可能让效果变差、重试变多，总成本反而上升
  - 「把 max_tokens 调小」——只碰输出侧，而输入侧才是大头
- **追问**：
  - 你怎么验证降本之后效果没掉？
  - 前缀缓存为什么在你这里命中率低？你会怎么改？
- **关联**：`docs/第13章 部署成本与性能.md`

### K20 · 线上效果不好，你的排查顺序是什么？

- **维度**：故障排查
- **难度**：困难
- **岗位**：全部
- **时长**：6
- **考察**：有没有归因顺序，还是靠猜
- **题面**：线上效果最近变差了，你的排查顺序是什么？第一步做什么？
- **参考思路**：
  - 第一步永远是分段定位：把系统拆成可分别测量的几段（检索层 / 上下文层 / 模型层 / 工具层），先找出退化的是哪一段
  - 并排两次结果逐条对比 pass/fail（同一批样本），在失败样本的 trace 里找共同点
  - 按集中度判方向：失败集中在同一类输入是提示词或判据问题、分散且工具相关是工具设计问题、同一步骤反复出错是那一步的观察结果有问题、整体小幅下滑是模型版本或参数变化
  - 交叉验证，一次只改一个变量，结论写成「一句话加数字」
- **加分**：
  - 给一个真实链条：引用准确率 0.93→0.71 → 分段测出检索层 Recall@5 0.88→0.62 → 换回上一版索引恢复 → 查出 3 份扫描件 PDF 解析成乱码污染了向量空间 → 解析失败文件进排除清单并告警 → 重跑回到 0.92
  - 说「stop_reason 的分布是 Agent 健康度的体检报告」
- **扣分**：
  - 「先看 prompt 写得对不对」——没有定位就改提示词，是最常见的浪费
  - 「重跑一遍就好了」——没有解释为什么会变差
- **追问**：
  - 如果手上没有 trace，你会怎么做？
  - 代码一行没改但指标慢慢掉了，你怎么查？怎么确定是模型版本变了？
- **关联**：`docs/第12章 评估可观测性与安全.md`

## 轮次：项目深挖轮

> **这一轮的问法只有一个套路：你说了一个结论，我就问它的数字和它的反面。** 「效果不错」→「召回率多少、怎么测的」；「用了向量库」→「为什么不用 ES」；「做了优化」→「优化前后差多少、代价是什么」。
> **面试官听项目时在听的四个维度：** 真实性（有没有别人不知道的操作细节）、判断力（说不说得出放弃的方案与它的代价）、数据意识（有没有口径、基线、反指标）、工程完备度（上线之后的事想过没有）。**功能列表谁都能背，取舍和故障只有做过的人才有。**
> **这一轮的题按项目阶梯 L1–L8 组织**，候选人做过哪一档就问哪几题。追问框架的完整版见 [[02-Wiki/面试题库/03-项目表达与追问应对]]。

### P1 · 你说 L1 的计算器 Agent 跑通了——10 个测试问题通过几个？失败的那几个是怎么失败的？

- **维度**：工程实现
- **难度**：基础
- **岗位**：全部
- **时长**：4
- **考察**：有没有真跑验证集，还是只跑了一个 happy path
- **题面**：你说这个最小 Agent 跑通了，那 10 个测试问题里它通过几个？失败的那几个是怎么失败的？
- **参考思路**：
  - 报通过数，并把失败按类型分类：选错工具、参数解析失败、该拒答却硬算
  - 失败要归因到工具描述或返回值设计，而不是「模型太笨」
  - 那 2 个无法回答的问题，看的是它有没有承认自己不会
  - 说出改动前后失败数的变化，才说明你真的迭代过
- **加分**：
  - 说「我改的不是 prompt，是工具描述里补了一句『什么时候不该用它』，失败数从 4 降到 1」
  - 主动说「其中一个是单位换算的精度问题，我加了小数位约束」
- **扣分**：
  - 「跑通了，都能算对」——没测过边界，也没准备验证集
  - 把失败归因成「模型能力不够」，说不出自己改了什么
- **追问**：
  - 那 2 个无法回答的问题它怎么处理的？答了还是拒了？
  - 你怎么判断它是「算错了」还是「根本没用工具」？
- **关联**：`01-Raw/03-项目阶梯与能力对照表.md`

### P2 · 文档问答你说 Recall@5 是 0.88——这个数是怎么算出来的？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：RAG工程师
- **时长**：5
- **考察**：被追问口径时的三段式回答：口径 → 样本 → 局限
- **题面**：你的文档问答系统 Recall@5 是 0.88，这个数是怎么算出来的？谁定的判据？
- **参考思路**：
  - 口径：gold chunk 是否出现在前 5 条，gold 由谁标注、怎么标
  - 样本：30 条来自真实问题，覆盖事实型、多跳、无答案、易混淆四类
  - 分层：检索指标与生成指标分开测量，才能定位问题在哪一层
  - 局限：这 30 条来自自己的场景，换一批文档绝对值会变，所以只看改动前后的相对变化
- **加分**：
  - 说「判据我请没参与设计的人写，防止自己批改自己的卷子」
  - 主动给 baseline：改之前是 0.74，改了什么之后到 0.88
- **扣分**：
  - 「就是检索对了的比例」——说不出 gold 怎么定
  - 报完数字被追问口径时开始含糊，改成「大概是 0.9 左右」
- **追问**：
  - 这 30 条里多跳和无答案各几条？它们的通过率是多少？
  - 0.88 是跑一次还是跑三次？三次之间波动多少？
- **关联**：`docs/第08章 RAG全链路.md`

### P3 · 你做了切片对比实验——两种切法差多少个点？为什么？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：RAG工程师
- **时长**：5
- **考察**：有没有实验意识：单变量、有对照、能解释原因
- **题面**：你说做过切片对比实验，两种切法的指标差多少？差在哪、为什么？
- **参考思路**：
  - 给参数：比如 400 字结构切对比 800 字固定长度切，overlap 固定
  - 给差异：Recall@5 差多少个点，是涨还是跌
  - 给解释：块太大语义被稀释、命中位置不精确；块太小跨块答案拿不到
  - 单变量对比：一次只改一个变量，不然涨了也不知道是谁的功劳
- **加分**：
  - 说「我把 chunk_size 和 overlap 分开扫的，先定 size 再定 overlap」
  - 说出反方向的数据：200 字为什么更差（跨块答案拿不到）
- **扣分**：
  - 「感觉小一点效果更好」——没有数字
  - 「书上都写 500 字是经验值」——经验值不是你的数据
- **追问**：
  - overlap 从 0 到 100 你怎么选的？扫过哪几档？
  - 换一批文档，这个结论还成立吗？你的依据是什么？
- **关联**：`docs/第08章 RAG全链路.md`

### P4 · 你们的拒答阈值是怎么定出来的？误拒率是多少？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：RAG工程师、AI应用开发
- **时长**：5
- **考察**：拒答是两个方向的取舍，只报一个方向说明没上线过
- **题面**：你说相似度低于阈值就直接回「未收录」——这个阈值怎么定的？误拒率多少？
- **参考思路**：
  - 阈值是在评测集上扫出来的，同时看两个方向：该拒答率与误拒率
  - 两个方向对应两类事故：该拒答却硬答是可信度事故，能答却误拒是可用性事故
  - 阈值必须写进配置或代码，不能写在 prompt 里
  - 可以组合判据：最高相似度、命中块数量、有没有 BM25 精确命中
- **加分**：
  - 说「误拒率不高于 5% 是我们和业务方一起定的，因为客服问不到答案会转人工，等于把成本转回去」
  - 给出具体数字和样本量，并说「换数据要重扫」
- **扣分**：
  - 「阈值凭感觉调的」——说不出扫的过程
  - 只报拒答准确率一个方向，被问误拒率时才发现没统计
- **追问**：
  - 换 embedding 模型之后这个阈值还能直接用吗？为什么？
  - 阈值短路帮你省了多少成本和延迟？算过吗？
- **关联**：`docs/第08章 RAG全链路.md`

### P5 · 代码审查 Agent 的误报率是多少？你用什么手段压下来的？

- **维度**：工程实现
- **难度**：困难
- **岗位**：AI应用开发、Agent工程师
- **时长**：6
- **考察**：有没有主动盯着副作用——误报率高会让工具被弃用
- **题面**：你的代码审查 Agent 误报率是多少？你怎么控制它不乱报？
- **参考思路**：
  - 给三个数：检出率、误报率（条/PR 这个口径更直观）、Precision@3
  - 手段：置信度阈值、条数上限、风格类过滤、建议必须可执行
  - 说清取舍：宁可少报也别乱报——被关掉的工具检出率再高也是零
  - 20 个真实 diff 的测试集要说清怎么来的
- **加分**：
  - 给一个真实的拐点：「第一版误报 2.1 条/PR，同事说『连 import 顺序都管』，很快就没人看了」
  - 说「最后我选了误报 0.6 条/PR、检出率 0.73，这个取舍是跟使用方谈出来的」
- **扣分**：
  - 「误报不多」——没有数字
  - 只报检出率，被追问副作用时才发现没统计过
- **追问**：
  - 置信度是模型自报的还是你在外面算的？两者差别在哪？
  - 大 diff 你怎么保证覆盖范围说清楚了？
- **关联**：`01-Raw/03-项目阶梯与能力对照表.md`

### P6 · 一个 5000 行的 diff 塞不进上下文，你的降级策略是什么？

- **维度**：工程实现
- **难度**：困难
- **岗位**：AI应用开发
- **时长**：5
- **考察**：处理不了的时候，会不会明确告知用户而不是假装看完了
- **题面**：如果这个 PR 改了 5000 行，根本塞不进上下文，你怎么处理？覆盖范围怎么告诉用户？
- **参考思路**：
  - 三种降级可选：分块审查、先摘要再细化、只审变更行附近
  - 分块要按文件与风险排序，先审核心逻辑，不是从头切到尾
  - 报告里必须显式声明覆盖范围：本次只覆盖了哪几个文件的哪部分
  - 宁可不报，也不能漏了还说全覆盖——这是信任问题
- **加分**：
  - 说「降级路径必须真的被跑过一次，不然出事时才发现它是坏的」
  - 说「我会先只审改动行附近，跑一段时间用数据决定要不要扩大范围」
- **扣分**：
  - 「分块就行」——没说覆盖范围，也没说块之间的一致性问题
  - 「我们的 diff 都不大」——回避问题
- **追问**：
  - 分块之后，跨文件的调用关系怎么审？这个缺口你怎么补？
  - 覆盖范围告诉用户之后，他还能拿这份报告做什么？
- **关联**：`docs/第09章 Skills能力包.md`

### P7 · 你的 Coding Agent 能执行命令——权限门怎么设计的？

- **维度**：工程实现
- **难度**：困难
- **岗位**：Agent工程师
- **时长**：6
- **考察**：安全是分级的，不是「要么全给要么全禁」；以及确认门放在哪一层
- **题面**：你的 Coding Agent 能读写文件、能执行命令——权限怎么设计的？怎么防止它删错文件？
- **参考思路**：
  - 按动作风险分级：只读（最小权限加记 trace，可不确认）、可逆写（参数校验加可回滚）、不可逆与对外（人工确认、白名单、幂等键、全量审计）
  - 确认门的正确位置是执行侧（Host 或服务端），绝不能放在提示词里——模型说「我已经确认过了」不算确认
  - 确认必须展示完整参数与影响说明，高风险动作要求输入特定确认串而不是 y/n
  - 命令执行必须在白名单内
- **加分**：
  - 说「读敏感数据的能力与对外发送的能力，我不给同一个 Agent」
  - 说「确认界面展示原始参数，不展示模型的自然语言解释」
- **扣分**：
  - 「在 system prompt 里写『请不要删除数据』」——工具描述与用户输入都是不可信输入
  - 「只让它跑测试命令」但说不出白名单怎么维护、谁能改
- **追问**：
  - 确认弹窗一天弹 50 次，用户会怎么绕过你？你会怎么减少打扰又不放水？
  - session 中断之后怎么恢复？已经改过的文件怎么办？
- **关联**：`docs/第14章 构建你自己的Agent框架.md`

### P8 · 上下文压缩你做了——压缩前后多少 token，成功率有没有变化？

- **维度**：工程实现
- **难度**：困难
- **岗位**：Agent工程师
- **时长**：5
- **考察**：压缩必须同时报两个数：省了多少、质量掉没掉
- **题面**：你说给 Coding Agent 做了上下文压缩，压缩前后上下文多少 token？成功率有变化吗？
- **参考思路**：
  - 给前后数字：比如 12k 降到 4k，同时成功率没有下降
  - 压缩三件套：摘要、关键实体逐字、待办与结论
  - 按 token 水位触发，压缩这一步用便宜模型，且要计入成本与延迟
  - 验证方式：must_keep 清单加回归评测集
- **加分**：
  - 说「压缩之后跑完才发现关键约束丢了，所以我把 must_keep 做成了断言」
  - 主动承认压缩的代价：「压缩本身是一次模型调用，我用小模型做，延迟加 1.2 秒」
- **扣分**：
  - 「压缩之后效果差不多」——没有数字
  - 只说 token 降了多少，质量指标一个没有
- **追问**：
  - 压缩水位设在多少？为什么留那么多余量？
  - 压缩失败或者压缩后指标掉了，你怎么回退？
- **关联**：`docs/第07章 记忆与上下文工程.md`

### P9 · Skill Pack 你做过 A/B——不带 Skill 的成功率是多少？

- **维度**：技术取舍
- **难度**：进阶
- **岗位**：Agent工程师、AI应用开发
- **时长**：5
- **考察**：有没有 A/B 意识，而不是「感觉变好了」
- **题面**：你说 Skill Pack 有用——A/B 怎么做的？不带 Skill 的成功率是多少，带了是多少？
- **参考思路**：
  - 用固定任务集（6–10 条来自真实历史的任务），重复 3 次取一致结果
  - 基线是等量无关文本，不是空白 prompt——空白基线会高估 Skill 的收益
  - 判定门槛：成功率提升不低于 20 个百分点且 token 增幅低于 50% 才值得留
  - 判据由没读过技能的人写，防止自己批改自己的卷子
- **加分**：
  - 主动说最容易踩的坑：判据写成关键词命中，而技能正文里本来就含这些关键词
  - 给 token 账：5 个技能时渐进式加载省 9%–48%（不值得搭），20 个技能才差 5 倍以上（刚需）
- **扣分**：
  - 「感觉用了 Skill 之后更稳定」——没有对照组
  - 说不出 5 个技能不值得搭、20 个技能才刚需这个分界线
- **追问**：
  - 为什么 Skill 不能写进 system prompt？用你的数据说
  - description 里的触发词你怎么抄的？抄自哪里？
- **关联**：`docs/第09章 Skills能力包.md`

### P10 · 压测报告里你的 P99 是多少？你优化了哪一段？

- **维度**：故障排查
- **难度**：困难
- **岗位**：AI后端
- **时长**：6
- **考察**：分不分得清 TTFT、TPOT 和端到端延迟——用户说「卡」可能指三个不同的东西
- **题面**：你那份压测报告上 P99 是多少？你优化了哪一段，优化前后差多少？
- **参考思路**：
  - 先分诊：TTFT 是「点了之后多久有反应」、TPOT 是「字出得快不快」、P95/P99 是「最慢那批有多慢」
  - Agent 的 P99 主要由最慢的一步乘以步数决定，先砍步数再谈单步优化
  - 手段：流式输出（改善感知）、缩短输入（前缀缓存、历史压缩）、减少常驻工具与技能目录、工具执行阶段给状态文案
  - 超时值按 P99 的 1.5 倍起步，设成平均值会砍掉一大批本可成功的请求
- **加分**：
  - 说「我先把每段计时打出来再动手，不然后面所有优化都是猜」
  - 说清压测条件：并发多少、机器什么配置、是不是本机
- **扣分**：
  - 「开流式就好了」——流式只改善感知，端到端总时长不变
  - 报 P50 当 P99 用，被追问测试条件时说不清
- **追问**：
  - 优化之后业务侧指标有没有变差？你怎么确认的？
  - 如果并发再涨 10 倍，下一个会爆的是哪一段？
- **关联**：`docs/第13章 部署成本与性能.md`

### P11 · 单次成本从多少降到多少？三级预算熔断怎么设的？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：AI后端、AI应用开发
- **时长**：5
- **考察**：成本口径意识，以及「降本」有没有和评测联动
- **题面**：你项目里单次成本是多少？做过降本吗？预算熔断怎么设的？
- **参考思路**：
  - 先说口径：每成功一次的成本等于总成本除以成功次数，失败重跑要算进去
  - 降本顺序：模型分级、减步数、前缀缓存、历史压缩、输出限制、批量通道
  - 熔断三层：单次、单日、单用户；触发后的行为要明确（降级还是拒绝，用户看到什么文案）
  - 降本必须和评测联动，否则是拿质量换成本
- **加分**：
  - 说「我把失败重跑算进去了，不然降本都是假的」
  - 给具体数字：比如从 ¥0.0198 降到 ¥0.0110，同时成功率没掉
- **扣分**：
  - 只报「成本降了 44%」但说不出口径
  - 熔断只设了单次上限，没设日与用户维度
- **追问**：
  - 预算被撞满的那一次，用户看到的是什么？
  - 你怎么发现成本异常上涨？靠人看账单还是靠告警？
- **关联**：`docs/第13章 部署成本与性能.md`

### P12 · 网页研究 Agent 你说编造引用率是 0——你用什么校验的？

- **维度**：工程实现
- **难度**：进阶
- **岗位**：AI应用开发
- **时长**：5
- **考察**：引用是设计出来的，不是求模型求出来的
- **题面**：你说研究报告里的引用都可追溯、编造率为 0——这个 0 是怎么保证的？
- **参考思路**：
  - 三道校验：编号存在 → 编号在本次范围内 → 被引原文能在来源里找到依据
  - 前两道是纯代码断言，第三道做句子级校验（关键词重合即可，离线可跑零依赖）
  - 不合格的降级路径要明确：重试一次，仍不合格就降级为「未收录」
  - 把「引用不可核验率」做成可监控指标，它不需要人工标注
- **加分**：
  - 说「模型很爱写『根据《XX 制度》』，这是编造不是引用，所以我在 prompt 里禁止提及外部来源名，并在校验层过滤」
  - 说清 5 个主题各跑一次是怎么人工检查的、检查了哪几项
- **扣分**：
  - 「让模型自己检查引用对不对」——用同一个概率模型检查自己的幻觉，不构成防线
  - 说不出「编造率 0」的统计口径，只说「我看了几个，都对」
- **追问**：
  - 检索回来的网页本身就是脏的（广告、无关内容、错误信息）怎么办？
  - 搜索结果互相矛盾时你怎么处理？
- **关联**：`docs/第06章 范式进阶.md`

### P13 · 浏览器 Agent 遇到页面改版、元素定位失败，你的降级路径是什么？

- **维度**：故障排查
- **难度**：进阶
- **岗位**：AI应用开发
- **时长**：5
- **考察**：失败恢复的设计，以及合规边界有没有写下来
- **题面**：页面改版了、元素定位不到、弹出登录框——这三种情况你的 Agent 分别怎么办？
- **参考思路**：
  - 三条降级路径：换定位策略（文本到属性到结构）、弹窗检测后关闭或跳过、失败重试并保存现场
  - 动作日志（截图或 DOM 快照）是复盘的前提，没有它无法定位
  - 安全边界要写进 README：只操作公开页面、不登录敏感账号、不绕过平台规则、遵守 robots 与访问频率
  - 降级路径必须被真跑过——故意改一个选择器验证它是活的
- **加分**：
  - 说「我故意改坏一个选择器，验证降级确实生效，而不是只在代码里存在」
  - 主动说清楚合规边界，不等面试官问
- **扣分**：
  - 「定位不到就重试几次」——没有分层降级
  - 完全不提合规与访问频率，面试官会直接怀疑风险
- **追问**：
  - 视觉定位（截图识别）失败率高吗？你什么时候会用它？
  - 你怎么保证不封号、不越权？频率是怎么控的？
- **关联**：`docs/第10章 MCP与通信协议.md`

### P14 · 你这个项目最大的缺点是什么？

- **维度**：沟通表达
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：缺点必须是技术根因导致的，不能是「我没做好」
- **题面**：你这个项目有什么缺点？说三个。
- **参考思路**：
  - 缺点要挑技术根因层面的：聚合类问题做不了（召回是局部视角）、多 Agent 成功率比单 Agent 低几个点（拿质量换的）、评测集只有 30 条（只能看相对变化）
  - 每条都要给出应对方式：降级到长上下文、转人工、写进 README 的已知限制
  - 不要用「以后会优化」这种空话收尾，要给边界
- **加分**：
  - 说「这三条我都写在 README 的已知限制里」
  - 主动区分「技术根因导致的限制」与「我还没做的部分」——前者是判断力，后者要认领
- **扣分**：
  - 「检索这块我还不太熟，可能还有优化空间」——把边界说成失职
  - 「没什么缺点，效果挺好」——面试官只会继续往下挖
- **追问**：
  - 那这个问题你打算怎么解决？解决不了怎么办？
  - 如果客户不接受这个限制呢？
- **关联**：`02-Wiki/面试题库/03-项目表达与追问应对.md`

### P15 · 如果让你重做一次，你会先改哪一步？

- **维度**：沟通表达
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：答「顺序」而不是「技术」——顺序类反思才显得你真复盘过
- **题面**：这个项目如果让你重做一次，你会先改哪一步？
- **参考思路**：
  - 说顺序类改动：把评测集提到第一周就建、先写 Workflow 版本做 baseline
  - 要说清这个改动省下了什么：前两周所有改动没有基线可比，回头看有两次改动其实是负收益
  - 要有具体动作，不只是一个愿望
- **加分**：
  - 说「现在我给自己的纪律是先有评测再加功能」
  - 说「没有基线就没有架构决策，只有偏好——这是我这次最贵的教训」
- **扣分**：
  - 「我会用更新的框架 / 更好的模型」——技术类反思听起来像「我当时学得不够」
  - 「没什么要改的，做得挺好的」
- **追问**：
  - 你怎么保证这次不会再犯？有什么机制在拦着你？
  - 你现在的工作习惯里，哪一条是那次换来的？
- **关联**：`01-Raw/03-项目阶梯与能力对照表.md`

## 轮次：系统设计轮

> **设计题的评分点从来不是「你选了哪个组件」，而是「你有没有先问约束」。** 一上来就说 Milvus 加 LangChain 的，直接扣分；先说「我要先确认三件事：多少租户、更新频率、延迟预算」的，直接加分。
> **每题按五段推进，面试官自己心里要有这张表：** ① 澄清约束（谁用、规模、延迟、成本）→ ② 画主链路（输入到输出，3–5 个模块）→ ③ 补失败路径（超时、降级、幂等）→ ④ 定指标与评测（怎么知道它行）→ ⑤ 说演进（下一步做什么、什么信号触发）。
> **候选人讲完主链路就停住时，追问一句「那它挂了怎么办」**——这一问能分开「读过架构文章的人」和「部署过东西的人」。

### D1 · 设计一个支持 10 万份文档的企业知识库问答系统

- **维度**：系统设计
- **难度**：困难
- **岗位**：RAG工程师、AI后端
- **时长**：12
- **考察**：会不会先算规模与约束再选型，而不是先选向量库
- **题面**：设计一个支持 10 万份文档的企业知识库问答系统，支持多租户和权限隔离，你会怎么设计？
- **参考思路**：
  - 先算量：10 万份文档按每份 20 块算是 200 万块，这个量级落在什么档位的库上，先算清楚再选
  - 分离线索引与在线查询两条链路：离线是加载、清洗、切片、向量化、入库；在线是改写、召回、融合、重排、组装、生成、校验
  - 两条主线决定成败：权限过滤必须在检索层用 pre-filter 强制注入，索引一致性要有增量更新与监控
  - 先建 20–50 条评测集再谈优化，否则无法判断任何改动是否有效
- **加分**：
  - 说「过滤能力是最容易被忽略的选型项」——很多实现是先取 Top-K 再过滤，召回率被过滤层吃掉了
  - 说切块规则变更要当成一次全量重建来发布：双索引加切换
- **扣分**：
  - 上来就说「用 Milvus 加 LangChain」——没有规模判断，也没有约束澄清
  - 只画主链路，更新、权限、成本一个字不提
- **追问**：
  - 文档每天新增 500 份、修改 200 份，你的索引流水线怎么设计？
  - 多租户下权限过滤放在哪一层？为什么不能放在应用层？
- **关联**：`docs/第08章 RAG全链路.md`

### D2 · 设计一个能连续跑 30 步的分析 Agent

- **维度**：系统设计
- **难度**：困难
- **岗位**：Agent工程师
- **时长**：12
- **考察**：长任务的四个真问题——失控、烧钱、状态、恢复
- **题面**：设计一个能连续跑 30 步的分析 Agent，你会怎么保证它不失控、不烧钱、断了还能接上？
- **参考思路**：
  - 四道闸门：步数上限、同签名重复检测、无进展检测、成本与墙钟上限
  - 30 步不能靠调大 max_steps 撑过去，要靠状态外置：槽位与任务清单落盘，上下文里只留摘要与引用
  - 上下文预算：工具结果截断并落盘成引用、大对象只留 doc_id、按水位压缩
  - 每步可观测：trace、stop_reason 分布、平均步数；人工介入点设在危险动作上
- **加分**：
  - 说「我会先做 10 步版本，用失败样本决定要不要放到 30 步——不是先设 30 再想办法」
  - 说「30 步里我会显式区分探索步与执行步，执行步要幂等」
- **扣分**：
  - 只答「设一个 max_steps=30」——把闸门当设计
  - 不谈恢复与成本，被追问「跑到第 20 步进程挂了怎么办」才开始想
- **追问**：
  - 跑到第 20 步进程挂了，恢复之后模型怎么知道哪些事已经做过了？
  - 它连续三次做同一件事，你怎么发现？发现之后怎么处理？
- **关联**：`docs/第14章 构建你自己的Agent框架.md`

### D3 · 设计一个多租户的 Agent 平台

- **维度**：系统设计
- **难度**：困难
- **岗位**：AI后端
- **时长**：12
- **考察**：隔离要分层说——数据、密钥、配额、工具权限、日志
- **题面**：设计一个给多个企业客户用的 Agent 平台，租户之间怎么做隔离？哪些地方最容易漏？
- **参考思路**：
  - 数据层：检索用 pre-filter 强制注入 tenant_id，这是安全要求不只是性能要求
  - 密钥与配额按租户隔离：每个租户自己的模型凭证、自己的限流与预算
  - 工具权限按租户白名单：A 租户不该能调到 B 租户的 MCP Server
  - 可观测与合规：trace 与日志脱敏，越权属于事故级别，必须有审计日志
- **加分**：
  - 说「绝不用 prompt 做租户隔离——提示词是概率防线，元数据过滤才是确定性防线」
  - 提「配置与版本按租户管理」：提示词、技能、工具集都要能版本化与回滚
- **扣分**：
  - 「每个租户一个数据库就行了」——忽略成本与运维复杂度
  - 不提审计与越权测试
- **追问**：
  - 如果 A 租户的 Agent 调用了 B 租户的 MCP Server，你的哪一层会拦住它？
  - 租户级成本怎么归集？谁来定每个租户的预算？
- **关联**：`docs/第12章 评估可观测性与安全.md`

### D4 · 设计一个日请求量一万的客服 Agent

- **维度**：系统设计
- **难度**：进阶
- **岗位**：AI应用开发、AI后端
- **时长**：10
- **考察**：先分层再设计，以及降级路径是否真的存在
- **题面**：设计一个日请求量一万的客服 Agent，你怎么设计它的降级路径和成本上限？
- **参考思路**：
  - 先分层：FAQ 类走 Workflow 加 RAG，只有需要现场决定查哪些系统的请求才放开一步给 Agent
  - 降级链：检索服务不可用回退固定答案、模型超时就换小模型或排队、工具失败转人工
  - 转人工的判定条件要说清（相似度低于阈值、连续两轮没解决、用户主动要求）
  - 算账：一万次每天乘以单次成本，再加上三级预算熔断与限流
- **加分**：
  - 说「降级路径要定期强制触发一次，不然出事时才发现它是坏的」
  - 把成本与延迟指标一起给出来（P95、TTFT、每成功一次的成本）
- **扣分**：
  - 只讲主路径，降级只说「转人工」但没说判定条件
  - 不提成本与限流，被追问「一万次每天多少钱」时算不出来
- **追问**：
  - 转人工率多少算健康？你怎么监控它？
  - 模型服务挂了 30 分钟，用户看到的是什么？
- **关联**：`docs/第15章 综合实战.md`

### D5 · 设计一个接在 Git 平台上的代码审查系统

- **维度**：系统设计
- **难度**：困难
- **岗位**：AI应用开发
- **时长**：12
- **考察**：一条完整的工程链路：触发、过滤、分块、审查、聚合、回写
- **题面**：设计一个接在 Git 平台上的代码审查系统，从 PR 触发到评论回写，你怎么设计？
- **参考思路**：
  - 链路：webhook 触发 → 取 diff → 过滤（生成文件、锁文件、超大文件）→ 按风险排序与分块 → 审查 → 聚合去重 → 回写评论
  - 误报控制是生死线：置信度阈值、条数上限、风格类过滤
  - 幂等：同一个 commit 不能重复评论，同一 PR 推新 commit 要有更新策略
  - 成本：每个 PR 设 token 预算，大 diff 走降级并声明覆盖范围
- **加分**：
  - 说「先只审改动行附近，跑一段时间再用数据决定要不要扩大范围」
  - 说清与人工 review 的分工：它负责第一遍筛查，人负责最终判断
- **扣分**：
  - 把设计说成「调 API 然后把结果贴上去」
  - 不谈误报控制与 token 预算
- **追问**：
  - 同一个 PR 又推了一个 commit，你怎么处理已经发过的评论？
  - 你怎么评估它到底有没有用？指标是什么？
- **关联**：`docs/第15章 综合实战.md`

### D6 · 设计一套 Agent 的评测与回归体系

- **维度**：系统设计
- **难度**：困难
- **岗位**：全部
- **时长**：12
- **考察**：有没有把「效果」变成可复现的数字，而不是感觉
- **题面**：设计一套评测与回归体系，让团队的改动不会偷偷让 Agent 变差。
- **参考思路**：
  - 三层：评测集（20 条起，覆盖事实型、多跳、无答案、不该触发四类）、判定器（代码断言兜机械项、模型评审补质量、人工抽检 10% 校准）、指标（任务完成率、每成功一次的成本、平均步数、失败分类分布）
  - pass@k 是能力上限，pass^k 是稳定性；生产报 pass^k，探索型任务才报 pass@k
  - 回归进 CI：改一次跑一次，指标存下来形成对比
  - 线上 bad case 回流固化成新样本；模型版本作为 trace 的一等字段
- **加分**：
  - 说「20 条的作用是回归与归因，不是统计显著性」
  - 说「判定器本身也会错，所以我留 10% 人工抽检做校准」
- **扣分**：
  - 「跑几个例子看看，觉得可以就上线」——没有基线、没有判定器、没有反指标
  - 只有主指标，没有反指标
- **追问**：
  - 服务商静默升级了模型导致指标掉了，你怎么发现？
  - 判定器自己错判了怎么办？你怎么知道它错了？
- **关联**：`docs/第12章 评估可观测性与安全.md`

### D7 · 设计一个工具接入层，让 20 个团队的 100 个 API 都能被安全调用

- **维度**：系统设计
- **难度**：困难
- **岗位**：AI后端
- **时长**：12
- **考察**：工具治理——注册、分层、权限、可观测，四件事缺一不可
- **题面**：公司有 20 个团队、100 个内部 API 想接给 Agent 用，你来设计这个接入层，怎么做？
- **参考思路**：
  - 注册与治理：命名规范、schema 校验、版本、归属人、下线流程
  - 分层加载与路由：100 个 schema 不能常驻上下文，先给工具目录再按需加载，或先路由再进循环
  - 权限与确认门：按动作风险分级，写操作要人工确认加幂等键
  - 可观测：每个工具的成功率、P95、选错率、被拒绝次数
- **加分**：
  - 说「工具清单要像 API 一样治理：定期清理、加前缀、锁版本」
  - 说「应用侧要裁剪 Server 暴露的工具，不要把全部工具直接转发给模型」
- **扣分**：
  - 「上 MCP 就解决了」——协议解决接得上，不解决选得对
  - 不提工具数量对上下文与选择准确率的影响
- **追问**：
  - 100 个工具里怎么让模型选对？你会做哪几步？
  - 某个工具坏了，你怎么快速定位是谁的责任？
- **关联**：`docs/第04章 工具调用.md`

### D8 · 设计一个能中断续跑的 Agent 运行时

- **维度**：系统设计
- **难度**：困难
- **岗位**：Agent工程师
- **时长**：12
- **考察**：恢复最难的不是状态，是副作用
- **题面**：设计一个能中断、能续跑、能回放的 Agent 运行时，你会怎么设计状态与恢复？
- **参考思路**：
  - 状态落盘：每步快照包含消息、槽位、待办、工具调用结果与幂等键
  - 恢复语义：从快照继续，重放已完成的步骤;已产生副作用的操作要靠幂等键去重
  - 人工介入：危险动作挂起等确认，确认结果写进状态
  - 并发与租约：同一个 session 不能被两个 worker 同时跑；挂起的 session 要有 TTL 清理
- **加分**：
  - 说「恢复之后我要能让模型知道哪些事已经做过了——靠的是工具结果里的幂等键与状态查询，不是它的记忆」
  - 说「回放能力是用来复盘的，不是用来重跑的」
- **扣分**：
  - 「把消息列表存进数据库就行了」——不谈幂等、并发与副作用
  - 说不出「已经发出去的邮件不能重发」这类具体风险
- **追问**：
  - 恢复之后模型怎么知道哪些事已经做过了？
  - 挂起的 session 数据怎么清理？不清理会怎样？
- **关联**：`docs/第14章 构建你自己的Agent框架.md`

### D9 · 设计一个 Agent 的成本可观测与预算熔断体系

- **维度**：系统设计
- **难度**：进阶
- **岗位**：AI后端
- **时长**：10
- **考察**：能不能把成本拆到可归因的维度上，而不是只看一个总数
- **题面**：设计一套成本可观测与预算熔断体系，让成本涨的时候你能立刻知道是谁在涨。
- **参考思路**：
  - 归集口径：按 task_id、用户、租户、模型、步骤归集，输入与输出分开计价
  - 看板指标：每成功一次的成本、单步成本分布、失败重跑占比、缓存命中率
  - 熔断三层：单次、单日、单用户，触发后的行为要明确
  - 异常检测：先分清是请求数变多还是单请求变长，再按根因清单排查
- **加分**：
  - 说「重试是全损，成本要算两次——失败那次白花，还要再付一次」
  - 说「降本要联动评测，不然是拿质量换成本」
- **扣分**：
  - 「算一下总花费就行」——没有归集维度，涨了也不知道是谁
  - 熔断只说「设个上限」，不说触发后发生什么、怎么通知、怎么恢复
- **追问**：
  - 账单突然涨了 20 倍，你从哪查起？
  - 熔断触发之后怎么通知？谁来恢复？恢复的依据是什么？
- **关联**：`docs/第13章 部署成本与性能.md`

### D10 · 设计一个多 Agent 的调研系统：谁负责什么、怎么停、成本多少

- **维度**：系统设计
- **难度**：困难
- **岗位**：Agent工程师
- **时长**：12
- **考察**：先有基线再谈拆分，以及停止条件的工程化
- **题面**：设计一个自动产出竞品调研报告的多 Agent 系统——你会拆几个角色？怎么保证它收敛？成本多少？
- **参考思路**：
  - 先给单 Agent 基线（一个 ReAct 循环加若干工具），再用失败样本判断要不要拆
  - 拆的话用 Supervisor 模式：主管只调度与裁决、不读子 Agent 全文，只收压缩结论
  - 每个角色的契约六要素：职责、输入 schema、输出 schema、停止条件、失败回退、禁令
  - 四道保险：MAX_ROUNDS 上限、相邻两轮意见重合度熔断、目标漂移检测、收尾按交付清单打勾
- **加分**：
  - 说「主指标可能比单 Agent 低，要用分项指标解释——结构合规率升了、事实错误率降了」
  - 给成本口径：每成功一次的成本，把失败重跑算进去
- **扣分**：
  - 「分成产品经理、开发、测试三个角色」——把人类岗位名当契约
  - 不设停止条件，或只说「让它多讨论几轮」
- **追问**：
  - reviewer 的意见怎么保证可判定？举一条你实际收到的意见
  - 25 条评测集上，单 Agent 与多 Agent 的成功率各是多少？
- **关联**：`docs/第11章 多智能体协作.md`

## 轮次：行为与压力轮

> **压力轮考的不是知识，是心态与深度。** 面试官想看的是：被质疑时会不会慌、会不会硬撑、能不能把质疑变成一次结构化的回答。
> **三条纪律（面试官要按这个尺度评）：** ① **不辩解**——面试官的质疑通常有一部分是对的，先承认对的那部分，再划出自己不同意的部分；② **不认领没做的事**——模糊归属比明确边界危险得多，追问两层就会自相矛盾；③ **不赌**——任何「绝对不会出错」的表述都会被追问，要改成机制层面的表述。
> **这一轮的题最容易放水，也最容易伤人。** 面试官问完必须给一句缓冲（「这个问题有点尖锐，你慢慢想」），并且**不要连续追问超过两层**。

### B1 · 你刚才讲的这个方案，听起来像是团队一起定的——具体哪部分是你做的？

- **维度**：沟通表达
- **难度**：进阶
- **岗位**：全部
- **时长**：5
- **考察**：讲团队项目时能不能划清边界，并指着一个具体决策说「这是我定的」
- **题面**：你刚才讲的整套方案，听起来挺完整的——不过我想确认一下，具体哪部分是你做的？
- **参考思路**：
  - 先说清边界：我做的、我参与的、别人做的，三句说清
  - 再指着一个具体决策说「这是我定的」，并说它带来的数字变化
  - 不要模糊归属，也不要反过来把团队成果全揽在自己身上
  - 评据不是「做了多少」，而是「能不能说清自己在哪一层做了判断」
- **加分**：
  - 说出「判据我请产品同学写，避免自证」这类别人不知道的细节
  - 说清「评估指标的口径是和业务方一起定的，一开始我报错了指标」
- **扣分**：
  - 把「我参与」说成「我负责」，追问细节时开始含糊
  - 全程用「我们」，一次「我」都没有——面试官无法判断你的水位
- **追问**：
  - 那个决策当时有人反对吗？你怎么说服的？
  - 如果现在让你重做那个决策，你还会这么做吗？
- **关联**：`02-Wiki/面试题库/03-项目表达与追问应对.md`

### B2 · 说实话，我觉得你说的这些不就是把 prompt 写长一点吗？

- **维度**：沟通表达
- **难度**：困难
- **岗位**：全部
- **时长**：5
- **考察**：被贬低时还能不能给出工程化的回答，而不是辩解
- **题面**：说实话，我觉得你说的这些 Agent 工程，不就是把 prompt 写长一点吗？有什么技术含量？
- **参考思路**：
  - 先接受合理的部分：「prompt 确实是其中一层，而且是最便宜的一层」——不辩解
  - 再用机制说明差异：prompt 只影响这一次输入，而 Agent 工程要处理的是决定权、停止条件、状态、工具边界这四件代码级的事
  - 给具体证据：max_steps、同签名重复检测、幂等键、stop_reason 分布，这些都不是写 prompt 能得到的
  - 用「prompt 决定单次质量上限，架构决定系统的成本与可靠性下限」收尾
- **加分**：
  - 给数字：同一任务把 prompt 写长，token 涨而成功率不动；加上停止条件与工具描述改写后，平均步数从 5.2 降到 3.8
  - 全程语速稳定，不抢话
- **扣分**：
  - 「不是的，Agent 还很复杂」——空泛反驳，且显得被激怒
  - 直接认输「您说得对，确实没啥技术含量」——为了迎合而否定自己
- **追问**：
  - 那你说一个不用 prompt 也能做到、而且真的提升了指标的动作
  - 如果预算只够做一件事，你先做 prompt 还是先做停止条件？为什么？
- **关联**：`02-Wiki/面试题库/01-Agent高频面试题.md`

### B3 · 这个概念你没在实际项目里用过吧？别编，我们就聊你做过的东西

- **维度**：沟通表达
- **难度**：困难
- **岗位**：全部
- **时长**：5
- **考察**：会不会硬撑——硬撑的人追问两层就露
- **题面**：这块你没在实际项目里用过吧？别编，我们就聊你真正做过的东西。
- **参考思路**：
  - 三段式：这块我没做过 → 我的理解是 X（给一个可证伪的猜测）→ 如果要验证我会先做什么
  - 主动降级成不确定，不要硬编；也不要一句「没用过」就沉默
  - 把话题接回自己真正做过的部分，并指出两者的机制差异在哪
  - 面试官此时在判断的是「诚实度 + 迁移能力」，不是那个知识点本身
- **加分**：
  - 主动给出验证路径：「我会先建 20 条样本做 A/B，门槛是成功率提升不低于 20 个百分点」
  - 说「这块我没在线上跑过，我的理解是……」，用词精确地标注不确定
- **扣分**：
  - 硬撑「用过」，追问两层就开始自相矛盾
  - 一句「没用过」然后沉默，或者立刻转移话题
- **追问**：
  - 那你估计它在你那个场景能提升多少？依据是什么？
  - 你打算怎么在两周内验证你的猜测？
- **关联**：`02-Wiki/面试题库/03-项目表达与追问应对.md`

### B4 · 你刚才答了两分钟，我没听明白重点——用三句话再讲一遍

- **维度**：沟通表达
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：被要求压缩时能不能给出结论先行的三段式，而不是把原话再说一遍
- **题面**：你刚才讲了两分钟，我没听明白重点。用三句话再讲一遍，结论先说。
- **参考思路**：
  - 结构：一句结论加一句依据加一句边界，主动丢掉所有铺垫
  - 如果记不住细节，就说「细节我可以展开，先把结论给你」
  - 压缩之后仍然要带一个数字或一个机制名，否则三句话全是形容词
- **加分**：
  - 压完之后主动问「需要我展开哪一部分」，把主动权接回来
  - 三句话里保持「结论 → 依据 → 边界」的顺序，不自乱阵脚
- **扣分**：
  - 重复刚才那两分钟，只是语速变快
  - 开始道歉和自我否定（「不好意思，我表达不太好」）
- **追问**：
  - 你觉得刚才为什么讲不清？下次你会怎么组织？
  - 如果只有 30 秒，你会砍掉哪一部分？
- **关联**：`02-Wiki/面试题库/03-项目表达与追问应对.md`

### B5 · 你的项目没上线吧？那这些指标有什么意义？

- **维度**：沟通表达
- **难度**：困难
- **岗位**：全部
- **时长**：5
- **考察**：能不能说清离线指标的合法性与局限，而不是把离线数据说成线上数据
- **题面**：你这个项目应该没上线吧？那你说这些指标有什么意义？
- **参考思路**：
  - 先承认：没有真实流量，这是事实
  - 说清替代口径：离线评测集 20–50 条来自真实问题、判据由谁写、跑几次取一致结果
  - 说清局限：绝对值换一批数据会变，所以看的是改动前后的相对变化
  - 给可上线的判断依据：单次成本、成功率、越权拦截率三个数能报出来，并且有兜底路径
- **加分**：
  - 说「没有真实用户时，离线评测集是我唯一需要的流量——它能在半天内判断一次改造是否有效」
  - 主动说「如果让我现在上线，我还差灰度与回滚这两块」
- **扣分**：
  - 把离线指标说成线上指标，或者含糊其辞
  - 「指标确实没什么意义」——直接放弃防守
- **追问**：
  - 如果让你现在上线，你还差什么？
  - 上线之后你最先盯哪个指标？为什么是它？
- **关联**：`02-Wiki/面试题库/03-项目表达与追问应对.md`

### B6 · 你为什么从上家离职？为什么投我们？

- **维度**：沟通表达
- **难度**：基础
- **岗位**：全部
- **时长**：4
- **考察**：动机是否清晰，说话是否对事不对人
- **题面**：你为什么从上家离职？又为什么投我们？
- **参考思路**：
  - 对事不对人：说环境、说方向，不说人，不抱怨前公司
  - 给一个与目标岗位一致的动机：我想做的是 Agent 的工程化，不是调用现成平台
  - 说清做过功课：这家公司在做什么、这个岗位的核心目标可能是什么
  - 「我为什么投这家」要有一句话的答案，不要临场编
- **加分**：
  - 把动机接回具体的技术方向（评测体系、工具治理、成本工程）
  - 说「我更想在一个已经有真实流量的场景里把指标做扎实」
- **扣分**：
  - 抱怨领导或同事，或者把「钱少」当唯一理由
  - 说不出自己为什么投这家，只会说「平台大、机会好」
- **追问**：
  - 如果这里的活和你预期的不一样呢？
  - 你希望半年后自己在这个岗位上做成什么事？
- **关联**：`docs/第16章 毕业设计与面试.md`

### B7 · 如果我现在给你一个类似的需求，你多久能交付？

- **维度**：沟通表达
- **难度**：进阶
- **岗位**：全部
- **时长**：4
- **考察**：估算是先问约束还是先给日期——给日期的人往往过度承诺
- **题面**：你刚才说那个项目做了三周。如果我现在给你一个类似的需求，你多久能交付？
- **参考思路**：
  - 先问约束：验收标准是什么、数据在哪、有没有评测集、要不要上线
  - 再给分阶段估计：第一周跑通并建 20 条评测集，第二周出指标与 bad case 分析
  - 说明估计依据：按模块估，不是拍脑袋；把风险项单独列出来
  - 给一个「最小可交付」的定义，让对知道最早能看到什么
- **加分**：
  - 说「我会先给一个三天能跑的 Workflow 版本，让业务方看到东西再谈优化」
  - 主动说风险：数据质量与评测集往往是最容易拖期的一环
- **扣分**：
  - 「三天就行」——过度承诺，面试官会继续加压
  - 「看情况」——没有结构，等于没答
- **追问**：
  - 如果第三周指标还不达标怎么办？
  - 你会砍掉哪个模块来保交付？依据是什么？
- **关联**：`01-Raw/03-项目阶梯与能力对照表.md`

### B8 · 你有什么想问我的？

- **维度**：沟通表达
- **难度**：基础
- **岗位**：全部
- **时长**：5
- **考察**：反问是判断团队值不值得去的唯一机会，也是最后一次展示水平的机会
- **题面**：时间差不多了，你有什么想问我的吗？
- **参考思路**：
  - 问能判断团队成熟度的问题：现在有评测集吗、谁维护、多久跑一次；线上怎么发现某个改动让它变差了；危险动作的确认门放在哪一层；线上成本怎么控
  - 准备 5 个，问 2–3 个，按对方的回答接着问一层
  - 不问薪资、加班、远程（这些找 HR）；不问官网能查到的信息
  - 收尾问一句「如果我有机会加入，你希望我第一个月先把哪件事做起来」
- **加分**：
  - 把反问接回自己的经历：「我之前这个问题是靠 X 解决的，很好奇你们是怎么处理的」
  - 对方回答之后追问一层，说明你真的在听
- **扣分**：
  - 「我有机会吗？」——把判断权交出去
  - 一个都不问，或者只问「你们用什么模型」
- **追问**：
  - 反过来问候选人一句「那你觉得这个问题该怎么解」——看他会不会顺着刚才的上下文给出方案
  - 他问的这些问题里，你最想听到哪一个？为什么？（面试官自评：反问的质量比答案的质量更能反映他平时在想什么）
- **关联**：`02-Wiki/面试题库/01-Agent高频面试题.md`
