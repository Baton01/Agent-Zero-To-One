# 第00章 环境准备与第一次模型调用

> **本章目标：** 不装任何第三方包、不花钱，用标准库亲手发出一次模型请求，并看懂请求与响应里的每个字段。
> **预计用时：** 2 小时　**前置章节：** 无（本书起点）　**配套代码：** `code/ch00_env_check.py`

## 0. 开篇：一个真实的问题

小周是测试工程师，想转 AI 应用开发。周一晚上，他照着教程在自己的 Windows 笔记本上敲下第一行命令，然后被卡了整整一周。

> **他：** `pip install openai` 卡了 8 分钟，最后报 `Read timed out`，是不是我的电脑有问题？
>
> **同事：** 不是。默认源在海外，换成国内镜像就行。
>
> **他：** 换完镜像装上了，可抄来的 20 行示例又报 `AttributeError: module 'openai' has no attribute 'ChatCompletion'`。
>
> **同事：** 你那篇文章写的是 0.x 版本的写法，你装的是 1.x。
>
> **他：** 行，那我先配 Key。结果报 401，我查了一下午，最后发现是 `Bearer` 后面漏了一个空格。
>
> **同事：** 那你有没有想过 —— 你抄的这 20 行，最后到底往哪个地址、发了什么内容？

小周答不上来。周二他去注册 API 平台，要实名认证；周三认证过了，发现余额是 0 元得先充值；周四加班没学。到周五，他一行"真正跟模型说上话"的代码都没跑起来，笔记本上写着「AI 好难」。

这不是能力问题，是**第一课的路径设计问题**：装包、镜像、版本、实名、充值，全堵在"看见模型回答"之前。本章只做一件事：

> **在 40 分钟内，用最少的步骤，让你亲眼看到模型对一个请求作出了回答。**

为此做了两个刻意的设计：**零第三方依赖**（只用标准库，不装包就没有网络、镜像、版本冲突这三座山）；**零成本可跑**（没有 API Key 也能跑完，后面的 16 章都能这样跑）。

读完本章你应该能回答一个问题：**当我调用一次大模型时，网络上到底发生了什么？** 这个答案比记住任何 SDK 的写法都值钱 —— SDK 会变，HTTP 契约十年没变。

## 1. 为什么第一课不装任何包

### 1.1 先讲"装了会出什么问题"

`pip install openai` 在国内环境下至少有四种失败方式，而 0 基础读者很难分辨它们：

| 现象 | 真实原因 | 新手容易误判为 |
|------|----------|----------------|
| `Read timed out` | 默认 pypi.org 在海外，网络慢 | "我的 Python 坏了" |
| `Could not find a version that satisfies the requirement` | 镜像源没配，或包名打错 | "这个包不存在" |
| `ERROR: Cannot uninstall 'xxx'` | 与已有版本冲突 | "电脑中毒了" |
| 装上了但 `AttributeError` | 抄的示例代码是旧版 API | "教程是骗人的" |

四种里至少有三种跟"能不能学 AI"毫无关系，但它们会在第一天消耗掉你的全部耐心。

### 1.2 本项目怎么做

**第 0 章到第 16 章的代码，全部只用 Python 标准库就能在 Mock 模式下跑通。** `code/requirements.txt` 里列的是可选的增强依赖（第 08 章向量检索、第 13 章 Web 部署用到），不装它前面的章节照样跑。

更重要的是第二个好处：**你会看到模型的"原始形态"。** 一次模型调用本质上就是一次 HTTPS POST —— 发一段 JSON 出去，收一段 JSON 回来。所有 SDK（`openai`、`dashscope`、各家框架）都只是这层 HTTP 的包装；如果第一眼看到的就是包装，那么当包装出问题时（超时、重试、参数被吞），你就没有能力往下追。

```text
你的脚本
  │  HTTPS POST  https://api.deepseek.com/v1/chat/completions
  │  Header:  Authorization: Bearer sk-xxxx
  │  Header:  Content-Type: application/json
  │  Body:    {"model": "...", "messages": [...], "temperature": 0.7}
  ▼
服务商网关 ── 鉴权 ── 余额/配额检查 ── 排队
  ▼
模型推理（整个链路里唯一真正"想"的一步）
  ▼
网关返回 JSON：choices[0].message.content  +  usage
  ▼
你的脚本：json.loads → 取 content → 打印
```

这张图就是本章的全部内容。下面我们一段一段把它变成代码。

### ⚠️ 常见坑

- **坑：把 `AGENT_MOCK=1` 当成"假装运行"。** 它不是空跑：Mock 会真实地走完你的 `while` 循环、真的解析 tool_call、真的调用你的工具函数，只有"思考"那一步由规则替代。详见第 7 节。
- **坑：跳过本章直接抄第 01 章的代码。** 第 01 章开始用 `code/common/llm.py` 封装，你看不到请求体长什么样，之后遇到 401/404 只能靠猜。本章的 20 行原始代码值得亲手敲一遍。

## 2. 检查 Python 版本

本项目要求 **Python 3.9 或更高**。所有代码都刻意避开了 3.10+ 的语法（比如 `match` 语句和 `str | None` 这种注解写法），所以 3.9 能完整跑通全部 17 章。

```bash
# Windows 推荐用 py 启动器，它能列出所有已安装版本
py -3 --version
py -0                 # 列出本机装过的所有 Python（仅 Windows 启动器支持）

# macOS / Linux / Git Bash
python3 --version

# 通用
python --version
```

期望输出类似 `Python 3.11.6`。只要 3.9.x 及以上都可以；如果显示 `Python 2.7.18`，说明系统里同时存在 Python 2，把所有命令里的 `python` 换成 `python3` 或 `py -3`。

### ⚠️ 常见坑

- **现象：`'python' 不是内部或外部命令`。** 原因：Windows 安装时没勾选 "Add Python to PATH"。改法：重新运行安装包 → Modify → 勾上 PATH 选项；或者不重装，直接用 `py -3` 代替 `python`（安装器默认会装 py 启动器）。
- **现象：输入 `python` 弹出了微软应用商店。** 原因：Windows 的"应用执行别名"占位符。改法：设置 → 应用 → 高级应用设置 → 应用执行别名 → 关掉 `python.exe` 和 `python3.exe` 两个开关。
- **现象：`py -3 --version` 有输出，但 `python --version` 报错。** 说明 PATH 里只有启动器。把本章所有命令的 `python` 都替换成 `py -3` 即可，不影响后续学习。
- **现象：多个 Python 版本，装包装到了错误的那一个。** 排查方法：`where python`（Windows）/ `which -a python3`（macOS/Linux）看清楚到底在用哪个；再配合 `python -c "import sys; print(sys.executable)"` 打印绝对路径。**记住这个命令，它是排查"我明明装了却 import 不到"的第一招。**

## 3. 虚拟环境（venv）：为什么需要，怎么做

### 3.1 先讲不用的后果

如果你直接在系统 Python 里 `pip install`，所有包都装在同一个 `site-packages` 目录里。于是会出现这种局面：

```text
项目 A 需要 openai==0.28（老教程的写法）
项目 B 需要 openai==1.40（新教程的写法）
```

pip 只能保留一个版本。你装了 B 的版本，A 就跑不起来；降级回 A，B 又坏了。这种问题在新手眼里表现为 "昨天还能跑的代码今天报错了"，极难自己定位。

**虚拟环境（venv）就是给每个项目发一个独立的工具箱。** 项目 A 一个文件夹，项目 B 一个文件夹，互不干扰，删掉文件夹就等于卸载干净。

### 3.2 完整步骤

在项目根目录（`Agent-Zero-To-One/`）下执行：

```bash
# ── Windows（CMD / PowerShell）────────────────────
py -3 -m venv .venv
.venv\Scripts\activate

# ── macOS / Linux / Git Bash ────────────────────
python3 -m venv .venv
source .venv/bin/activate
```

**注意 Windows 和类 Unix 的目录名不一样**：Windows 是 `Scripts`，macOS/Linux 是 `bin`。这是 Git Bash 用户最常踩的一个坑（Git Bash 在 Windows 上跑，虚拟环境里生成的仍然是 `Scripts`）。

激活成功的标志是命令行提示符前面多出 `(.venv)`：

```text
(.venv) C:\Users\you\Agent-Zero-To-One>
```

退出环境：

```bash
deactivate
```

顺手升级 pip（只影响当前虚拟环境）：`python -m pip install -U pip`。

### ⚠️ 常见坑

- **现象（PowerShell）：`无法加载文件 ...\Activate.ps1，因为在此系统上禁止运行脚本`。** 原因：PowerShell 默认执行策略是 Restricted。改法二选一：① 当前用户放开：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`；② 换成 CMD 或 Git Bash，直接不碰这个策略。
- **现象（Git Bash）：`source .venv/bin/activate` 报 `No such file or directory`。** 原因：Windows 上 venv 生成的是 `Scripts` 目录。改法：`source .venv/Scripts/activate`。
- **现象：以为激活了，其实没有；`pip install` 装到了全局。** 判断方法：`python -c "import sys; print(sys.prefix)"`，路径里带 `.venv` 才算在环境里。另一个信号是 pip 安装时的提示有没有 `(.venv)` 前缀。
- **现象：`python -m venv .venv` 报 `ensurepip is not available`。** 原因：Linux 上装的是精简版 Python（缺 `python3-venv`）。改法：`sudo apt install python3-venv`。
- **现象：`TypeError: Object of type bytes is not JSON serializable`。** 原因：把 encode 过的字节直接塞进了 `json.dumps`。顺序永远是"先 dumps 再 encode"。
- **提醒：`.venv/` 不要提交到 Git。** 它体积大、和本机路径绑定，别人 clone 后重新 `python -m venv .venv` 就行，`.gitignore` 见第 6 节。

## 4. 零依赖调用模型：手写一次 HTTP POST

现在开始本章的核心。打开 `code/ch00_env_check.py` 的对应片段，或者新建一个 `my_first_call.py` 跟着敲。

```python
"""第一次模型调用：只用标准库，把请求体和响应体都看清楚。"""
import json
import urllib.error
import urllib.request


def call_model_once(prompt, api_key, base_url, model):
    """发一次 chat/completions 请求，返回原始响应 dict。"""
    url = base_url.rstrip("/") + "/chat/completions"

    payload = {
        "model": model,
        "messages": [
            {"role": "system", "content": "你是一个简洁的助手，回答不超过 50 个字。"},
            {"role": "user", "content": prompt},
        ],
        "temperature": 0.7,
        "stream": False,
    }

    body = json.dumps(payload).encode("utf-8")     # 中文必须编码成 UTF-8 字节
    request = urllib.request.Request(
        url,
        data=body,
        headers={
            "Content-Type": "application/json",     # 少了它，很多网关直接 400
            "Authorization": "Bearer " + api_key,   # Bearer 后面有一个空格
        },
        method="POST",
    )

    try:
        with urllib.request.urlopen(request, timeout=30) as response:
            raw = response.read().decode("utf-8")
    except urllib.error.HTTPError as error:
        # 关键技巧：HTTPError 本身是可读的，服务端到底说了什么都在 body 里
        detail = error.read().decode("utf-8", "ignore")
        raise RuntimeError("HTTP %s\n服务端返回：%s" % (error.code, detail))

    return json.loads(raw)


if __name__ == "__main__":
    import os
    api_key = os.environ.get("OPENAI_API_KEY", "")
    base_url = os.environ.get("OPENAI_BASE_URL", "https://api.deepseek.com/v1")
    model = os.environ.get("OPENAI_MODEL", "deepseek-chat")
    result = call_model_once("用一句话解释什么是 Python。", api_key, base_url, model)
    print(json.dumps(result, ensure_ascii=False, indent=2))      # 先看原始结构
    print("模型说：", result["choices"][0]["message"]["content"])
```

### 4.1 请求里的每个字段

| 位置 | 字段 | 作用 | 写错的后果 |
|------|------|------|-----------|
| URL | `base_url + /chat/completions` | 接口路径。`base_url` 只到版本号，如 `https://api.deepseek.com/v1` | 拼错 → 404 |
| Header | `Authorization: Bearer <key>` | 身份凭证。`Bearer` 与 key 之间**一个空格** | 漏空格 / 重复加 Bearer → 401 |
| Header | `Content-Type: application/json` | 告诉服务端 body 是 JSON | 写成 `text/plain` → 部分网关 400 |
| Body | `model` | 用哪个模型，字符串，必须和服务商的命名完全一致 | 拼错 → 404 或 `model not found` |
| Body | `messages` | 对话历史数组，**请求的全部语义都在这里** | 结构错 → 400 |
| Body | `temperature` | 随机性，0 最稳、1 最发散（第 02 章细讲） | 超范围 → 400 |
| Body | `stream` | 是否流式返回（第 02 章细讲） | 传 `"true"` 字符串 → 400 |

`messages` 是本项目后面每一章都要打交道的核心结构，它只有三个常用角色：

```json
[
  {"role": "system",    "content": "你是一个订单抽取器，只输出 JSON。"},
  {"role": "user",      "content": "订单 A12345678 一共 199 元。"},
  {"role": "assistant", "content": "{\"order_id\": \"A12345678\"}"},
  {"role": "user",      "content": "再抽一次客户名。"}
]
```

- `system`：全局设定，相当于给模型的岗位说明书。通常只有一条，放在最前面。
- `user`：你（或者你的程序）说的话。
- `assistant`：**模型上一轮的回答**。注意：这不是你写的，是模型生成的，你要把它的原话**原样加回数组**，模型才知道自己上轮说过什么。

第 4 条消息的存在，就是"多轮对话"的全部秘密：**模型没有记忆，每一轮你都要把完整历史重新发一遍。** 这也是 Agent 循环烧钱的根本原因（第 02 章算这笔账）。

### 4.2 响应里的每个字段

一次成功的响应长这样（真实响应已精简，`usage` 数字随内容变化）：

```json
{
  "id": "chatcmpl-9f2c1a3b",
  "object": "chat.completion",
  "created": 1737000000,
  "model": "deepseek-chat",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Python 是一门语法简洁、生态丰富的通用编程语言。"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 32,
    "completion_tokens": 21,
    "total_tokens": 53
  }
}
```

| 字段 | 含义 | 为什么你要关心 |
|------|------|----------------|
| `choices[0].message.content` | 模型的回答文本 | 90% 的代码就是在取这个值 |
| `choices[0].finish_reason` | 为什么停下来 | `stop`=正常说完；`length`=被 `max_tokens` 截断（JSON 会残缺！）；`tool_calls`=模型要调工具（第 04 章） |
| `usage.prompt_tokens` | 输入计费量 | 算钱的输入侧 |
| `usage.completion_tokens` | 输出计费量 | 算钱的输出侧，单价通常是输入的 3–4 倍 |

### ⚠️ 常见坑

- **现象：`urllib.error.HTTPError: HTTP Error 401: Unauthorized`，什么信息都没有。** 原因：只看了异常的类型，没读 body。改法：像上面代码那样 `except urllib.error.HTTPError as error: error.read()` —— 服务端返回的 `{"error": {"message": "Authentication Fails..."}}` 会直接告诉你原因。**这是本章最值得记住的一个调试技巧。**
- **现象：`UnicodeEncodeError: 'ascii' codec can't encode characters`。** 原因：`json.dumps` 之后忘了 `.encode("utf-8")`，或者用了 `str(payload).encode()`。改法：严格按 `json.dumps(payload).encode("utf-8")` 写。
- **现象：Windows 终端里中文显示成 `ä½ å¥½`。** 原因：终端编码是 GBK。改法：运行前设 `set PYTHONIOENCODING=utf-8`（CMD）或 `chcp 65001`；打印时加 `ensure_ascii=False` 也能改善。
- **现象：`KeyError: 'choices'`。** 原因：直接用 `resp["choices"]` 而没有先确认响应结构。调试期先 `print(json.dumps(result, ensure_ascii=False, indent=2))` 看完整结构，再写取值代码。

## 5. 什么是"OpenAI 兼容接口"

2023 年 OpenAI 定义了 `POST /v1/chat/completions` 这套 HTTP 契约。因为生态里几乎所有工具（客户端、框架、SDK）都按它写代码，后来的模型服务商为了让"现有工具能直接连上自己"，纷纷实现了同一套接口 —— 这就是"**OpenAI 兼容接口**"。它的价值非常具体：**换服务商只需要改 3 个字符串**（`base_url` / `api_key` / `model`），代码一行都不用动。

下表是 0 基础起步最常用的一批服务（价格与模型名会变，以各官网当期文档为准）：

| 服务商 | `base_url` | 示例模型名 | 备注 |
|--------|-----------|-----------|------|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 中文好、便宜，本书示例默认用它 |
| 通义千问（DashScope 兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 路径里必须有 `compatible-mode` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | 路径不含 `/v1`；有免费档模型 |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | 长文本见长 |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` | 聚合多家模型，模型名带斜杠 |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | 需要海外网络与支付方式 |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` | 完全离线，`api_key` 随便填非空字符串 |

配置方式就是本章第 6 节的 `.env` 三个变量。

### ⚠️ 常见坑

- **现象：通义千问报 400 且提示 `url error` 或字段不认识。** 原因：用了原生接口地址 `https://dashscope.aliyuncs.com/api/v1`，那是另一套协议，字段名不同。改法：认准 `compatible-mode`。
- **现象：智谱报 404。** 原因：智谱的 `base_url` 是 `https://open.bigmodel.cn/api/paas/v4`，**没有 `/v1`**，很多人习惯性补一个。改法：以官网给出的完整地址为准，代码里用 `base_url.rstrip("/")` 防止末尾斜杠导致 `//chat/completions`。
- **现象：本地 Ollama 报 `Connection refused`。** 原因：服务没启动。改法：先 `ollama serve`，再 `curl http://localhost:11434/v1/models` 确认能通。

## 6. `.env` 文件：配置与代码分离

### 6.1 为什么不能把 key 写在代码里

三个真实后果：**会泄露**（提交过一次就永久留在 Git 历史里，截图、录屏、发群求助也会带出去）；**会互相覆盖**（key 写死在多个脚本里，改 key 时漏掉一处，就出现"为什么这个脚本能用那个不能用"）；**会误提交**（别人 clone 你的仓库用你的 key 跑，账单算你的）。

正确做法：**key 放在一个不进 Git 的文件里，代码从环境变量读。**

### 6.2 创建 `.env`

在 `code/` 目录下新建 `.env`（与脚本同级）：

```ini
# code/.env —— 这个文件永远不要提交到 Git
OPENAI_API_KEY=sk-你的密钥
OPENAI_BASE_URL=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-chat
```

同时把 `code/.env.example`（只有变量名、没有真实值）提交上去，让后来者知道要配哪些变量。注意 `.env` 必须和脚本同在 `code/` 目录下 —— 放到仓库根目录，脚本就读不到，会静默进入 Mock 模式。

### 6.3 手写一个 10 行的解析器

`.env` 不是 Python 标准，它只是一个约定俗成的文本格式。手写解析的好处是你完全知道它做了什么 —— `code/common/llm.py` 里的 `load_env()` 就是这么实现的：

```python
import os

def load_env(path):
    """读取 .env 并写入 os.environ。已存在的环境变量优先，不会被覆盖。"""
    if not os.path.exists(path):
        return
    with open(path, "r", encoding="utf-8") as handle:
        for line in handle:
            line = line.strip()
            # 跳过空行、注释、不含等号的行
            if not line or line.startswith("#") or "=" not in line:
                continue
            key, _, value = line.partition("=")      # 只按第一个等号切分
            key = key.strip()
            value = value.strip().strip('"').strip("'")
            if key and key not in os.environ:
                os.environ[key] = value
```

两个设计点：**不覆盖已存在的环境变量**（临时换 key 只要 `export OPENAI_API_KEY=xxx`，优先级高于 `.env`，CI 同理）；**所有脚本只需在开头调一次 `load_env()`**，不用额外装 `python-dotenv`。

### 6.4 别忘了 `.gitignore`

仓库根目录的 `.gitignore` 至少要有四行：`.env`、`.venv/`、`__pycache__/`、`*.pyc`。

**如果 key 已经提交过，删文件是不够的** —— Git 历史里还有。正确顺序：① `git rm --cached code/.env`（从版本控制移除，保留本地文件）；② 把 `.env` 写进 `.gitignore` 并提交；③ **立刻去服务商控制台删除该 key 并重新生成** —— 历史提交可能已被同步到远端，任何人都能翻出来。

### ⚠️ 常见坑

- **现象：配了 `.env`，脚本还是进入 Mock 模式。** 原因：`.env` 放错目录（放到了仓库根目录，而 `load_env()` 读的是 `code/.env`）。改法：打印 `os.path.abspath("...")` 确认路径；本项目所有脚本都用"相对脚本自身位置"的路径读取，所以只要 `.env` 和脚本同在 `code/` 下就一定能读到。
- **现象：401，但 key 看起来完全正确。** 原因：值被引号包住了（`OPENAI_API_KEY="sk-xxx"` 在某些解析器里引号会变成值的一部分），或者从网页复制时带了零宽字符 `\u200b`。排查方法：`print(repr(os.environ.get("OPENAI_API_KEY")))` —— 用 `repr` 才能看见不可见字符和多余引号。
- **现象：全角等号 `＝`。** 肉眼几乎和 `=` 一样，但 `"=" in line` 判定为 False，整行被跳过。用 `repr` 一眼就能看出来。

## 7. 离线 Mock 模式：没有 Key 也能学完 17 章

### 7.1 为什么要有这个东西

三个真实场景：**还没充值**、**公司网络访问不了 API**、**想先看懂流程再花钱**。如果这些情况意味着"无法学习"，那 90% 的人会在这里流失。所以本项目内置了离线 Mock：**当检测到没有可用的 key，或者显式设置了 `AGENT_MOCK=1` 时，全部模型调用由 `code/common/llm.py` 用规则生成的假响应替代。**

| 触发条件 | 结果 |
|----------|------|
| `AGENT_MOCK=1` | 强制离线，即使有 key 也不用 |
| 没有 `OPENAI_API_KEY` | 自动离线 |
| 有 key，且 `AGENT_MOCK` 不是 `"1"` | 在线，真实调用 |

三种设置方式（Windows 与类 Unix 差异很大，这里一次讲清）：

```bash
# macOS / Linux / Git Bash
AGENT_MOCK=1 python ch00_env_check.py

# Windows CMD
set AGENT_MOCK=1 && python ch00_env_check.py

# Windows PowerShell
$env:AGENT_MOCK="1"; python ch00_env_check.py
```

### 7.2 Mock 到底"真"在哪、"假"在哪

| 环节 | 离线 Mock 的表现 | 是否真实执行 |
|------|-----------------|-------------|
| 你的 `while` 循环、`if` 分支 | 完全按真实代码走 | 真实 |
| `tool_calls` 的解析与执行 | 按工具名匹配，真实调用你的函数 | 真实 |
| RAG 的切片、检索、排序 | 真实计算 | 真实 |
| Token 统计与成本估算 | 按字符数近似 | 真实（近似值） |
| 「模型怎么想」 | 规则替代：关键词命中就返回对应结果 | **假** |
| 模型对 Prompt 的理解能力 | 完全无法体现 | **假** |

结论：**Mock 模式验证"流程是否正确"，不验证"效果好不好"。** 所以每个章节的推荐流程是：先用 `AGENT_MOCK=1` 跑通、看懂每一步，再切到在线模式观察真实差异。这也是本项目 CI 里跑测试的方式 —— 不需要密钥就能保证代码没写错。

代码里判断当前模式：

```python
from common.llm import is_mock_mode

if is_mock_mode():
    print("当前：离线 Mock 模式（不会产生任何费用，也不会真的问模型）")
else:
    print("当前：在线模式（会产生费用）")
```

### ⚠️ 常见坑

- **现象：`export` 在 Windows CMD 里报 `'export' 不是内部或外部命令`。** 原因：那是 Linux 语法。改法：用上面列出的对应平台写法。
- **现象：设了 `AGENT_MOCK=0` 却还是离线。** 原因：判定规则是 `== "1"`，所以 `AGENT_MOCK=0` 不算强制离线；此时如果你**没有 key**，仍然会自动进入 Mock。想在线就必须"有 key + 不设 `AGENT_MOCK=1`"。
- **现象：以为 Mock 跑通了就等于学会。** 常见后果：在线一跑发现 prompt 效果完全不对。改法：每章的"在线验证"步骤不要跳过，至少跑一次真模型。

## 8. 排错手册：401 / 404 / 429 / 超时 / SSL

出问题时的第一原则：**先看服务端返回的 body，再猜原因。** 下面是本项目学习者最常遇到的几类问题。

| 现象 | 典型报错 | 真实原因 | 第一步检查动作 |
|------|----------|----------|----------------|
| **401** | `Authentication Fails` / `invalid api key` | key 错、过期、被禁用、带了引号或空格、重复加了 `Bearer` | `print(repr(key))` 对比前后 6 位；确认 Header 是 `Bearer sk-xxx` 而不是 `Bearer Bearer sk-xxx` |
| **404** | `{"error":{"message":"Not Found"}}` 或 `model not found` | `base_url` 少/多了 `/v1`（智谱是 `/api/paas/v4`）、路径拼错；或模型名拼错、未开通 | 打印拼好的完整 URL 与官网逐字符对比；模型名从控制台列表复制 |
| **400** | `maximum context length is 65536 tokens, however you requested 70000` | 输入太长，超过上下文窗口 | 数一下 messages 的总字数（第 02 章教估算） |
| **400** | `invalid type: string "true", expected a boolean` | 参数类型错，比如 `"stream": "true"` | 打印请求体，确认布尔值不是字符串 |
| **429** | `insufficient_quota` / `Insufficient Balance` | **余额不足**（这不是限流！） | 去控制台看余额，充值即可 |
| **429** | `rate_limit_exceeded` / `Requests rate limit exceeded` | 请求太密，触发频率限制 | 加 `time.sleep(1)` 重试；确认是不是循环里没加间隔 |
| **超时** | `urlopen error timed out` / `Read timed out` | 网络不通、需要代理、服务端排队慢 | `curl -I https://api.deepseek.com` 看能否连通；公司网络要配 `HTTPS_PROXY` |
| **SSL** | `SSLCertVerificationError` / `CERTIFICATE_VERIFY_FAILED` | 公司代理替换了证书，或系统根证书过期 | 用 `curl` 访问同一地址对比；确认是否需要把公司根证书加入信任链 |
| **连接拒绝** | `ConnectionRefusedError: [WinError 10061]` | 本地服务没起（Ollama），或端口写错 | `curl http://localhost:11434/v1/models` |

两个额外的提醒：**区分 429 的两种含义** —— `insufficient_quota` 是没钱（重试一万次也没用），`rate_limit_exceeded` 是太快（等待重试有效），很多人看到 429 就加 `time.sleep` 死循环，白白浪费时间；**兜底二分法（本项目通用）** —— 先跑 `AGENT_MOCK=1 python chXX_xxx.py`，Mock 能跑通而在线跑不通就是配置/网络/账户问题（按上表查），Mock 也跑不通就是代码问题（看 traceback 最后一行）。

## 自测题

**第 1 题：** 请求里 `Authorization` 头的正确写法是什么？写错会返回哪个状态码？

**第 2 题：** `messages` 数组里 `role: "assistant"` 的消息是谁产生的？多轮对话里为什么必须把它加回去？

**第 3 题：** 模型的 key 已经提交到 Git 了，只执行 `git rm code/.env` 再提交为什么不够？完整的补救步骤是什么？

**第 4 题：** `AGENT_MOCK=1` 时"模型回答"是真实推理出来的吗？这个模式能验证什么，不能验证什么？

**第 5 题：** 收到 429 时，怎么区分"账户没钱了"和"请求太快了"？两种情况分别该怎么处理？

<details>
<summary>点击查看答案</summary>

**第 1 题：** `Authorization: Bearer sk-xxxxxxxx`，`Bearer` 与密钥之间**恰好一个空格**。常见错误是漏空格（`Bearersk-xxx`）或重复前缀（`Bearer Bearer sk-xxx`），都会导致 **401 Unauthorized**。

**第 2 题：** 是模型在上一轮生成的内容（不是人写的）。大模型本身**没有跨请求的记忆** —— 它只看得见本次请求里的 `messages`。所以你要把历史逐条带上，模型才能"记得"上轮说过什么。这也解释了为什么对话越长、每轮输入 token 越多、成本增长越快。

**第 3 题：** 因为 Git 历史里仍然有那次提交的内容，任何人 `git log -p` 都能翻出来，远端仓库同样保留。完整步骤：① `git rm --cached code/.env`（从版本控制移除、保留本地文件）；② 把 `.env` 写进 `.gitignore` 并提交；③ **立刻到服务商控制台删除该密钥并重新生成一个** —— 泄露过的密钥必须视为已作废。

**第 4 题：** 不是，"思考"那一步由规则替代，是假的。它能验证：代码流程、`while` 循环与分支、`tool_calls` 的解析与执行、JSON 结构、RAG 的切片与排序、成本估算逻辑。不能验证：Prompt 的好坏、模型对复杂指令的理解、输出质量的稳定性。所以每章建议"Mock 跑通 → 在线再跑一次做对比"。

**第 5 题：** 看响应体里的错误码：`insufficient_quota`（或 `Insufficient Balance`）表示**余额/配额问题**，重试无效，要去控制台充值；`rate_limit_exceeded` 表示**频率限制**，等待后重试有效（加退避重试 `time.sleep`）。只看状态码 429 分不出来，所以"读服务端 body"永远是排查的第一步。

</details>
