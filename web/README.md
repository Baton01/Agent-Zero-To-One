# web · 网页版学习系统

> 把整个项目（17 章教程 + 9 个专题 + 5 份速查表 + 3 份题库 + 16 周笔记 + 8 级项目阶梯 + 规划文档）
> 变成一个**可以双击打开、离线可用、能记录学习进度**的单页应用。

---

## 一、怎么打开

### 方式 A：直接双击（推荐）

打开 `web/index.html` 就行。不需要服务器、不需要联网、不需要装任何东西。

> **为什么能双击打开？** 浏览器在 `file://` 协议下禁止 `fetch()` 读本地文件。所以本项目的内容
> 不是运行时从 Markdown 读取的，而是由 `_build.py` **在构建期**把全部 Markdown 嵌进了
> `content.js`，页面用 `<script src>` 加载它 —— 这条路不受 CORS 限制。
> 全站零 `fetch`、零 `XMLHttpRequest`、零 CDN 依赖。

### 方式 B：起一个本地服务器

```bash
cd web
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

用这种方式**改了 CSS 或 JS 之后**要按 `Ctrl+Shift+R` 硬刷新 —— 默认的 Python 静态服务器
不发 `Cache-Control`，浏览器会吃磁盘缓存，普通刷新拿不到新文件。

### 三个值得一说的细节

**全站搜索**：顶栏搜索框（快捷键 `/`）会在 17 章 + 全部知识库里做全文匹配，结果带**命中位置高亮**。搜索是防抖的 —— 因为内容有 1.4MB，等你不打字了再算。

**进度存在浏览器本地**：`localStorage` 的 `azto.progress.v1`。换设备或换浏览器就没了，所以「我的进度」页提供了**导出 JSON**。清空浏览器数据会丢进度，学习笔记请用 Git 备份。

**深色模式**：右上角 `◐` 切换，默认跟随系统。选择会记住。

## 三、内容更新后怎么同步

网页内容是**构建出来的**，不是手写的。改了 `docs/`、`02-Wiki/` 等任何 Markdown 之后：

```bash
cd ..                       # 回到项目根目录
python web/_build.py        # 重新生成 web/content.js
```

只改 CSS / JS 不需要重新构建，直接刷新页面即可。

### 构建脚本做了什么

1. 扫描 `docs/`、`02-Wiki/`、`01-Raw/`、`00-配置/`、`03-学习笔记/`、`学习中枢.md`、`README.md`
2. 从章节文档的头部提取结构化元信息：章节号、标题、**本章目标**、**预计用时**、**前置章节**、**配套代码**
3. 按 5 个阶段和 16 周给章节归组（映射写在脚本顶部的 `STAGES` / `WEEK_CHAPTERS` 里）
4. 把全部 Markdown 原文（约 1.4MB）连同元信息一起输出成 `web/content.js`

`_build.py --check` 可以只打印解析结果、不写文件，用来确认新章节有没有被正确识别：

```bash
python web/_build.py --check
```

**加新章节时**：把 Markdown 放进 `docs/`，文件名以 `第NN章 ` 开头，并保证章首有这四行：

```markdown
# 第NN章 标题

> **本章目标：** 一句话
> **预计用时：** N 小时　**前置章节：** 第XX章　**配套代码：** `code/chNN_xxx.py`
```

然后到 `_build.py` 的 `STAGES` 里把新章节号加进对应的阶段，重新构建。

## 四、文件说明

```
web/
├── index.html            # 应用外壳：顶栏、侧栏容器、启动画面
├── content.js            # 【自动生成】全部 Markdown + 元信息，约 1.4 MB
├── _build.py             # 构建脚本（Python 3.9+，只用标准库）
├── _test_md.js           # 渲染器测试（node web/_test_md.js，27 项检查）
└── assets/
    ├── app.css           # 全部样式：主题变量、深色模式、响应式、打印
    ├── app.js            # 应用逻辑：路由、进度存储、搜索、阅读器
    └── markdown.js       # 极简 Markdown 渲染器（约 600 行，零依赖）
```

### 为什么 Markdown 渲染器要自己写

项目的 Markdown 里有几样通用渲染器不一定会处理好的东西：`<details>` 折叠答案（自测题全靠它）、GFM 表格里的行内代码、`[[wikilink]]` 内部引用、中文排版空隙。自己写一个约 600 行的渲染器，能精确控制这些行为，而且**不需要联网加载任何 CDN 资源** —— 这与项目「离线优先」的原则一致。

它支持的语法、以及 27 项针对真实文档的自检（内容零丢失、表格/围栏数一致、折叠块数量一致、TOC 锚点可解析、XSS 防护），见 `_test_md.js`：

```bash
node web/_test_md.js
```

## 五、常见问题

**打开是一片空白？**
看浏览器控制台。多半是 `content.js` 没生成 —— 在项目根目录跑一次 `python web/_build.py`。

**样式改了没生效？**
用 `python -m http.server` 的话按 `Ctrl+Shift+R`。直接双击 `file://` 打开一般没这个问题。

**进度丢了？**
进度存在浏览器的 `localStorage` 里。清理浏览器数据、用无痕模式、或换浏览器都会丢。重要进度请到「我的进度」页**导出 JSON**。

**搜索很卡？**
首次搜索会构建索引（要把 1.4MB 文本转小写），大约几百毫秒。之后就快了。输入框有 160ms 防抖，正常打字感觉不到。

**手机上能用吗？**
能。小于 1100px 时侧边栏变成抽屉（左上角 `☰` 打开），小于 640px 时单列布局。
