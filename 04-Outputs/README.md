# 📦 04-Outputs · 产出区

> **这里放的是你自己的作品和复盘，不是学习资料。**
> 学习资料在 `docs/`、`02-Wiki/`；学习过程在 `03-学习笔记/`；**能拿给别人看的东西放这里**。

---

## 一、这个目录是干什么的

按重要性排序，三个用途：

1. **作品仓库**：项目阶梯 L1–L8 的交付物，每一级一个"能跑、有 README、有指标"的工程目录。
2. **复盘档案**：每周 / 每月一份，写清"做对了什么 / 做错了什么 / 下次怎么改"。
3. **简历与面试素材**：把作品翻译成简历语言与面试答案，每个数字都能答"怎么测的"。

**判断标准（一句话）：** 一份文件删掉之后你**不心疼**，它就不该放这里。

---

## 二、目录约定

```
04-Outputs/
├── README.md                  # 本文件：作品清单与模板
├── 知识图谱说明.md             # Obsidian 图谱与 wikilink 用法
├── l1-calculator-agent/       # 一级一个目录，命名 l<级别>-<简短英文名>
├── review-week01.md           # 复盘：每周一份
└── resume/                    # 简历素材（项目卡、量化结果、表达稿）
```

每个作品目录里至少要有：`README.md`（怎么跑 / 怎么配 / 怎么扩展 / **已知限制 ≥3 条**）、一键跑分脚本（输出主指标 + 反指标）、`evals/`（≥20 条，含无答案与恶意样本）、`traces/`（至少一次失败运行）、`requirements.txt`。**判据：** 陌生人照 README 在 10 分钟内能复现你的指标；做不到就还不是作品。

## 四、每个作品的记录模板

> 复制到作品目录下（建议命名 `作品记录.md`）。**关键指标一栏必须带数字。**

```
## 作品：xxx（L?）

**一句话：**
（给谁用 + 解决什么问题 + 效果多少，一句话说完，不许堆形容词）

**解决什么问题 / 给谁用：**
（具体角色，例：给每周要读 30 份 PR 的后端同学，减少走查时间）

**技术方案：**
（3~5 行：编排方式 / 检索方案 / 校验策略 / 关键取舍；每条附"为什么不用另一个"）

**关键指标：**（必须带数字，且写明怎么测的）
- 主指标：　　反指标：
- 成本：$/完成任务 =　　　延迟：P50 = 　P95 =
- 评测集规模：　　测法：

**踩过的坑：**
（至少 2 条，写"现象 → 原因 → 怎么改 → 指标变化"）

**如果重做会怎么改：**
（至少 1 条真取舍，不是"我会写更多测试"这种空话）

**演示方式：**（3 分钟怎么展示）
- 0:00–0:30 给谁用、解决什么
```

## 六、简历素材区

> 写作公式：**动词 + 对象 + 方法 + 数字**。删掉所有"负责 / 参与 / 显著提升 / 效果良好"。

| 作品 | 技术要点（关键词） | 量化结果（要能答"怎么测的"） | 简历句式（≤2 行） |
|---|---|---|---|
| | | | |
| | | | |
| | | | |

**自检三条：**
1. 每一行的数字，你能在 10 秒内说出"怎么测的、评测集多大"吗？
2. 每一行里有没有一个"替代方案被放弃"的痕迹（证明你做过取舍）？
3. 念出来像不像在念文档？像就删形容词重写。

**项目卡（一页纸，面试前打印）：** 六段式关键词（业务问题 → 技术选型 → 系统设计 → 评估指标 → 故障与优化 → 最终结果）+ 指标数字表，放 `resume/项目卡-<作品名>.md`。

## 七、备份提醒

- **`04-Outputs/` 与 `03-学习笔记/` 是最该用 Git 备份的两个目录**——它们是"你的资产"，其余目录可以随时从教程重新获得。
- 提交前确认 `.gitignore` 已排除 `.env`、可能含密钥的 trace 输出、体积过大的索引文件；**每个作品交付后 commit 一次**（附指标报告），不要攒到月底。
- 想公开的话：只公开单个作品目录 + 它的 README，不要把整个学习仓库推上去（里面可能有你的踩坑原文与个人笔记）。
