# 在线判题

> **98 道题 / 729 个用例 / 每个用例都用参考解法验证过 / 支持 Python 与 C++。**
> 在浏览器里写代码 → 运行 → 提交 → 逐用例看判定（含用时与内存）→ 提交记录留档 →
> 让 AI 讲错在哪 → 去力扣正式提交。

---

## 一、为什么不是一个网页版 LeetCode

上周有个学员问我：「题解我都看懂了，但自己写的时候总在边界上翻车，怎么办？」

看题解和写代码是两件事。看懂「一遍哈希表」这个思路，和亲手处理 `[3, 3]` 这种「同一个元素不能用两次」的边界，中间隔着几十次实际提交。而每次提交都去力扣，你会被两件事打断：**等网络**，和**不知道错在哪**（力扣只告诉你「解答错误」，不告诉你哪个用例挂了）。

所以这套判题器的定位很明确：**它是你刷题时的草稿纸，不是力扣的替代品。**

- **快**：本地跑，没有网络往返。一个用例通常 1 毫秒。
- **透明**：每个用例的输入、你的输出、期望输出全部摊开给你看。
- **能追问**：错了可以直接让模型讲讲思路哪里偏了。
- **最后一步还是回力扣**：每道题都有「去力扣提交」按钮。本地过了不代表力扣能过（那边的用例更多更狠），这份代码值得再交一次。

## 二、怎么用

### 方式一：网页端（推荐）

```bash
# 1. 启动判题服务（在项目里开一个终端，保持开着）
cd "05-算法面试/06-在线判题"
python judge_server.py

# 2. 打开网页 → 左侧导航「在线判题」
```

网页会自动连上服务。然后：选一道题 → 编辑器里写代码 → **运行**（跑第一个用例，快）或 **提交**（跑全部用例）。

- 代码**自动存在浏览器本地**，关掉页面回来接着写
- 列表里题号旁的小绿点表示「我写过这道题」
- `Tab` 缩进 4 空格、`Enter` 自动继承缩进、`Ctrl+Enter` 提交

### 方式二：命令行

不想开网页也能刷：

```bash
cd "05-算法面试/06-在线判题"

python judge.py list                    # 列出 98 道可判的题
python judge.py show 1-两数之和          # 看题面、签名、用例
python judge.py stub 1-两数之和          # 生成 my_solution.py 模板
python judge.py run 1-两数之和 my_solution.py -v
```

输出长这样：

```
  用例 1     通过  （题解示例）
  用例 3     通过  （边界：同一个元素不能用两次）
  用例 6     答案错误  （规模：3700 个数的大输入）
             得到 [0, 0]
             期望 [3698, 3699]
----------------------------------------------------------------------------
  结果：答案错误   0/6 通过   总耗时 0.01 秒
```

### 方式三：从根目录启动

```bash
python run.py judge      # 等价于 cd 进去再 python judge_server.py
```

## 三、AI 讲评怎么配

「AI 讲评」会把题目、你的代码、失败的用例一起发给模型，让它按三点回答：
**错在哪 / 正确思路 / 复杂度是否达标**。

它走判题服务转发 —— 也就是说**密钥只存在你机器的配置文件里，浏览器永远碰不到它**。

### 网页上直接配（推荐）

打开「在线判题」页，在 **AI 接口配置** 面板里填三样东西：

| 填什么 | 说明 |
|--------|------|
| **API 地址** | 以 `/v1` 结尾。选上面的「服务商预设」能一键填好地址和模型名 |
| **API Key** | 密码框，点「显示」可以核对 |
| **模型 ID** | 要和服务商匹配，写错会报 404 model not found |

面板里有六个常见服务商的预设（DeepSeek / 通义千问 / 智谱 GLM / Kimi / 硅基流动 / OpenAI），
选一下就把地址和模型名填好，你只要补 API Key。

**填完先点「测试连接」再点「保存」。** 测试连接会用一次极小的调用验证你的配置，
几秒内告诉你结果 —— 比写完代码才发现 Key 是错的省事得多：

```
通了（120 ms）。模型回了：可用
```

失败时它会把原因翻译成人话：

| 报错 | 判题器会说 |
|------|-----------|
| 401 | API Key 不对，或者这个 Key 没开通该模型 |
| 404 | 接口地址或模型名不对。最常见的是 BASE_URL 少了 `/v1` |
| 429 | 被限流，或者余额不足 |
| 连不上 | 检查 URL 是否拼错、网络是否通 |

**保存不需要重启服务**，下一次提问就用新配置。

### 也可以手写配置文件

不想用界面的话，配置文件是 `06-在线判题/judge.env`（从 `judge.env.example` 复制）：

```ini
OPENAI_API_KEY=sk-xxxxxxxxxxxx
OPENAI_BASE_URL=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-chat
```

优先级：**`judge.env` > `code/.env` > 系统环境变量**。
所以网页上配的说了算；把 `judge.env` 删掉就会退回用 `code/.env`（和前面 17 章共用的那份）。
面板底部会明确告诉你"当前生效的配置来自哪个文件"，免得你改了 `code/.env` 却没生效还找不到原因。

> 没配也能用判题，只是点「AI 讲评」时会指引你去配置。

### 关于安全，有两件事你要知道

**一、密钥不会进浏览器。** 页面永远拿不到已保存的完整密钥 —— 服务端只回打码后的样子
（`sk-m…7890`）。输入框留空表示"不修改"，所以"只换模型、不重填密钥"是可以的。
保存后输入框会被清空，不会留在页面上被截图带走。

**二、判题服务只接受本机页面调用。** 这一点很重要，所以单独说：

判题服务能在你机器上**执行任意代码**、能**花你的 API 额度**。如果它对所有网页开放，
那么你浏览任意一个恶意网站时，那个网站的脚本就能跨域调 `/judge` 跑代码、
或者调 `/chat` 用你的密钥发请求。

所以服务端会检查请求的 `Origin`：

| 来源 | 结果 |
|------|------|
| `http://127.0.0.1:*` / `http://localhost:*` | 放行 |
| `null`（`file://` 打开的网页） | 放行 |
| 没有 `Origin`（curl、命令行） | 放行 |
| 其他任何域名 | **403 拒绝** |

受影响的是 `/judge`、`/chat`、`/config`、`/submissions/clear` 这几个接口。
真要允许别的地址访问，把地址加进 `judge_server.py` 顶部的 `_LOCAL_ORIGIN` 正则。

这个防护挡得住"陌生网页借用你的服务"，但挡不住"你自己在浏览器里装了恶意扩展"——
那种情况任何本地服务都防不了。

## 四、判题器支持什么

### 两种语言

| 语言 | 签名风格 | 需要装什么 |
|------|----------|-----------|
| **Python 3** | `def twoSum(nums, target):` 或 `class Solution:` | 有 Python 就行（3.9+） |
| **C++17** | `class Solution { public: vector<int> twoSum(vector<int>& nums, int target) {...} };` | `g++` 或 `clang++` |

网页工具栏有个语言下拉框，**每种语言的代码分开保存**，来回切不会互相覆盖。
编译器没装的语言会标成"未安装编译器"并禁止选中 —— 不会让你写完了才发现跑不了。

C++ 的解题骨架会自动生成，**返回类型从用例反推**（`put` 的期望是 null 就是 `void`，
`get` 的期望是数字就是 `int`），参数引用符也按力扣惯例给（容器用 `&`，标量按值）。
所以从骨架开始写，抄到力扣上能直接用。

```bash
python judge.py langs      # 看这台机器上哪些编译器可用
```

### 三种题型

| 类型 | 例子 | 你要写什么 |
|------|------|-----------|
| **函数题** | 两数之和、最长回文子串 | `def twoSum(nums, target):` |
| **链表 / 二叉树题** | 反转链表、二叉树的最大深度 | 和力扣一样，参数直接当节点用 |
| **类设计题** | LRU 缓存、实现 Trie、最小栈、数据流的中位数 | `class LRUCache:`，判题器按操作序列调用它 |

数据结构由判题器自动转换，你不用自己建链表：

```python
def reverseList(head):      # head 进来就是 ListNode
    pre = None
    while head:
        head.next, pre, head = pre, head, head.next
    return pre              # 返回的链表会被序列化回数组再比对
```

### 编译错误会映射回你自己的代码

C++ 报错给的是**生成文件**的行号，而生成文件前面还有 400 多行判题运行时。直接显示的话，
你看到的是「solution.cpp:437: 错误」，可你的代码只有 12 行 —— 根本不知道去改哪里。
判题器把偏移减掉了：

```
第 3 行第 17 列：expected identifier before numeric constant
```

运行时错误也会翻译成人话，不是甩一个退出码：

| 现象 | 判题器会说 |
|------|-----------|
| 空指针 / 越界 | 段错误（非法内存访问）—— 常见原因：数组越界、访问空指针、迭代器失效 |
| 无限递归 | 递归深度超限（栈溢出）—— 检查终止条件，或深度太大时改用迭代 |
| 死循环 | 运行超过 N 秒 —— 检查是不是死循环，或者算法复杂度过高 |
| 除零 | 除零错误（Integer division by zero） |

### 内存与用时

每次运行都会报告**峰值内存**（进程峰值工作集，问操作系统要，不用 tracemalloc ——
那个会拖慢代码、把内存测量变成超时来源）。逐用例也会显示。

内存上限默认 256 MB，超了判「内存超限」。Python 解释器本身占 10~15 MB，
所以这个上限抓的是"真的把内存吃爆"，不是抠几 MB。

### 几个和力扣一致的细节

- **原地修改题**（移动零、轮转数组、矩阵置零、旋转图像、颜色分类、下一个排列）：判题器比对的是**被改动的参数**，所以 `return None` 也算对 —— 和力扣规则一致。页面上会标出来。
- **解集顺序不固定**的题（全排列、子集、组合总和、三数之和、括号生成、N 皇后）：判题器忽略顺序，页面上会标出来。
- **答案不唯一**的题（最长回文子串、将有序数组转换为二叉搜索树）：多个正确答案都算通过。
- **返回链表/树的题**：判题器按力扣的层序格式序列化后比对。

### 两道暂时判不了的题

`160-相交链表` 和 `138-随机链表的复制` 没有内置用例 —— 它们需要「两条输入共享同一批节点」和「节点带 random 指针」这种 JSON 表达不了的结构。这两道题的卡片会标成「无判题」，点进去仍然能看题解，然后去力扣提交。

## 五、提交记录

**每一次「提交」都会留档**：结论、通过用例数、**语言**、用时、峰值内存、时间，以及你当时写的代码。
存在服务端的 `submissions.json` 里（不是浏览器 localStorage），所以换浏览器、清缓存之后记录还在。

三个地方能看到：

| 在哪 | 看什么 |
|------|--------|
| 做题页底部 | 这道题的历次提交（带语言标记），点「恢复这段代码」把那次写的代码放回编辑器 —— 记录是别的语言写的，会自动切过去 |
| 判题列表页 | 每道题前面标状态：**已通过 ✓** / 尝试过 · / 未开始；顶部是总进度条 |
| `#/judge/records` | 全部提交记录，按时间倒序，可筛选、可恢复、可清空 |

状态是怎么聚合的（对应参考项目里 Judge / JudgeCase 两张表的思路）：

- 只要有一次 `通过` → 这道题标 **已通过**，并记下历史最好的用时与内存
- 有提交但没通过 → 标 **尝试过**
- 一次都没提交 → **未开始**

> 注意「运行」不记入历史 —— 那只跑第一个用例，是用来调试的。只有「提交」才算。

最多保留 500 条。命令行判题（`judge.py`）不走这个记录，它是给快节奏手测用的。

## 六、这套用例是怎么保证可信的

这是最要紧的部分。**用例错了比没有用例更糟** —— 你会花一晚上调一个根本不存在的 bug。

所以每道题都存了两个东西：用例 + **参考解法**。判别可信度的唯一标准是：

```bash
python harness.py --selfcheck
```

它拿参考解法跑一遍全部用例。**参考解法都过不了的用例，一定是用例错了。**

```
[ OK ] 1-两数之和                             6/6
[ OK ] 206-反转链表                           7/7
[ OK ] 146-LRU缓存                          7/7
...
自检完成：98 题用参考解法验证通过，0 题不通过，0 题无用例/参考解法
```

当前 98 道题全部通过。生成用例时还做了两件额外的事：

1. **每个期望值都用独立方法复核过** —— 不是照抄参考解法的输出，而是再用暴力解法 / 公式 / `itertools` 枚举重算一遍，两者一致才写入。
2. **反向验证用例的鉴别力** —— 拿故意写错的解法去跑（不用哑节点删节点、只比较父子不算祖先的 BST 校验、移动零返回 None……），确认它们**真的会被判错**。用例抓不住错解的题等于没测。

`cases/` 目录保留的是四组作者文件，`testcases.json` 是它们合并后的成品（合并时按用例更完整的那份优先）。改题目就用 `merge_cases.py` 重新合并，再跑一次 `--selfcheck`。

### 但自检只覆盖 Python

参考解法都是 Python，所以 `--selfcheck` 验证的是**用例本身**，不是 C++ 那条路。
C++ 走的是完全不同的链路（生成源码 → 编译 → 二进制读 JSON → 输出 JSON），
那条路上任何一环坏了，Python 自检都发现不了。

所以多了一个针对真实 C++ 解法的回归测试：

```bash
python test_multilang.py        # 17 项，全过才算好
```

它用**能编译能跑的真解法**覆盖每种数据类型和题型：

| 覆盖什么 | 用哪道题 |
|----------|----------|
| 整数数组 + 整数 | 1-两数之和 |
| 字符串 | 20-有效的括号 |
| 链表（ListNode 自动构造） | 206-反转链表 |
| 二叉树（层序格式 + null） | 104-二叉树的最大深度 |
| 字符网格 | 200-岛屿数量 |
| 整数矩阵 + 原地修改（void 返回，判被改动的参数） | 73-矩阵置零 |
| 原地修改 + 数组 | 75-颜色分类 |
| 解集顺序不固定 | 15-三数之和 |
| 类设计题（带参构造） | 146-LRU缓存 |
| 类设计题（无参构造） | 208-实现Trie |
| 类设计题（方法返回类型各异） | 155-最小栈 |

外加 6 个**反向用例**，验证判题器不放水：语法错误判编译错误、错答案判答案错误、
空指针判运行时错误、死循环判超时、无限递归判爆栈/超时、原地修改题不写回判失败。

### 判题器是怎么做到安全隔离的

用户的代码是不可信的 —— 死循环、递归爆栈、`sys.exit()`、把 stdout 刷满都可能发生。所以：

1. 把代码写进**临时目录**，配一个驱动脚本
2. 在**子进程**里跑，带超时（默认 6 秒）
3. stdout 超过 200KB 就截断
4. 跑完删掉临时目录

一次提交的失败绝不会影响下一次。

C++ 还有一个额外的考虑：**编译只发生一次**。如果按用例编译，一次提交要跑 6~8 次 g++
（每次约 2 秒），学员提交一次要等十几秒，根本没法迭代。现在的做法是源码里只放一份
运行时，编译出的二进制**在运行时从 stdin 读用例 JSON**，所以 6 个用例只是 6 次进程启动
（每次 40 毫秒左右）。

为此需要一份 C++ 的 JSON 解析器 —— 手写的最小实现，放在 `cpp_runtime.py` 里，
用户看不到。这是零依赖这个前提的代价，但换来的是编译一次、执行很快。

另外：`judge_server.py` **默认只监听 127.0.0.1**，同网段的其他机器访问不到。要改成 `0.0.0.0` 之前想清楚 —— 那等于把「在你这台机器上执行任意 Python 代码」开放出去。

## 八、常见问题

**「判题服务没在运行」**
在 `05-算法面试/06-在线判题` 下执行 `python judge_server.py`，保持窗口开着。端口不是 8900 的话，在页面上填新地址再点「重新连接」。

**「找不到函数 twoSum。当前可用的函数：[...]」**
入口函数名写错了。判题器会把你代码里所有可调用的函数列出来，对照着改。注意判题器找的是**模块级函数**，写在 `if __name__ == '__main__'` 里的不算。

**「运行超过 6 秒」**
先看是不是死循环（尤其是 `while` 循环里没有推进条件）。如果逻辑没问题，那是复杂度不达标 —— 这正是规模用例想暴露的。

**返回值对但被判错**
看看题目是不是原地修改题。这类题判的是被改动的参数，你要真的改 `nums`，只返回一个新数组不算。

**AI 讲评报「还没配置大模型」**
把 Key 写进 `code/.env` 或本目录的 `judge.env`，然后**重启服务**（改配置文件不会热加载）。

**「运行」的结果没进提交记录**
对，「运行」只跑第一个用例，是调试用的，不记历史。要留档请点「提交」。

**内存怎么算的，为什么比力扣高**
报的是整个 Python 进程的峰值工作集，包含解释器本身的 10~15 MB 开销。力扣的 Python 也是进程级统计，
量级可比、绝对值会因解释器版本和环境不同。

**能不能用 Java / Go / JavaScript**
还在路上。加一门语言的成本是写一份运行时（类型定义 + 输入解析 + 结果序列化）再加一个
后端类，`languages.py` 的架构已经为此留好了位置。当前先把 Python 和 C++ 做扎实 ——
这两种也覆盖了大多数人的刷题语言。

**C++ 里我要写 `class Solution` 还是自由函数**
两种都认。判题器会看你的代码里有没有 `class Solution`，有就调它的方法，没有就按自由函数调。
力扣用 `class Solution`，所以建议照着模板来。

**为什么我的 `int& target` 编译不过**
模板给的是 `int target`（按值）—— 力扣的 C++ 签名就是这样。只有容器才按引用
（`vector<int>& nums`）。判题器传的是具名变量，所以两种写法在调用侧都能接上，
但抄到力扣时要一致。

**力扣上的用例比这里多**
正常。本地的 6–8 个用例是为了让你快速定位错误，不是穷尽。本地过了之后去力扣再交一次，那才是最终判定。
