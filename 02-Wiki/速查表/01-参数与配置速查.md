## 一、环境变量清单

| 变量 | 必填 | 默认值 | 作用 | 写错的后果 |
|---|---|---|---|---|
| `OPENAI_API_KEY` | 在线模式必填 | 无 | 服务商密钥，Header 里是 `Authorization: Bearer <key>` | 401；没配则自动进入离线 Mock |
| `OPENAI_BASE_URL` | 建议填 | `https://api.deepseek.com/v1`（本书示例默认） | 接口根地址，**只到版本号**，代码拼 `/chat/completions` | 404（少/多了 `/v1`） |
| `OPENAI_MODEL` | 建议填 | `deepseek-chat` | 模型名，必须与服务商控制台一致 | 404 `model not found` |
| `AGENT_MOCK` | 否 | 未设置 | `=1` 强制离线 Mock（不发真实请求、不花钱） | 设 `AGENT_MOCK=0` **不等于**在线（判定规则是 `== "1"`） |
| `AGENT_TRACE` | 否 | 未设置 | `=1` 打开每步 messages / trace 打印 | 无 |
| `HTTPS_PROXY` / `HTTP_PROXY` | 否 | 无 | 公司网络走代理 | 不配则超时 / SSL 错误 |
| `PYTHONIOENCODING` | Windows 建议 | 无 | 设 `utf-8`，避免中文乱码 | 控制台中文乱码 / 编码异常 |
| `PYTHONUTF8` | 否 | 无 | `=1` 让 Python 全程按 UTF-8 | 同上 |

### `.env` 模板（放 `code/.env`，已被 `.gitignore` 排除）

```ini
# 在线模式：填任意 OpenAI 兼容服务商的三个值，代码不用改
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxx
OPENAI_BASE_URL=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-chat

# 调试开关（注释掉即在线）
# AGENT_MOCK=1
# AGENT_TRACE=1
```

```bash
# 临时强制离线跑一次（Linux / macOS / Git Bash）
AGENT_MOCK=1 python ch05_react_loop.py
# Windows CMD
set AGENT_MOCK=1 && python ch05_react_loop.py
# Windows PowerShell
$env:AGENT_MOCK=1; python ch05_react_loop.py
```

> **判定规则**：`有 key 且 AGENT_MOCK != "1"` → 在线；否则离线 Mock。
> **密钥纪律**：只放 `.env`；提交过就要**吊销重发**；绝不写进代码、trace、提示词。

## 三、生成参数表

| 参数 | 常见默认 | 作用 | 调高会怎样 | 调低会怎样 | 什么时候该动它 |
|---|---|---|---|---|---|
| `temperature` | 1.0（本书示例用 0.7） | 采样随机性 | 多样有创意，但跑题、编造、格式不稳 | 稳定保守可复现，但可能死板重复 | **最常动的参数**：抽取/分类/JSON/选工具 → 0–0.3；改写 → 0.3–0.6；文案 → 0.7–1.0；头脑风暴 → 1.0–1.3 |
| `top_p` | 1.0 | 只从累计概率前 p 的候选里抽 | 同 temperature 调高 | 同 temperature 调低 | 一般**不动**；和 temperature **只调一个**，否则无法归因 |
| `top_k` | 多数 API 不暴露 | 只从概率最高的 K 个候选里抽 | 更发散 | 更保守 | 只有在服务商支持且 `top_p` 不够用时才碰 |
| `max_tokens` | 服务端默认（常见 4K） | **输出**长度上限 | 允许更长输出，更贵、更慢 | 可能**静默截断**（`finish_reason=length`） | 抽取类 512–1024；长文写作 2048–4096；不确定就不传 |
| `frequency_penalty` | 0 | 按"出现过多少次"惩罚 | 减少重复词，过强则语句不通 | 允许重复 | 复读严重时 **+0.2~0.3**，一次只加一点 |
| `presence_penalty` | 0 | 按"出现过没有"惩罚 | 鼓励新话题，容易跑题 | 允许复读 | 想让它别老在原话题打转时用，同样小步调 |
| `stop` | 无 | 遇到指定字符串立即停止 | — | — | **少用**；输出 JSON 时尤其危险（可能被自己的内容截断） |
| `seed` | 无 | 尽量固定随机种子 | — | — | 需要复现实验/评测时用；**不保证跨版本一致** |
| `response_format` | 无 | 强制 JSON 输出（`{"type":"json_object"}`） | — | — | 需要稳定 JSON 时用；仍要**代码校验 + 重试**兜底 |
| `n` | 1 | 一次生成几个候选 | 更贵（按 n 倍计费） | — | 只有做采样投票（Self-Consistency）时才 >1 |
| `stream` | `false` | 流式返回 | — | — | 有真人等待时必须开；`tool_calls.arguments` 是分片，要累积后解析 |

### temperature 速查（背这一行就够）

```text
分类 / 抽取 / JSON / 工具选择 → 0 ~ 0.3
翻译 / 摘要 / 润色           → 0.3 ~ 0.6
客户回复 / 文案写作           → 0.7 ~ 1.0
头脑风暴 / 起标题             → 1.0 ~ 1.3（超过 1.3 基本不可用）
```

**三条容易搞错的**：

- `temperature=0` **不等于**确定性输出（浮点累加顺序、动态批处理、MoE 路由、副本差异、模型版本都会引起变化）；
- `max_tokens` 太小 + 要求 JSON = 半个 JSON（`json.loads` 报 `Expecting value`）；
- `temperature` 调低**不能消除幻觉** —— 它只减少发散型胡说，管不了"没知识硬答"。

## 四、上下文窗口速查

| 档位 | 典型模型 | 大致能装 |
|---|---|---|
| 8K | 早期/小模型 | 约 5000–8000 汉字 |
| 32K | 常见中档 | 约 2 万字 |
| 64K | `deepseek-chat` | 约 4–6 万字 |
| 128K–200K | 长文本模型 | 约 10 万字以上 |

```text
输入预算 = 上下文窗口 − max_tokens − 安全余量
超限报错长这样（400）：maximum context length is 65536 tokens, however you requested 70000
  → 正确动作：减历史 / 压缩 / 切片，不是改提示词措辞
```

## 五、模型选型建议（按任务类型）

| 任务 | 建议档位 | temperature | 备注 |
|---|---|---|---|
| 意图分类 / 路由 / 参数抽取 | 最便宜的一档 | 0–0.3 | 量大、要稳，质量差异对结果影响小 |
| 工具选择（Agent 循环） | 中小档 | 0–0.3 | 选错工具代价高；这层是成本大头 |
| 结构化输出（JSON） | 中小档 + `response_format` | 0–0.3 | 一定要代码校验 + 失败重试 |
| RAG 问答 / 摘要 | 中档 | 0.3–0.6 | 长上下文能力比"聪明"更重要 |
| 复杂推理 / 规划 | 强档 | 0.3–0.7 | 调用次数少，值得花 |
| 最终写作 / 报告 | 强档 | 0.6–0.9 | 只调用 1 次，钱花在刀刃上 |
| 模型评审（LLM-as-judge） | 强档 | 0–0.3 | 判定器不准，整套评测都不可信 |
| 离线批处理 | 便宜的批量通道 | 视任务 | 时效以小时/天计就换价格 |
| 本地开发 / 调试 | 本地小模型 或 `AGENT_MOCK=1` | — | **调流程别用最贵的模型** |

**分级惯例（省钱第一杠杆）**：便宜模型跑循环和抽取 → 强模型只在"最终写作 / 复杂规划 / 评测判定"出现。

## 六、连通性自检命令

```bash
# 1. 网络能不能通（换成你的 base_url 域名）
curl -I https://api.deepseek.com

# 2. 模型列表（部分服务商支持，能验证 key 与 base_url 都对）
curl -s https://api.deepseek.com/v1/models -H "Authorization: Bearer $OPENAI_API_KEY"

# 3. 最小对话请求（最可靠的验证）
curl -s https://api.deepseek.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"hi"}],"max_tokens":8}'

# 4. 本地 Ollama
curl -s http://localhost:11434/v1/models
```

## 七、配置类问题快速定位

| 症状 | 先查这一项 |
|---|---|
| 401 / invalid api key | `print(repr(key))`：是否带引号、空格、`Bearer` 重复 |
| 404 Not Found | `base_url` 是否少/多了 `/v1`（智谱是 `/api/paas/v4`）；模型名是否与控制台一致 |
| 429 `insufficient_quota` / `Insufficient Balance` | **余额不足**，充值；加 `sleep` 没用 |
| 429 `rate_limit_exceeded` | 请求太密，退避重试 |
| 设了 key 还是离线 | `AGENT_MOCK` 是否被设为 `1`；`.env` 是否在 `code/` 目录；环境变量是否真的加载 |
| 换了模型后效果全变 | 检查是否用了"浮动别名"（会静默升级版本），锁定具体版本名 |
