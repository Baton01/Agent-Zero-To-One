# 速查表：报错排查手册

> 报错先查这里，不用重读正文。相关：[[02-Wiki/速查表/01-参数与配置速查]]、[[docs/第00章 环境准备与第一次模型调用]] §8、[[docs/第05章 ReAct最小Agent-Loop]] §6

## 零、总纲：二分定位法（先判断是配置问题还是代码问题）

```text
① 读报错：先看最后一行（异常类型 + 消息），再看第一行（哪个文件哪一行）
   → 不要一上来就换模型、改提示词
② 二分：AGENT_MOCK=1 python chXX_xxx.py
   ├─ Mock 能跑通、在线跑不通 → 配置 / 网络 / 账户问题（查下面第 1–6 条）
   └─ Mock 也跑不通            → 代码问题（看 traceback 最后一行，查第 7–13 条）
③ 拿到服务端返回的 body：错误原因 90% 写在 body 里（例如 429 到底是没钱还是太快）
④ 只改一个变量：一次改两处，即使修好了也不知道是哪一处生效
```

**通用三条纪律**：报错必须**打印完整 body**（不要只打印状态码）；请求必须打印**拼好的完整 URL 与模型名**；Agent 类问题先 `dump_messages()` / 看 trace，再怀疑模型。

## 一、认证与权限：401 / 403

| 项 | 内容 |
|---|---|
| **现象** | `401 Authentication Fails` / `invalid api key` / `403 Forbidden` |
| **最可能原因** | key 错/过期/被禁用；粘进了引号或空格；`Authorization` 里重复 `Bearer`；用了别人的 base_url 配自己的 key |
| **第一步** | `print(repr(api_key))`，对比前后 6 位；确认 Header 是 `Bearer sk-xxx` |
| **验证** | `curl -s <base_url>/models -H "Authorization: Bearer $OPENAI_API_KEY"`；或换回一个确定可用的 key |
| **怎么修** | 去掉引号与空格；重新从控制台复制 key；确认 key 与 base_url 属于同一服务商；确认 Header 只带一次 `Bearer` |

**403 补充**：多为"key 有效但权限不够"（模型未开通、地区限制、账号被风控）。看 body 里的 `code`/`type` 字段。

---

## 二、找不到路径或模型：404

| 项 | 内容 |
|---|---|
| **现象** | `404 {"error":{"message":"Not Found"}}` / `model not found` / 中文的"模型不存在" |
| **最可能原因** | ① `base_url` 少/多了 `/v1`（最大的坑：智谱是 `/api/paas/v4`）；② 模型名拼错或未开通；③ URL 拼成了 `//chat/completions` |
| **第一步** | 打印拼好的完整 URL 与模型名，逐字符对照服务商官网 |
| **验证** | `curl -I <base_url>/models`；把模型名从控制台列表**复制**（不要手打） |
| **怎么修** | 按对照表修正 base_url（见 [[02-Wiki/速查表/01-参数与配置速查]] §二）；代码里用 `base_url.rstrip("/")`；模型名以控制台为准 |

---

## 三、限流与余额：429（两种含义必须区分）

| 项 | 内容 |
|---|---|
| **现象** | `429`。**两种完全不同的原因**：`insufficient_quota` / `Insufficient Balance`（没钱） vs `rate_limit_exceeded` / `Requests rate limit exceeded`（太快） |
| **最可能原因** | 余额耗尽 / 免费额度用完 / 并发或 QPS 超限 / 循环里没加间隔 |
| **第一步** | **读 body 里的 code**：`insufficient_quota` → 去控制台看余额；`rate_limit_exceeded` → 控速 |
| **验证** | 休息 1 分钟重试：能成功 = 限流；仍失败且 code 是 quota = 余额 |
| **怎么修** | 余额：充值（**重试一万次也没用**）。限流：指数退避 + 抖动重试、加并发上限、请求合并、错峰；给循环加最小间隔 |

> **最常见的浪费**：看到 429 就 `while True: sleep(1)` 死循环 —— 如果是余额问题，你在白等。

## 四、超时

| 项 | 内容 |
|---|---|
| **现象** | `urlopen error timed out` / `Read timed out` / `ReadTimeout` / 请求卡住不动 |
| **最可能原因** | 网络不通或需代理；服务端排队慢；模型在生成长输出；`max_tokens` 过大 + 非流式；并发太高把自己堵住 |
| **第一步** | `curl -I <base_url>` 看能否连通；看单次请求耗时与输出长度 |
| **验证** | 换网络（手机热点）试一次；把 `max_tokens` 降到 64 再跑一次（快了 = 输出太长） |
| **怎么修** | 配 `HTTPS_PROXY`；开流式；缩短输出；设**分层超时**（连接 3–5s < 单次调用 30–60s < 工具 10–30s < 整体 120–300s）；加并发上限与重试（带退避抖动） |

---

## 五、SSL / 代理错误

| 项 | 内容 |
|---|---|
| **现象** | `SSLCertVerificationError` / `CERTIFICATE_VERIFY_FAILED` / `SSL: WRONG_VERSION_NUMBER` |
| **最可能原因** | 公司代理替换了证书；系统根证书过期；代理地址写错（把 HTTP 代理当 HTTPS 用）；环境变量里残留了已失效的代理 |
| **第一步** | `curl -I <base_url>` 对比（curl 能通而 Python 不通 = Python 侧的证书/代理配置问题） |
| **验证** | 清空代理变量再试：`unset HTTPS_PROXY HTTP_PROXY`；或显式指定证书路径 |
| **怎么修** | 把公司根证书加入信任链（`REQUESTS_CA_BUNDLE` / `SSL_CERT_FILE`）；修正代理地址；**不要**长期用 `verify=False` 绕过（安全与合规问题） |

---

## 六、连不上：ConnectionError / 拒绝连接

| 项 | 内容 |
|---|---|
| **现象** | `ConnectionRefusedError: [WinError 10061]` / `ConnectionError` / `getaddrinfo failed` / `Max retries exceeded` |
| **最可能原因** | 本地服务没起（Ollama）；端口写错；域名解析失败（DNS/网络）；未开代理访问境外地址 |
| **第一步** | `curl http://localhost:11434/v1/models`（本地）或 `nslookup <域名>`（远程） |
| **验证** | 换一个已知可用的公共地址（如 `https://api.deepseek.com`）测试网络 |
| **怎么修** | 启动本地服务；修正端口；配 DNS/代理；本地服务用 `127.0.0.1` 而不是 `localhost`（避免 IPv6 解析问题） |

## 七、JSON 解析失败

| 项 | 内容 |
|---|---|
| **现象** | `json.decoder.JSONDecodeError: Expecting value: line 1 column 15` / `Extra data` |
| **最可能原因** | 输出被截断（`max_tokens` 太小）；模型加了 ```json 代码块或前后解释文字；输出含中文全角引号；模型直接返回非 JSON；**流式分片未累积完就解析** |
| **第一步** | `print(repr(raw_output))` 看真实字符（是不是有 ` ``` `、`\u3000`、全角引号） |
| **验证** | 检查 `finish_reason` 是否 `length`；把 `max_tokens` 调到 2048 再试 |
| **怎么修** | ① 用 `response_format={"type":"json_object"}`；② 提示词里给一个完整 JSON 示例；③ 写**容错提取**（截取第一个 `{` 到最后一个 `}`）；④ 解析失败 → 把错误信息喂回模型重试**一次**；⑤ 仍失败 → 走降级（返回结构化错误，不要让流程崩） |

```python
def parse_json_loose(text):
    """容错解析：先直接解析，再截取第一个 { 到最后一个 }。"""
    try:
        return json.loads(text)
    except ValueError:
        start, end = text.find("{"), text.rfind("}")
        if start >= 0 and end > start:
            return json.loads(text[start:end + 1])
        raise
```

## 八、输出被截断：`finish_reason=length`

| 项 | 内容 |
|---|---|
| **现象** | 回答断在半路；`completion_tokens` 恰好等于 `max_tokens`；JSON 少一个右括号 |
| **最可能原因** | `max_tokens` 设太小；任务要求输出过长；传了 `stop` 参数被自己的内容命中 |
| **第一步** | 打印 `finish_reason` 与 `completion_tokens` |
| **验证** | 把 `max_tokens` 翻倍重跑，看是否恢复完整 |
| **怎么修** | 调大 `max_tokens`（抽取 512–1024 / 长文 2048–4096）；拆分任务（"先给大纲再逐段写"）；**检查是否传了 `stop`**（输出 JSON 时尤其危险） |

**`finish_reason` 对照表**：

| 值 | 含义 | 动作 |
|---|---|---|
| `stop` | 自然说完 | 正常 |
| `length` | 被 `max_tokens` 截断 | 调大上限或简化任务 |
| `tool_calls` | 模型要调工具 | 执行工具并回填结果 |
| `content_filter` | 被内容安全策略拦截 | 检查输入/输出是否违规 |

## 九、工具参数解析失败（Agent 专属）

| 项 | 内容 |
|---|---|
| **现象** | 工具调用报 `KeyError`、`TypeError: missing required argument`、参数是 `{}` 或 `"true"`（字符串）；流式下 `Expecting value` |
| **最可能原因** | schema 里参数**没有 `description`**（模型不知道填什么）；必填未进 `required`；类型写错（布尔写成字符串）；**流式分片未累积**就解析 `arguments` |
| **第一步** | 打印本轮 `tool_calls` 的完整结构与模型的原始参数 |
| **验证** | 检查 `registry.to_openai_schema()` 的实际输出，确认每个参数都有 `type` + `description` |
| **怎么修** | 补参数描述与示例值；参数做**类型转换与校验**（`"true"` → `True`）；缺参数时把错误信息写清楚并让模型重试；校验失败的参数**先别执行工具**（省 token 也防误操作） |

## 十、上下文超限

| 项 | 内容 |
|---|---|
| **现象** | `400 This model's maximum context length is 65536 tokens, however you requested 70000 tokens (65000 in the messages, 5000 in the completion)` |
| **最可能原因** | 历史未裁剪；工具返回太长；RAG 塞了太多 chunk；一次把整个文件读进上下文 |
| **第一步** | 分开估算 system / 历史 / 本次输入 / 预留输出各占多少（见 [[02-Wiki/速查表/02-Token与成本速查]] §一） |
| **验证** | 把历史裁到最近 3 轮再跑，看是否通过 |
| **怎么修** | 给上下文分预算（`输入预算 = 窗口 − max_tokens − 余量`）；历史超阈值就摘要；工具结果截断；检索限定 Top-K；**不要改提示词措辞** —— 报错说的是长度，不是措辞 |

## 十一、编码问题（中文乱码）

| 项 | 内容 |
|---|---|
| **现象** | 控制台中文变 `????` 或 `锟斤拷`；`UnicodeEncodeError: 'gbk' codec can't encode character`；写入文件后中文乱码 |
| **最可能原因** | Windows 控制台默认 GBK；文件读写未指定编码；子进程（MCP stdio）未设 UTF-8 |
| **第一步** | 确认报错是"打印"还是"写入"环节；`import sys; print(sys.stdout.encoding)` |
| **验证** | `set PYTHONIOENCODING=utf-8` 后重跑，看乱码是否消失 |
| **怎么修** | 跑之前设 `PYTHONIOENCODING=utf-8`（Windows）或 `export PYTHONIOENCODING=utf-8`；脚本内 `sys.stdout.reconfigure(encoding="utf-8")`（Python 3.7+）；所有 `open()` 显式 `encoding="utf-8"`；子进程同样设置 |

## 十二、循环不终止（Agent 不动了 / 停不下来）

| 项 | 内容 |
|---|---|
| **现象** | 步数一直涨；反复调用同一个工具；同一段 thought 重复出现；跑到时间/额度耗尽 |
| **最可能原因** | 提示词没写"必须调用工具或给答案"；工具的 `description` 太宽导致总选它；工具一直返回错误但错误信息没说清怎么改；没有停止条件；参数为空模型反复试 |
| **第一步** | `dump_messages()` 打印完整 messages（用第 05 章 §6.1 的 `dump_messages`），看**每一步到底发了什么、回了什么** |
| **验证** | 看是否重复同一动作（`action` + `args` 相同）→ 说明模型没有获得新信息 |
| **怎么修** | 设置组合停止条件：**最大步数（3–8）+ 重复动作检测（相同 action+args 出现 2 次即停）+ 无工具调用即结束 + 超时 + 预算**；工具错误信息写成"说明书"（告诉模型怎么改）；收窄过宽的 description；缺参数就补示例值 |

**六个典型症状 → 病因（第 05 章 §6.2）**：

| 症状 | 最可能原因 |
|---|---|
| 第 1 步就不输出 Action | 系统提示格式与任务冲突；模型不支持该格式 → 打印模型**原始输出** `repr()` |
| 一直分析从不调工具 | 没写"必须调用工具或给答案" |
| 总选同一个工具 | 那个工具的 description 太宽，其他太弱 |
| 参数总是空 `{}` | 参数没有 description |
| 格式对但正则匹配不上 | 模型加了 `**加粗**`、代码块或中文标点 → `print(repr(...))` |
| 第 2 步就说"信息够了" | 幻觉，以为自己知道 → 提示里写明"涉及文件/精确计算必须先获取真实数据" |

## 十三、万能排查顺序（背下来）

```text
1. 服务端 body 是什么？           ← 90% 的答案在这里
2. 拼好的完整 URL 和模型名对吗？   ← 404 几乎都是这个
3. AGENT_MOCK=1 能跑通吗？        ← 二分：配置 or 代码
4. 打印 messages / trace 了吗？   ← Agent 类问题必做
5. 一次只改一个变量了吗？          ← 否则修好了也不知道为什么
```
