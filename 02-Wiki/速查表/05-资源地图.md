## 一、入门必读（先读这 6 份，全部免费）

| 资源 | 为什么有用 / 看到什么程度 |
|---|---|
| ⭐ [Anthropic: Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | 官方工程视角讲清 workflow 与 agent 的边界、5 种常见编排模式 —— **精读一遍，重点是"先简单后复杂"** |
| ⭐ [OpenAI: A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) | 生产视角的选型与护栏清单 —— 读 multi-agent 与 guardrails 两节，理解"什么时候别做 Agent" |
| ⭐ [Anthropic: How we built our multi-agent research system](https://www.anthropic.com/engineering/built-multi-agent-research-system) | 唯一公开讲了多 Agent 真实账本的文章（token 约 15 倍） —— 读"成本与权衡"部分校准预期 |
| [Anthropic: Claude Code best practices](https://www.anthropic.com/engineering/claude-code-best-practices) | 一个成熟编码 Agent 的工具设计、上下文管理与权限门 —— 通读，抄它的工具与权限设计 |
| [12-Factor Agents](https://github.com/humanlayer/12-factor-agents) | 把"Agent 应用"当软件工程对待的 12 条原则 —— 过一遍目录，记住"own your control flow / own your context window" |
| [Hugging Face Agents Course](https://huggingface.co/learn/agents-course) | 有练习、有评测的免费课程 —— 只想补一段系统课就做它的 unit 1–2 |

## 二、经典论文（按主题，读摘要 + 方法图即可，不必复现）

### Agent 基础

| 资源 | 为什么有用 / 看到什么程度 |
|---|---|
| ⭐ [ReAct: Synergizing Reasoning and Acting (2210.03629)](https://arxiv.org/abs/2210.03629) | Thought/Action/Observation 循环的源头 —— 读方法一节，对照你写的 50 行 Agent Loop |
| [Reflexion: Language Agents with Verbal Reinforcement (2303.11366)](https://arxiv.org/abs/2303.11366) | "把失败写成反思再重试"的范式 —— 读摘要 + 架构图，理解反思为什么能提升 pass@k |
| [Toolformer (2302.04761)](https://arxiv.org/abs/2302.04761) | 让模型自己学会何时调工具 —— 读摘要，理解"工具调用是训练目标而不只是提示技巧" |
| [Self-Refine (2303.17651)](https://arxiv.org/abs/2303.17651) | 自我批评与迭代修改 —— 读实验结果，注意它**同上下文自省效果有限**的局限 |
| [Tree of Thoughts (2305.10601)](https://arxiv.org/abs/2305.10601) | 把推理做成搜索（分支 + 评估 + 回溯） —— 读方法图，知道成本量级后再决定要不要用 |
| [Plan-and-Solve Prompting (2305.04091)](https://arxiv.org/abs/2305.04091) | 先规划再执行的最简版本 —— 20 分钟读完，它是"拆任务"的入门论文 |

### 记忆与上下文

| 资源 | 为什么有用 / 看到什么程度 |
|---|---|
| ⭐ [Lost in the Middle (2307.03172)](https://arxiv.org/abs/2307.03172) | 长上下文"中间信息最容易被忽略"的实证 —— 读结论，它直接决定你把关键信息放哪 |
| [MemGPT: Towards LLMs as Operating Systems (2310.08560)](https://arxiv.org/abs/2310.08560) | 分层记忆 + 自主换页的经典设计 —— 读架构图，对照第 07 章的三层记忆 |
| [Generative Agents (2304.03442)](https://arxiv.org/abs/2304.03442) | 记忆流 + 反思 + 计划，智能体社会模拟的先驱 —— 读记忆检索打分公式那一节 |

### 评测与 Benchmark

| 资源 | 为什么有用 / 看到什么程度 |
|---|---|
| ⭐ [GAIA (2311.12983)](https://arxiv.org/abs/2311.12983) | 真人日常任务的通用 Agent 基准（含工具使用与多步推理） —— 读任务分级与失败分析 |
| ⭐ [τ-bench (2406.12045)](https://arxiv.org/abs/2406.12045) | 带**用户交互**与规则遵循的 Agent 评测（pass^k 概念的重要来源） —— 读指标定义 |
| [SWE-bench (2310.06770)](https://arxiv.org/abs/2310.06770) | 真实 GitHub issue 修复基准，coding agent 的标尺 —— 读任务构造与评测方法，知道"解决率"怎么来的 |
| [AgentBench (2308.03688)](https://arxiv.org/abs/2308.03688) | 多环境 Agent 综合评测 —— 读环境清单与结论，了解 Agent 的典型短板 |
| [WebArena (2307.13854)](https://arxiv.org/abs/2307.13854) | 可复现的真实网站环境（浏览器 Agent 基准） —— 读环境与指标设计 |

### 多智能体与协作

| 资源 | 为什么有用 / 看到什么程度 |
|---|---|
| [AutoGen (2308.08155)](https://arxiv.org/abs/2308.08155) | 对话式多 Agent 的学术原型 —— 读架构与局限，理解工程上为什么要加契约与轮次上限 |
| [CAMEL (2303.17760)](https://arxiv.org/abs/2303.17760) | 角色扮演式协作的开创工作 —— 读摘要，"自由对话式"的问题在这里就有苗头 |
| [MetaGPT (2308.00352)](https://arxiv.org/abs/2308.00352) | 用 SOP 约束多 Agent（产品/架构/开发角色） —— 读它的标准化输出设计，这是"契约"的雏形 |

### 安全与鲁棒性

| 资源 | 为什么有用 / 看到什么程度 |
|---|---|
| ⭐ [Not what you've signed up for: Indirect Prompt Injection (2302.12173)](https://arxiv.org/abs/2302.12173) | 间接注入的奠基论文（注入藏在你要读的内容里） —— 精读，它解释了为什么"提示词防不住" |
| [Universal and Transferable Adversarial Attacks on Aligned LLMs (2307.15043)](https://arxiv.org/abs/2307.15043) | 对抗后缀攻击（GCG） —— 读摘要，建立"提示词层不是安全边界"的认知 |
| [Many-shot Jailbreaking (Anthropic)](https://www.anthropic.com/research/many-shot-jailbreaking) | 长上下文带来的新攻击面 —— 读一遍，理解为什么上下文越长越危险 |

### RAG 与检索

| 资源 | 为什么有用 / 看到什么程度 |
|---|---|

## 六、怎么用这张地图（不是收藏夹，是路线）

```text
第 1 步：§一 挑 2 篇读完（Anthropic Building effective agents + OpenAI practical guide）
第 2 步：跑通本项目的 code/，卡住时查 §三 的官方文档（不要查博客）
第 3 步：§四 挑一个方向读源码 —— 想要工具/权限设计读 Aider，想要浏览器读 browser-use
第 4 步：§二 补论文 —— 按你踩过的坑去读（上下文丢了读 Lost in the Middle，循环不停读 ReAct）
第 5 步：§五 追前沿 —— 每周 1 篇，别的别贪
```

**三条纪律**：**能跑起来的比读起来爽的重要**；**官方文档优先于博客**（协议细节变化快）；**每读一篇就问自己：我能在项目里用它改一行什么？** 答不出来就跳过。
